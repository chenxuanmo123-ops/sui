更新唯一完整交接文档 `docs/项目进度与交接说明.md`。本轮重点：$ARGUMENTS

执行步骤：

1. 读取 `CLAUDE.md`、`docs/项目进度与交接说明.md`、`docs/数鉴Agent-项目长期上下文.md`，以及本轮直接相关的代码和测试。
2. 运行以下命令获取事实，不要凭记忆填写：
   - `git rev-parse --abbrev-ref HEAD`
   - `git rev-parse --short HEAD`
   - `git status --short`
   - `git diff --stat`
   - `git log -5 --oneline`
   - `date '+%Y-%m-%d %H:%M:%S %z'`
3. 保持文档现有章节与历史，不要改写成固定模板。至少更新：
   - 第 1 节「接手先看」：当前阶段、工作区、最关键事实。
   - 第 7 节「最新未提交改动」：新增/修改文件与不能丢失的内容。
   - 第 8 节「实际验证结果」：写明命令、数量、失败与复跑结果。
   - 第 10 节「公网、Git 和安全状态」：部署地址、实际路由证据、产物版本。
   - 第 12 节「未完成内容与优先顺序」：已完成项标注完成，保留未完成项。
   - 第 15 节「本次交接交付记录」：追加一条日期、修改、验证、待办。
4. 如果本轮涉及部署、模型能力或数据来源，补充具体 URL、状态码、资源哈希或失败记录；没有实测就写“未验证”。
5. 约束：
   - 不编造测试结果、部署状态、模型能力或用户未确认的决定。
   - 不写入真实 API Key、`.local/` 内容、临时凭据或无法公开的数据。
   - 不把“连接成功”写成“分析准确”，不把测试替身写成真实模型输出。
   - 不删除历史变更日志和尚未解决的问题；未核实的内容标记“待确认”。
6. 写完后用一句话报告：更新了哪些章节、当前 HEAD、以及最关键的未完成事项。
