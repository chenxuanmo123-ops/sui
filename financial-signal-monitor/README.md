# 🔔 Financial Signal Monitor

**基于 Agent 的金融信号监控与自动推送系统**

> 双数据源协同 | 多维度信号检测 | 自动化定时执行 | 微信推送集成(待完成)

---

## 📋 项目概述

Financial Signal Monitor 是一个智能化的金融信号监控系统，能够自动采集多市场（A股/港股/美股）行情数据，通过多维度信号检测算法识别异动，并及时推送告警通知。

### 核心能力

- **双数据源协同**: `westock-data` (腾讯自选股) + `neodata-financial-search` (自然语言搜索)
- **多维度信号检测**: 价格异动、成交量放大、主力资金流向、MACD技术指标
- **自动化执行**: 通过 WorkBuddy Automation 实现定时监控
- **多级告警推送**: 控制台输出 → 日志文件 → HTML报告 → 微信推送(待集成)
- **结构化配置**: 监控列表和信号阈值可通过JSON文件灵活配置

## 🎯 核心痛点

### 问题1: 信息碎片化，缺乏统一监控入口

个人投资者通常需要在多个平台之间切换：
- 打开多个股票 App 查看行情
- 手动刷新关注列表
- 错过关键异动信号（如突发涨停、大单流入）

**解决方案**: 通过 Agent 统一采集多市场数据，自动检测异动并推送告警，用户无需时刻盯盘。

### 问题2: 传统预警工具缺乏智能推理

现有股票预警工具通常只能设置简单的价格阈值，无法：
- 综合分析多个指标（价格+成交量+资金流向）
- 根据市场环境动态调整判断逻辑
- 提供结构化的行动建议

**解决方案**: 引入 AI Agent 进行长链推理，不仅判断"是否触发"，还能分析"为什么触发"和"可能的影响"。

### 问题3: 数据来源单一，覆盖不全面

单一数据源可能存在：
- 数据延迟
- 字段覆盖不全（如缺少资金流向、财务指标）
- 跨市场支持不一致

**解决方案**: 双数据源协同，互为补充：
- `westock-data`: 提供精确的K线、资金流向、技术指标
- `neodata-financial-search`: 提供自然语言查询能力，覆盖宏观、财报、研报

### 长链推理示例

当检测到某只股票触发多个信号时，Agent 会进行推理分析：

**输入**: 
- 贵州茅台 (sh600519) 触发信号:
  - 价格异动: 单日上涨 +6.8%
  - 成交量放大: 3.2x 均量
  - MACD金叉: DIF上穿DEA

**Agent 推理链**:
1. **数据验证**: 检查三个信号是否同时有效（排除单一指标误判）
2. **原因分析**: 查询 neodata 获取当日新闻/公告（如业绩超预期、行业政策利好）
3. **影响评估**: 
   - 价格+成交量+MACD三重确认 → 强势上涨信号
   - 查看资金流向 → 主力资金是否同步流入（确认不是游资炒作）
4. **行动建议**: 生成结构化建议（如"可关注，建议设定止损位X元"）

**输出**: 
```markdown
🔴 高严重度信号: 贵州茅台 (sh600519)
- 价格异动: +6.8% (超过阈值 5%)
- 成交量放大: 3.2x (均量 12345 手)
- MACD金叉: DIF: 0.85, DEA: 0.72
- AI分析: 三信号共振，主力资金同步流入，趋势较强
- 建议: 可关注，注意止损
```

## 🤖 多 Agent 协作设计

### Agent 角色分工

| Agent | 职责 | 使用的 Skill/Tool |
|-------|------|-------------------|
| **主控制器 (Main Controller)** | 协调各 Agent，汇总结果 | WorkBuddy Agent 核心 |
| **数据采集 Agent** | 调用 westock-data 和 neodata API | `westock-data-skillhub`, `neodata-financial-search` |
| **信号检测 Agent** | 运行检测算法，识别异动 | 内置 JavaScript 算法 |
| **分析推理 Agent** | 对触发信号进行深度分析 | 可调用 LLM 进行推理 |
| **推送 Agent** | 生成告警消息，分发到各渠道 | 文件 I/O, HTTP (待集成微信) |

### 协作流程

```
用户配置 → 主控制器
    ↓
主控制器 调用 数据采集 Agent (并行采集多只股票)
    ↓
数据采集 Agent 返回结构化数据
    ↓
主控制器 调用 信号检测 Agent (逐只股票检测)
    ↓
信号检测 Agent 返回触发信号列表
    ↓
(如果有触发) 主控制器 调用 分析推理 Agent
    ↓
分析推理 Agent 返回分析报告
    ↓
主控制器 调用 推送 Agent
    ↓
推送 Agent 分发告警 (控制台/文件/微信)
    ↓
主控制器 生成执行日志
```

## 🚀 使用说明

### 1. 安装依赖

```bash
cd financial-signal-monitor
npm install
```

### 2. 配置监控列表

编辑 `config/watchlist.json`:

```json
{
  "stocks": [
    {
      "code": "sh600519",
      "name": "贵州茅台",
      "market": "A股",
      "enabled": true
    }
  ]
}
```

### 3. 配置信号阈值

编辑 `config/signals.json`:

```json
{
  "signals": [
    {
      "id": "price_surge",
      "name": "价格异动",
      "params": {
        "threshold_percent": 5.0
      },
      "enabled": true
    }
  ]
}
```

### 4. 手动执行

```bash
node src/index.js
```

### 5. 设置自动化 (WorkBuddy Automation)

在 WorkBuddy 中创建自动化任务：

```yaml
name: "金融信号监控 - 每30分钟"
schedule: "FREQ=HOURLY;INTERVAL=0.5"
command: "node c:\\Users\\asus\\WorkBuddy\\20260429203017\\financial-signal-monitor\\src\\index.js"
```

## 📊 项目阐述 (用于表单第04题)

### 项目名称

**Financial Signal Monitor — 基于 Agent 的金融信号监控与自动推送系统**

### 核心痛点

个人投资者在股票监控中面临三大痛点：
1. **信息碎片化**: 需要在多个平台切换查看行情，容易错过关键异动信号

3. **数据来源单一**: 单一数据源可能存在延迟、字段不全、跨市场支持不一致

### 核心逻辑流

本系统采用 **多 Agent 协作架构**，实现从数据采集到告警推送的完整自动化链路：

**1. 长链推理能力**:
- 不仅是简单的阈值判断，而是综合多个信号进行推理

**2. 多 Agent 协作**:
- **数据采集 Agent**: 并行调用 `westock-data` 和 `neodata-financial-search` 双数据源
- **信号检测 Agent**: 运行4种检测算法（价格/成交量/资金/MACD）

- **推送 Agent**: 多级分发告警（控制台/文件/HTML/微信）

**3. 自动化执行**:
- 通过 WorkBuddy Automation 实现定时调度（如每30分钟执行一次）
- 自动保存执行日志和触发记录，支持历史回溯

**4. 双数据源协同**:
- `westock-data`: 提供精确的K线、资金流向、技术指标（覆盖A股/港股/美股）
- `neodata-financial-search`: 提供自然语言查询能力（覆盖宏观/财报/研报/事件）

### 技术亮点

1. **Agent 自主性**: 无需人工介入，自动完成"采集→检测→分析→推送"全链路
2. **智能推理**: 不是简单的规则判断，而是综合多维度信息进行推理

## 📝 第05题回答: 小想法

### 想法: 嵌入式 AI 调试助手

**方向**: 针对 STC15/51 单片机开发，构建一个能读懂时序图、直接生成驱动代码的 Agent

**痛点**:
- 单片机开发需要频繁查阅 datasheet，配置寄存器
- 时序图理解错误导致硬件不工作，调试困难
- 现有工具缺乏"理解时序图→生成代码"的能力

**实现思路**:
1. **Agent 读取时序图** (通过 OCR 或用户上传图片)
2. **Agent 理解时序约束** (建立时间、保持时间、时钟频率)
3. **Agent 生成驱动代码** (自动配置寄存器，生成延时函数)
4. **Agent 验证代码** (检查时序是否满足 datasheet 要求)

**技术栈**:
- 视觉识别: 读取时序图
- 代码生成: 针对 C51 架构优化
- 验证: 对比 datasheet 约束
