# 数鉴 Agent

面向真实表格与文档的数据分析、可视化比赛作品。当前主流程是“导入真实数据 → 默认 AI 初步定位 → 窗口助手明确目标与口径 → 确认计划 → 真实计算与证据回查”。不包含内置虚构业务数据，不提供模拟 AI 答案。MCP 暂缓。

## 安装与启动

需要 Node.js 24.16+（24 系列，本机验证版本 24.16.0）和 npm。在项目根目录执行：

```sh
git clone https://github.com/chenxuanmo123-ops/sui.git
cd sui
npm ci
npm run dev
```

浏览器打开终端实际显示的地址。默认端口 5173，被占用时 Vite 会换端口。新版命令同时启动前端和 AI 服务端接口；如原来运行的是纯 Vite，请关闭旧开发进程后重新执行。没有模型配置仍能上传与手动计算，但 AI 规划按钮不会生成假答案。

## 在网页中连接真实模型

点击右上角“连接 AI 模型”（或 AI 助手的配置按钮），添加连接，填写名称、API Base URL、API Key 与模型 ID，然后“保存并使用”。可以添加多套连接，在 AI 助手中切换；编辑配置或切换后旧计划失效。无需创建 .env。

- “获取列表”实际调用所填服务的 /models；部分供应商不支持，可手动输入模型 ID。
- “测试连接”实际调用 /chat/completions，发送一个简短文本请求，会消耗少量 token。成功仅表示文本调用成功；结构化分析兼容性在首次规划时校验。
- 本机访问时，连接保存在 .local/model-connections.json，包含明文 API Key，刷新与服务重启后仍可使用。该目录已排除 Git，也禁止通过开发服务器读取；网页状态接口不读回密钥。编辑时密钥留空保留原值，填写新值替换，删除连接清除该条配置。请勿把 .local 随项目打包公开。
- 可勾选“设为内置 AI 的默认分析模型”。默认模型用于上传后的初步定位；助手可以独立选择其他模型。浏览器记住助手选择与自动定位授权，localStorage 不保存密钥。
- 远程访问不能修改本机连接或默认模型；远程自填密钥仍只存当前页面内存，刷新后重填。
- 测试、模型发现和分析由本站 Node 服务端转发到所指定接口。已保存的密钥由本机服务读取，不回传状态接口，不放入分支或报告。当前持久化适用于单机使用，尚不是多用户凭据系统。
- 仅支持 OpenAI 兼容 Chat Completions。接口地址应保留服务商要求的完整版本路径；自动追加 /chat/completions。如已填写完整 /chat/completions 地址，会去掉后缀再统一组装。当前没有 Responses API、原生 Anthropic/Gemini 协议或流式 SSE。
- 默认启用 JSON 模式；服务商不支持 response_format 时可关闭。无论开关状态，计划和解读都需要通过结构与引用校验。

部署者也可选用服务端预配置：把 .env.example 复制为 .env，填写以下字段并重启。预配置在网页中作为只读连接选择，密钥不返回浏览器。

```dotenv
LLM_BASE_URL=供应商提供的兼容接口根地址
LLM_API_KEY=你的真实密钥
LLM_MODEL=供应商支持的实际模型 ID
LLM_PROVIDER_NAME=页面显示名称
LLM_JSON_MODE=true
```

多套服务端预配置用 LLM_PROVIDERS_JSON，格式见 .env.example。不要把真实密钥提交 Git 或发到聊天。当前不自动跨模型重试。

## 实际工作流程

1. 上传真实 UTF-8 CSV、Excel（XLSX / XLS）或 PDF，也可主动加载 Our World in Data 的真实公开能源 CSV。Excel 先选工作表、表头与范围；PDF 先选页并对照原页核对提取内容；确认后进入分析。初始为空，不自动选定业务场景。
2. 在画布“数据初步定位”授权调用默认模型，查看候选场景、行粒度、字段角色、风险、澄清问题与建议方向。默认只发送元数据，可补充真实业务背景并单独授权少量样本。自动定位需勾选授权，之后新文件自动发送字段与质量摘要。初步定位不执行业务计算，所有候选含义均需确认。
3. 点击右下角打开 AI 分析助手，或点击建议方向带入问题和已填背景。窗口可拖动、展开、收起，收起保留本次会话输入与计划。填写分析目标；业务背景、每行代表什么、字段定义和单位均可选填。原始样本与有限类别字典分别授权，默认均关闭。类别字典只包含符合上限的文本列完整取值；高基数或超长列整列省略，不发送频次。
4. 授权把目标、背景、字段质量统计，以及独立勾选的样本或类别字典发送给模型。完整文件仍在浏览器中；用户在背景中主动填写的数据也会发送。
5. AI 提出数据适用场景、行粒度、字段理解、假设、待澄清问题与任务计划。有可执行任务和待确认问题时可以先确认并查看安全结果；只有任务为空时才需要补充信息后重新规划。
6. 用户核对指标、单位、筛选、时间分桶与汇总方式后确认，浏览器执行受约束的计算任务。逐任务保留成功结果并列出真实错误；全部失败也保留修正入口。点击“让 AI 修正失败任务”可提交原失败任务和执行错误，查看修正前后口径；重新确认后只重算失败任务，成功结果保留。每次规划最多请求两轮修正（前端流程限制）。
7. 程序把每个任务首项、末项、最低与最高分组的去重摘要发给模型作辅助解读。该摘要不是完整序列，不能据此证明持续趋势。引用可定位相应图表与原始记录。
8. AI 解读失败时，真实计算结果保留，可单独重试解读。改变目标、背景、样本或类别授权、数据或模型后需重新规划。后续问题可返回目标框重新规划。
9. 导出当前任务的结果 CSV、SVG 和 HTML 证据报告，或在本轮分析结果中导出所有成功任务的完整 HTML。完整报告包含多任务图表、SQL、参数、事实、已有 AI 解读、失败任务与出处；单任务报告只包含该项计算与证据。

## 已实现能力和边界

- React + TypeScript + Vite 前端，原生 Node.js AI 服务；SheetJS 0.20.3 解析 Excel，PDF.js 6.4.299 解析 PDF，解析器按需加载。
- 左侧数据导航、完整分析画布、上传后的 AI 初步定位、点击打开的浮动助手；手动字段计算折叠为辅助工具。
- 网页内模型配置、发现与连接测试、多供应商切换、结构化分析规划、安全任务与待澄清问题并存、人工确认、失败反馈与确认后重算、计划失效校验、结果解读与证据定位。
- SQLite / sql.js 在 Web Worker 中真实执行参数化只读 SQL；支持求和、均值、记录数、非空原值去重数、最小值和最大值，单列分组、精确筛选、最多六个附加条件、标准日期按月或年分桶。SQL、参数、数据指纹和来源记录绑定保存。数据库设为 query_only，不开放任意 SQL 输入；单次计算超时 30 秒会终止 Worker。
- 新增“数据处理”：全量空值、严格数值、唯一值、首尾空白、重复行、中位数、四分位与 IQR 异常候选。清理先预览、再确认，可撤销；处理后生成新快照，旧结果清空，保留原文件定位。异常候选不会自动删除。
- 新增“探索分析”：ECharts SVG 折线图、柱状图、散点图、热力图与结果表；分组、指标、聚合、筛选、排序和展示上限可选。点击图形或来源按钮回查记录，支持 CSV / SVG / 单文件 HTML 导出。Top N 与前 N 项明确标注。
- 新增“对比诊断”：两个不重叠期间的求和／记录数对比，按维度显示差额、变化率和净差额份额；只有一期有记录时不补零、不计算该组差额，存在缺期分组时停止计算贡献份额。用户需确认粒度、单位和可加性，分解不证明因果。
- 探索与对比配置、结果、选中证据在导航间保留，并随当前工作区保存到此浏览器；换数据或应用／撤销清理会清空当前分析配置。两类页面可以把分析上下文带入窗口 AI 助手，仍需要重新规划和确认计算。原公开能源规则入口作为辅助工具，不作为 AI 能力展示。
- 缺失或非数值不按零参与运算；类型检测仅为候选。格式错误不静默修复，不自动确定业务含义。
- 目前不支持任意 SQL 编辑、跨表关联、加权均值、回归、预测、因果识别或连续自主 Agent 重规划。失败任务的有限修正仍需人工确认。AI 计划目前生成六种聚合的折线／柱状任务；散点、热力与期间分解在独立探索／对比页面执行，尚未纳入统一自动 Agent 工具循环。Excel 一次载入一张工作表；PDF 一次载入一页中的一张表，尚不支持自动跨页合表或任意文档自动还原。
- 引用存在性、输出结构与部分数字/因果表述受到程序校验；这不能保证模型所有语义与推论正确。需要结合原数据核查。
- 计算使用双精度浮点数，不适合精确财务记账。没有代表性抽样依据时不能推断全网用户偏好；财报时点余额不能随意跨期相加。
- 文件上限 30 MB、100,000 行、200 列；最多显示 200 个分组。未作极限规模性能认证。
- 原始预览前 20 个记录 / 8 列；HTML 内嵌前 1,000 个参与计算的记录，另保留各分组全部来源记录号。CSV 记录号不等于有换行单元格的物理行号。
- 当前数据、出处备注、处理撤销记录、分析路径和结果自动保存到此浏览器。页面显示“已保存到本机”后刷新可恢复；恢复不自动重复调用模型。新导入会替换当前工作区，清除前有确认入口，模型连接配置独立保留。尚无跨设备同步、多个工作区管理或多标签页冲突保护。

## 图表交互

- 分组图与右侧操作区联动：点击图形或定位分组，核对数值后可直接查来源、限定该分组继续追问；完整结果表按需展开。
- 支持横纵方向、排序、参考线与数值标签、SVG 导出和放大查看。显示设置可点击外部或按 Esc 收起；放大继承当前显示设置，关闭返回原按钮。
- 超过 12 个分组可分段浏览，坐标范围始终覆盖全部分组；完整分析 HTML 导出全部分组。
- 探索图支持来源联动和缩放；探索／对比报告保留当前图表视图，同时包含本次 SQL 返回的完整结果表。查询展示上限仍适用。

## Excel、PDF 与多模态入口

- Excel：最多 50 张工作表，选择其中一张；支持指定表头、数据截止行、预览与手工修订。显示合并单元格、隐藏行或表、公式缓存、无缓存公式和错误单元格警告。合并单元格不自动向下补值；宏、外部链接、嵌入图片不执行、不作为表格数据。
- 数值保留底层值，编号的零填充格式保留前导零，日期保留时刻。百分比格式使用底层比例（15% 为 0.15），明确提示用户确认单位；不自动换算金额单位。公式仅使用文件已有缓存，没有缓存时保持空，错误值保留为文本。应用不重算 Excel 公式。
- PDF：最多 100 页，按页提取文字位置并生成表格候选，同时渲染原页供对照。选真正表头与数据范围，修订错误后勾选确认；没有文字层的扫描件不会虚构文字。复杂表头、旋转文字、特殊字体或多表混排仍需人工核对，不能保证任意 PDF 自动还原。
- 多模态：PDF 导入窗口可选择支持图片输入的真实模型，单独授权发送当前页 JPEG。仅兼容 Chat Completions 的 image_url 内容格式；模型不支持图片时会报错。结果经过服务端列名、行宽、字符串、规模等契约校验，再次显示为待核对候选。失败保留已有候选。当前没有内置免费视觉模型、原生图片文件入口、批量 OCR 或 OCR 准确率承诺。
- 对逗号千分位、货币符号、括号负数等非纯数字文本，不会偷偷去符号后计算；可在“数据处理”明确选中字段并预览后规范严格千分位；货币符号、括号负数等仍需在导入预览或源表中核对修订。财务单位和统计口径仍须确认。
- 文件原始 SHA-256、工作表或页码、来源行位置、解析方法与警告会进入来源视图与单文件 HTML 报告；PDF 原页以 JPEG 内嵌，图表以 SVG 内嵌。PDF 的“提取行”是版面读取行或模型转录行，不是可靠的 PDF 物理行号。手工修订会记录在读取方法中；尚无逐单元格修改审计历史。
- 导入预览最多显示前 50 行，可通过行号指定更后面的表头和数据末行。一次完整工作簿最多读取 200 万个矩形单元格。确认导入后的数据和分析路径会保存到当前浏览器工作区；未确认的导入预览不保存。

## 公开数据来源

主动选择“加载公开数据”时访问 OWID energy-data 仓库中的 owid-energy-data.csv。页面“数据与来源”提供仓库与实际 CSV 链接、载入时间及 SHA-256。来源持续更新，以本次实际载入的快照为准；网络失败明确报错，可以上传已有真实文件。本项目不自带虚构样例数据，也不保证 GitHub 来源随时可达。

## 构建与服务部署

```powershell
npm run build
npm start
```

npm start 由 Node 服务同时托管 dist 和 AI 接口，默认 127.0.0.1:5173，使用 HOST/PORT 调整。npm run preview 只是静态产物预览，没有 AI 后端。开发与生产默认都只监听本机。网页自填接口在本机访问时允许 HTTPS 及 localhost HTTP 模型；公网访问必须由部署者通过 LLM_ALLOWED_HOSTS（逗号分隔的精确主机名）允许目标域名，且只允许 HTTPS，不跟随重定向。公网部署说明见 [部署与交付](docs/部署与交付.md)。仓库提供 Render 配置、Dockerfile 与生产冒烟检查；添加这些文件不代表线上服务已经开通。当前保留基础同源检查、并发和频率限制，实际公网域名、供应商连通性和评审访问仍需在部署后验收。

```powershell
npm run build
npm run test:core
npm run test:evaluation
npm run test:ai
# 启动隔离开发服务后，也可验证私有配置目录不被静态访问
node tests/static-boundary-acceptance.mjs
python -m pip install --target .tools/python playwright
$env:TEST_BASE_URL="http://127.0.0.1:5173"
python tests/browser_acceptance.py
python tests/core-browser-acceptance.py
python tests/ai-browser-acceptance.py
python tests/model-browser-acceptance.py
# 转换已取得的真实 OWID 子集作为格式验证文件；需要 Pillow
python -m pip install --target .tools/python pillow
python tests/create-import-fixtures.py
python tests/import-browser-acceptance.py
python tests/document-vision-browser.py
# npm run build 后，在隔离配置及 5181 端口启动 npm start，再执行
python tests/production-import-smoke.py
```

Python 测试使用本机 Microsoft Edge；先启动开发服务。模型浏览器测试会创建、编辑和删除连接，请用隔离配置启动测试服务：设置 SHUJIAN_CONFIG_PATH=artifacts/browser-model-store.json 后执行 npm run dev，并令 TEST_BASE_URL 与实际端口一致；不要针对保存了个人配置的服务运行模型测试。静态边界脚本默认使用 5180，也可用 TEST_BASE_URL 调整。browser_acceptance.py 从公开来源读取真实数据并独立计算预期结果，生成真实子集到 artifacts。当公开来源暂时不可达且 artifacts 中已有此前实际获取的 OWID 子集时，可设置 TEST_OWID_FILE 为该文件绝对路径运行回归；这只验证真实缓存文件路径，不算联网通过。core-browser-acceptance.py 与 ai-browser-acceptance.py 直接读取 tests/fixtures 中附来源的真实子集计算，并通过明确的接口替身测试 AI 交互流程。model-browser-acceptance.py 则验证浏览器填写配置 → 真实应用后端 → 本地 HTTP 上游替身的完整链路，包括两套密钥/模型切换、本机配置跨刷新恢复、留空编辑保留密钥、默认定位与助手模型独立、样本授权、窗口交互和四档响应式。接口替身和人为解析字符串仅用于测试，不进入产品，不代表真实模型评测。“内置 AI”是应用预置的分析流程和默认连接入口，不包含模型权重或厂商额度，需首次配置真实接口（或由 .env 预置）。此前上述契约与浏览器回归使用明确替身。2026-10-19另使用已保存默认模型完成世界银行原始XLS的真实网页规划与解读，数值核对通过，解读仍有冗余和口径过度保守；没有真实视觉准确率成绩。连续重复运行模型集成测试可能触发应用每分钟限流；各轮使用新的隔离服务进程。

`npm run test:core` 与 `npm run test:evaluation` 是独立套件。后者使用固定 SEC 响应快照和经过字段筛选的 Stack Exchange 来源快照，校验来源哈希、固定申报和问题 ID、真实 SQL 结果以及财务存量/流量与平台样本范围口径；它不调用模型，不是 AI 准确率成绩。SEC 或 Stack Exchange 夹具只有在人工审阅后显式运行对应 `fetch-*-fixture.mjs --update` 才会更新，脚本无参数时拒绝覆盖。Stack Overflow 夹具为 61 条单标签过滤事件，只代表该查询结果，不代表平台总体或用户偏好。
