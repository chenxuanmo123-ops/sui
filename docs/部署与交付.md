# 公网部署与交付

当前源码已上传 GitHub，公网运行服务尚未创建。代码仓库地址不能作为在线演示地址提交。

## Render 部署

仓库提供 [render.yaml](../render.yaml)，在 [Render 部署入口](https://render.com/deploy?repo=https://github.com/chenxuanmo123-ops/sui) 登录负责人账号并授权访问本仓库，检查配置后创建服务。

| 配置 | 值 |
| --- | --- |
| 运行环境 | Node.js 24.16.0 |
| 构建命令 | `npm ci --include=dev && npm run build` |
| 启动命令 | `npm start` |
| 健康检查 | `/api/health` |
| 监听地址 | `HOST=0.0.0.0`；`PORT` 使用平台提供值 |

创建时填写 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，为在线访客提供默认分析模型。密钥只填云平台环境变量，不上传仓库或填入前端变量。其他配置见 [.env.example](../.env.example)。公网访客自填供应商接口时，还需配置 `LLM_ALLOWED_HOSTS` 精确域名白名单。

一个 Node 服务同时提供网页与 AI 接口。GitHub Pages 无法直接运行本项目的 Node AI 后端。模板选择免费实例，实例空闲会休眠；评审期间如需持续可用，应由负责人选择合适的服务方案。当前关闭自动部署，后续在控制台手动部署确认过的提交。

参考：[Render Blueprint 配置](https://render.com/docs/blueprint-spec)、[免费实例限制](https://render.com/docs/free)。

## 其他 Node / Docker 平台

支持 Node 24 的云平台可沿用上表命令。已有 Docker 环境可执行：

```sh
docker build -t shujian-agent .
docker run --rm -p 5173:5173 --env-file .env shujian-agent
```

容器中使用 `HOST=0.0.0.0`，由平台或反向代理提供 HTTPS。镜像不包含本机凭据与测试数据；当前开发环境未实际构建 Docker 镜像。

## 上线验收

GitHub Actions 自动检查构建、核心计算、评测契约、AI 接口和生产路由，不调用真实付费模型。部署完成后，还需对实际公网地址完成以下核对：

1. 首页与 `/api/health` 可访问，刷新与静态资源正常。
2. 上传真实 CSV / Excel / PDF，检查字段、范围与 PDF 提取结果。
3. 调用实际模型，确认计划，执行 SQL 并核对图表和原始行。
4. 进行范围追问，导出 HTML 报告并核对来源与证据。
5. 验证远程访问无法读取凭据或修改服务端模型配置。

最后把实测通过的 HTTPS 地址写入仓库首页及参赛材料。模型费用由部署者承担；现有限流按连接地址计算，反向代理后多个访客可能共享额度，需验证实际并发体验。浏览器工作区只在当前设备与站点保存，不是云端同步。
