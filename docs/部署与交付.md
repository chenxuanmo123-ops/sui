# 数鉴 Agent：部署与交付

截至 2026-10-22，代码已推送到本仓库 main；代码提交 `64913ad` 的 GitHub Actions 构建与全部自动测试已通过。尚未创建公网运行服务，当前没有可交付的线上演示 URL。

## 运行结构

生产由一个 Node.js 24 服务同时提供 `dist` 网页和 `/api/ai/*`，浏览器执行真实 SQLite 与图表渲染，服务端保管部署者模型密钥。不使用 GitHub Pages 承担 AI 服务。MCP 当前暂缓。GitHub 上传、云端部署与正式比赛材料提交是三个独立步骤。

## 克隆与本机运行

```sh
git clone https://github.com/chenxuanmo123-ops/sui.git
cd sui
npm ci
npm run dev
```

无需模型即可导入真实文件并手动计算。启用 AI 时在本机网页配置连接，或复制 `.env.example` 为 `.env`，填写真实接口。浏览器不包含 API Key。

## Render 部署配置

仓库根目录提供 `render.yaml`。登录自己的 Render 账号，选择 New → Blueprint，连接本仓库并检查配置后创建服务。模板选择免费预览实例，不自动购买付费实例；`autoDeployTrigger: off` 防止代码推送立即改变已确认的比赛版本。后续更新需在控制台手动部署目标提交。

也可手动创建 Node Web Service：

| 项目 | 值 |
| --- | --- |
| Node | 24.16.0 |
| Build | `npm ci --include=dev && npm run build` |
| Start | `npm start` |
| Health check | `/api/health` |
| HOST | `0.0.0.0` |
| PORT | 使用平台提供值 |

模型配置直接填控制台环境变量：`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、可选 `LLM_PROVIDER_NAME` 与 `LLM_JSON_MODE`。密钥不要填仓库、聊天、截图或前端 `VITE_` 变量。`LLM_PROVIDERS_JSON` 可配置多模型；具体格式见 `.env.example`。未配置时网页明确显示没有可用模型，不返回模拟 AI。

公网访问者自填供应商接口需要 `LLM_ALLOWED_HOSTS` 精确域名白名单，只支持 HTTPS。建议比赛展示先由部署者配置默认分析模型，避免要求评委提供自己的密钥。公网访问不能保存、编辑服务端模型连接。

免费实例的休眠、配额、网络位置及供应商可达性会影响展示，应按平台当时政策评估。评审要求持续可用时，应由负责人选择满足要求的部署资源，不能把免费预览当作可用性保证。代码模板本身不预购任何服务。

参考官方配置说明：https://render.com/docs/blueprint-spec 、https://render.com/docs/free 。

## Docker 部署

```sh
docker build -t shujian-agent .
docker run --rm -p 5173:5173 --env-file .env shujian-agent
```

容器镜像仅包含构建网页与 Node 服务，不包含本机 `.local`、`.env`、测试数据或开发工具。容器的 `.env` 中应删除本机专用的 `HOST=127.0.0.1`，或改成 `HOST=0.0.0.0`；宿主机应提供 HTTPS 反向代理。当前环境没有 Docker 引擎，因此镜像配置需在具备 Docker 的机器或云构建器实际构建验证。

## 上线验收与运行限制

发布前执行：

```sh
npm run build
npm run test:core
npm run test:evaluation
npm run test:ai
npm run test:production
```

生产冒烟启动隔离配置服务，不读取本机保存的真实连接，不调用模型；检查构建资源、WASM/PDF Worker MIME、健康接口、私有路径、SPA、远程连接管理拒绝策略。线上还必须用实际评审浏览器核对首页、真实 CSV/Excel/PDF 导入、模型规划与实际 SQL、图表证据、追问和 HTML 导出。域名存在或健康接口通过不能代替全流程验收。

当前浏览器工作区仅保存到当前设备和站点，换设备或域名不会自动同步。服务器没有多用户体系；默认模型额度由部署者承担。现有限流基于服务端 socket 地址，反向代理后可能多个访问者共享限流；当前不盲目信任访问者提供的转发 IP。评审前需核对实际代理与并发体验，必要时在平台入口增加访问控制和额度措施。大规模数据和复杂扫描 PDF 没有任意精度或规模保证。

GitHub Actions 会在正常推送和 PR 后验证代码；此前未提交阶段不能补造开发历史。仓库上传成功后，还应在控制台创建云服务、配置模型、核验真实公网 URL，再填写比赛在线演示地址。
