# 公网部署与交付

当前源码已上传 GitHub；前端与同源 AI 接口都通过 Cloudflare Pages 部署。代码仓库地址不能作为在线演示地址提交。

## Cloudflare Pages（当前部署）

- 地址：<https://sui-ae9.pages.dev/>；项目名 `sui`，推送 `main` 触发自动构建。
- 路由：`functions/api/` 处理 `/api/ai/*`、`/api/health` 与未知 `/api/*`（返回 JSON 404），与 Node 服务共用 `server/ai.mjs` 的计划校验、提示词、证据约束与限流。
- 环境变量：`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`；可选 `LLM_PROVIDER_NAME`、`LLM_JSON_MODE`、`LLM_PROVIDERS_JSON`。允许访客自带密钥时，`LLM_ALLOWED_HOSTS` 填精确域名（逗号分隔），否则公网请求会被拒绝。密钥只写在 Cloudflare，不写入前端变量或仓库；环境变量只在新建部署时注入，改完需重新部署。
- 未配置模型时 `/api/ai/status` 返回 `configured:false`，页面仍可导入、计算和出图，状态栏会明确提示。
- Pages Functions 运行在 Workers：没有本机文件系统，网页端保存/删除模型连接返回 403（预期行为，模型配置只能在 Cloudflare 环境变量里维护）；免费计划每请求约 10 ms CPU，慢模型、大 PDF 视觉转录或超大 JSON 可能超出额度，需要稳定长任务时改用 Render / Node 服务。
- 未知路径仍会被 SPA 回退成 HTML，但 `/api/*` 已显式返回 JSON；健康检查要同时核对 `content-type` 与响应体，不能只看状态码。
- `POST /api/ai/web-lookup`（联网查术语）只用维基百科公开接口，不需要模型，不读取用户数据，网页内容不进入计划与证据链。部署方网络访问不了维基百科时，可在 Node 服务设置 `WEB_LOOKUP_PROXY` 转发到自己部署的同一路由；只接受 HTTPS，不接受前端传入的任意 URL。
- 服务端配置 Key 后，访客请求会消耗部署者额度；限流按来源地址计算，反向代理后可能共享额度。

## Render 部署（完整 Node 服务方案）

仓库提供 [render.yaml](../render.yaml)，在 [Render 部署入口](https://render.com/deploy?repo=https://github.com/chenxuanmo123-ops/sui) 登录负责人账号并授权访问本仓库，检查配置后创建服务。

| 配置 | 值 |
| --- | --- |
| 运行环境 | Node.js 24.16.0 |
| 构建命令 | `npm ci --include=dev && npm run build` |
| 启动命令 | `npm start` |
| 健康检查 | `/api/health` |
| 监听地址 | `HOST=0.0.0.0`；`PORT` 使用平台提供值 |

创建时填写 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，为在线访客提供默认分析模型。密钥只填云平台环境变量，不上传仓库或填入前端变量。其他配置见 [.env.example](../.env.example)。公网访客自填供应商接口时，还需配置 `LLM_ALLOWED_HOSTS` 精确域名白名单。

一个 Node 服务同时提供网页与 AI 接口。Cloudflare Pages 静态托管和 GitHub Pages 都无法直接运行本项目的 Node AI 后端。模板选择免费实例，实例空闲会休眠；评审期间如需持续可用，应由负责人选择合适的服务方案。当前关闭自动部署，后续在控制台手动部署确认过的提交。

参考：[Render Blueprint 配置](https://render.com/docs/blueprint-spec)、[免费实例限制](https://render.com/docs/free)。

## 其他 Node / Docker 平台

支持 Node 24 的云平台可沿用上表命令。已有 Docker 环境可执行：

```sh
docker build -t shujian-agent .
docker run --rm -p 5173:5173 --env-file .env shujian-agent
```

容器中使用 `HOST=0.0.0.0`，由平台或反向代理提供 HTTPS。镜像不包含本机凭据与测试数据；当前开发环境未实际构建 Docker 镜像。

## 上线验收

GitHub Actions 自动检查构建、核心计算、评测契约、AI 接口和生产路由，不调用真实付费模型。部署完成后，还需对实际公网地址完成以下核对：

1. 首页与 `/api/health` 可访问；`/api/health` 必须返回 JSON 且 `status` 为 `ok`，不能是 SPA 的 HTML。刷新与静态资源正常。
2. 上传真实 CSV / Excel / PDF，检查字段、范围与 PDF 提取结果。
3. 调用实际模型，确认计划，执行 SQL 并核对图表和原始行。
4. 进行范围追问，导出 HTML 报告并核对来源与证据。
5. 验证远程访问无法读取凭据或修改服务端模型配置。

最后把实测通过的 HTTPS 地址写入仓库首页及参赛材料。模型费用由部署者承担；现有限流按连接地址计算，反向代理后多个访客可能共享额度，需验证实际并发体验。浏览器工作区只在当前设备与站点保存，不是云端同步。
