## 1. 一页摘要

**产品**：数鉴 Agent——对真实表格数据进行可追问、可质询、可核验的 AI 分析工作台。

**用户任务**：上传 CSV/XLSX，提出中文问题；系统先识别字段与分析口径，必要时征询用户，再由联网模型规划并调用实际数据工具调查，随着计算完成逐步呈现图表和结论。用户可以随时询问“这个数字怎么算的”“只看某一群体呢”“换一种合理口径结论还成立吗”；系统应解释或重新计算，而不是继续生成无出处的话术。最终导出固定在特定数据版本和分析分支上的单文件 HTML 报告。

**竞争主张（待验证，不是已证实优势）**：不是“自然语言直接生成一张图”，而是 **口径协商 → 真实调查 → 挑战结论 → 可核验交付**。不得声称比现有分析产品必然先进、对任意数据准确、保证获奖或值得投资；这些是验证命题。

**P0 成功定义**：公网评审地址可独立完成七步旅程（无需开发者电脑开机）；两类经授权的真实数据各跑通端到端任务；关键口径不明确时主动澄清；至少一次模型根据真实工具结果调整下一步；页面数值与证据可核对；追问重新查询，合理的替代口径重算；报告可离线打开；模型/工具失败不展示假成功。

## 2. 背景、用户与范围

### 2.1 要解决的问题

- 用户不清楚字段、记录粒度、单位、期间、样本与分母，直接问答容易答非所问。
- 图表给出数值，却无法核对对应计算、查询范围与数据版本。
- 一次性报告不能承接对图表和结论的即时追问；更改筛选或口径后容易沿用旧结果。
- 只显示单一口径容易把相关性当因果、样本当总体、累计值当当期值。

**目标用户**：拥有可合法使用表格文件、能描述业务问题但不擅长 SQL 的研究者、业务分析者和项目负责人。P0 面向单个使用者的公网可访问分析会话，不做完整多用户协作和权限系统；公网隔离不同访问者上传数据仍属安全必需。

### 2.2 数据适用范围与边界

| 数据 | P0 可验证的能力 | 必须提醒或拒绝的推断 |
| --- | --- | --- |
| 规范化财务指标表（单表、字段可映射） | 按主体、指标、币种、单位、期间、当期/累计方式筛选和比较；同口径趋势与拆解 | 不同单位、币种或季度/累计值直接比较；把财务指标等同投资建议；声称支持任意财报 PDF |
| 调查表／平台使用记录表（单表） | 识别记录粒度、问卷多选/单选、平台使用次数、首选选项、样本数和分母；做样本内比较 | “使用次数”自动代表“偏爱”；便利样本代表“全网”；没有抽样设计就给总体置信结论 |
| 其他字段明确的单表 | 上传、质量报告、基础分组/趋势/筛选；用户确认字段后尝试分析 | 未经该类型测试就保证正确分类、任意文件自动解释、自动跨表关联 |

**真实数据约束**：业务数据只来自用户上传的真实文件，或有可核查发布机构、原始地址、取得时间及使用条件的真实公开文件快照；公开文件也经上传流程导入。**禁止**虚构、合成、随机生成业务数据、预制“标准答案”当实际运行结果。来源声明来自用户时标为“用户声明、未经独立核实”；SHA-256 仅确认参与分析的文件版本，不证明数据客观真实。P0 不做任意 URL 抓取，不在 UI 中把历史快照说成实时网络数据。

**支持限制**：默认单工作表/单表；多工作表需人工选其一；不支持 PDF/OCR 解析、扫描版财报、跨表自动关联。大型文件须显示可配置的大小/行数限制及拒绝原因，具体阈值在性能测试后确定，不先承诺任意规模。

### 2.3 非目标

通用聊天、实时外部业务系统接入/高频动态数据流、预测性机器学习、金融投资建议、无证据因果判断、多用户权限系统；不为比赛包装“断网时 AI 仍在工作”的假演示。

### 2.4 产品目标与成功判据

| ID | 目标 | 验证方法（不是预设成绩） |
| --- | --- | --- |
| G-01 | 不把模糊问题硬算成确定答案 | 两类真实数据各含歧义问题；观察是否先确认影响答案的口径及能否回看确认记录 |
| G-02 | 数字可信并可独立复算 | 对关键数值逐条从查询与参数复算；记录通过数/受检数和不一致原因 |
| G-03 | 分析具备交互性而非一次性文章 | 追问至少一次切换筛选或指标；检查是否新增真实查询及同步更新图表 |
| G-04 | 结论具备可质询性 | 至少一次有理据的替代口径挑战；比较两分支结果和证据，标记不适用的挑战 |
| G-05 | 用户能理解而非只看到技术术语 | 未参与开发的使用者实际完成上传、解读数字与导出；记录卡点和是否理解“样本≠总体” |

以上是**验收任务与计量方式，不宣称已达到目标**；用户研究尚未开展。不得用未经测量的“准确率”“节省时间”或投资回报包装成果。

## 3. 核心体验与页面信息架构

```text
数据入口（上传、工作表、来源与版本）
 └─ 数据工作区（字段概览、质量提示、分析口径确认）
     └─ 分析工作台
         ├─ 主画布：问题、执行状态、渐进图表、结论与限制
         ├─ 常驻「问数鉴」：针对图表/点/结论追问和重新分析
         ├─ 证据抽屉：指标、SQL、结果、原始记录定位和来源
         ├─ 执行抽屉：计划、真实 MCP 调用、结果、重规划与错误
         ├─ 挑战对照：原分支与替代口径分支并排比较
         └─ 报告预览及单文件 HTML 导出
```

**主流程**：导入 → 检查 → 用户提问 → 关键口径澄清/确认 → 模型提出计划 → MCP 工具真实执行 → SSE 渐进展示 → 观察与重规划 → 审计结论 → 随时追问/挑战 → 导出。图表针对已完成查询增量呈现，失败中的查询不得显示为成功；技术日志不应遮挡核心发现。

**“实时”定义**：P0 的实时是**运行过程事件及查询结果逐步到达浏览器**，而不是接入持续变化的数据源。图表保存查询定义、绑定数据版本，为未来新增数据版本后按需重算留接口；旧结论永不被新数据静默覆盖。

| 页面/区域 | 入口与用户任务 | 核心组件 | 空态或错误态 |
| --- | --- | --- | --- |

## 4. 功能需求（P0）

以下每项均须有能现场复现的验收；“模型给出的文字”本身不能证明工具执行或数值正确。

### 4.1 P0 范围索引

| 模块 | 需求 ID | 优先级 | 核心交付/验收重点 |
| --- | --- | --- | --- |
| 真实数据入口 | FR-01—FR-02 | P0 | 来源、版本、字段与质量报告 |
| 口径与调查 | FR-03—FR-06 | P0 | 关键歧义澄清、模型观察、真实 MCP/安全 SQL |
| 图表与证据 | FR-07—FR-08 | P0 | 逐步渲染、数值可追溯 |
| 追问与挑战 | FR-09—FR-10 | P0 | 真重算、保留原分支 |
| 报告与可靠性 | FR-11—FR-13 | P0 | 单文件报告、故障透明、数据版本控制 |

### 4.2 功能详情及验收条件
#### 4.2.1 FR-01 真实数据导入与溯源

**要求**：上传 CSV/XLSX；识别编码、分隔符、表头与可选工作表；展示预览、总行列数，保留受控原始文件和文件 SHA-256，生成 `datasetId`/`datasetVersion`。收集来源类型：用户自有数据/公开来源文件；公开来源记录发布机构、原始链接、快照取得时间、许可或使用条件及无法核实说明。用户可移除数据，移除后阻止后续分析访问。仅上传成功且解析成功的数据进入分析。

**验收**：同一文件可复查哈希；坏文件/空表/超限得到可理解错误；公开快照显示“快照”而非“正在联网”；原始文件和元数据均可被恢复或明确提示失效，不凭空生成缺失表。

#### 4.2.2 FR-02 字段概览、质量与适用性

**要求**：显示每字段原名、候选类型、非空率、解析失败数量、样例值、疑似唯一键、日期范围、单位候选、缺失/重复提示、记录粒度候选；XLSX 选择工作表后再确认映射。敏感样例按默认遮蔽策略显示。标出无法可靠计算的风险（例如混合币种、重复财务期间、多选记录重复计数）。用户可修改字段映射并记录版本。

**验收**：一列同时含数字和字符串时不得无声丢弃非数字；更正映射后相关口径和分析结果需重新确认/失效。

#### 4.2.3 FR-03 中文问题与分析契约（关键）

**要求**：输入中文问题。联网模型结合用户问题及字段摘要生成待确认的分析契约：指标及计算方式、单位、分母、期间与时间粒度、比较基准、过滤范围、记录粒度、字段映射、适用样本/总体及可能缺失条件。只有**会改变答案**的歧义阻断执行并向用户询问；能在不改变结论时安全默认的项目应公开展示默认值。经用户确认后产生不可混淆的契约版本。

**验收**：“平台偏爱”但只有使用次数时不得默认为首选；“利润”但仅有营收时不得当利润回答；财务数据当期与累计口径含混时提示选择；不会反复询问已确认且未变化的口径。

#### 4.2.4 FR-04 模型驱动的 Agent 调查循环

**要求**：**只有一套正式联网模型工作流**。模型用于意图/口径识别、计划生成、工具选择、结果观察、追问和解释；服务端以结构化输出与 Zod 校验、步数/查询成本/时间预算约束循环。计划列出调查步骤、至少两个有实际数据依据时的竞争假设及所需证据；每次读取真实工具结果，选择继续、修改计划、向用户澄清或停止，并说明变更原因。Planner/Executor/Analyst/Critic 为**责任环节**，不要求四个独立模型。Critic 在发表前交叉核对数值、分母、范围及引文。

**验收**：能在日志看到模型提出计划、观察实际查询结果、据此决定下一步；遇到无数据支撑的假设明确撤回/未证实，而非编造完整“多假设”故事；不得将固定脚本或回放伪装为模型自主调查。执行预算耗尽时说明尚未完成。

#### 4.2.5 FR-05 独立 MCP 数据工具与可见日志

**要求**：Agent Host 通过官方 MCP SDK 的 client 连接真正的独立 MCP 数据服务（公网优先 Streamable HTTP；本机联调可使用同协议或 stdio，传输不是产品价值本身）；数据集通过受控 ID 注册，模型不得提供任意本地路径。工具优先包括 `register_dataset`（Host 内部受控调用）、`profile_dataset`、`execute_sql`、`analyze_dimension`、`detect_anomalies`、`build_chart_data`；报告组装由 Host 完成，可按确实需要增设 MCP 工具，不为凑数量虚构调用。每次真实调用记录工具名、经脱敏的参数、起止状态、关联运行/查询 ID、耗时和错误；日志内敏感值与密钥脱敏。

**验收**：至少三个不同的数据分析 MCP 工具成功真实调用；公网链路中能观察到 Host → MCP 数据服务 → SQL 的真实调用；断开 MCP 数据服务后有可见失败，而不是继续出现假成功调用；可以从 UI 日志映射到 Host 执行记录。

#### 4.2.6 FR-06 真实 SQL、统计与安全

**要求**：查询在 sql.js/SQLite 中对已注册数据版本真实运行；结构化查询优先，模型提供 SQL 时一律当不可信输入：解析为**单一只读查询**，白名单数据表/列/函数，阻止 ATTACH/PRAGMA/写语句/危险扩展及多语句，参数化外部过滤值，限制返回行数/计算资源/时长并可取消；聚合处理 NULL、重复、时间范围、零分母和单位。不得只用“以 SELECT/WITH 开头”或追加 LIMIT 当安全措施。超出当前安全策略的表达式拒绝并要求重写。

**验收**：同一查询条件独立复跑得同一结果；注入、多语句、递归耗资源查询及试图访问未授权表不能成功；遇空集或分母零不显示伪数值，返回原因。

#### 4.2.7 FR-07 渐进可视化与联动

**要求**：前端用 ECharts 接收真实查询结果，按字段与问题选择表格、柱状、折线、散点或热力图；保存 `chartId → queryId + 数据版本 + 编码映射`。展示坐标轴单位、时间范围、分组和样本/分母；选中图形元素可定位证据与发起追问。报告以静态内联 SVG 或等效的单文件可阅读图呈现，不依赖在线 JS 或图片资源。

**验收**：第一次真实查询完成即能显示对应结果；后续步骤可增补/更新图表并标明版本；类型不适配时不强行用热力图/散点；空值及缺少时间序列的场景不暗示存在趋势。

#### 4.2.8 FR-08 证据审计和推断等级

**要求**：每个事实性数值与关键结论保留 `claimId → contractVersion → queryId → 数据版本 → SQL/参数 → 查询结果行/字段 → 图表` 链接；对明细级证据可定位到原始文件工作表/行号（行号是追溯线索，重复及聚合证据仍依赖完整查询）；对聚合结论需展示**完整聚合查询及结果**，几行示例原始数据不能证明总体结论。区分“直接计算”“描述性关联/贡献”“解释性假设”“证据不足”；没有对照实验或其他可验证因果证据时不写“导致”。

**验收**：点开关键数值可看查询、参数、计算口径与聚合结果；改动字段/数据版本后旧结论明确标记失效或历史，不静默沿用；审计失败的数字不得发布为事实。

#### 4.2.9 FR-09 常驻问数鉴：解释、追问与重算

**要求**：在数据工作区与分析页常驻可用；支持以当前图表、特定点/柱、结论或整段分析为上下文提问。“怎么算的”优先引用现有证据；改变时间、群体、指标等需创建新 `runId`/`branchId` 或新查询并实际执行；回答标出所用数据/契约/分支版本；缺少所需字段或权限时清楚说明不能回答。

**验收**：对已展示数字询问计算方式不生成新数字；提出新筛选条件时日志有真实新增工具调用、图表/结论根据新结果更新；不把旧分支数字带入新数据口径。

#### 4.2.10 FR-10 挑战结论与分支对照

**要求**：用户或模型能提出**有方法依据**的替代口径（如分母、当期/累计、群体边界或比较期间），显示具体改变、为什么合理，保存原分支，再经同样的 MCP/SQL 流程重算；并排显示原始与挑战结果及证据，输出“稳健/对口径敏感/无法判断”等状态，状态必须由两组实际结果支持。禁止任意筛选以制造反转；无有效替代口径则解释无法挑战。

**验收**：原分支可回看；挑战前后 SQL、结果、图表与所依赖数据版本可比较；挑战失败保留失败状态，不覆盖原结论。

#### 4.2.11 FR-11 报告预览与导出

**要求**：选择数据版本与分支，服务端组装单文件 HTML：问题、确认口径、来源声明和快照信息、文件指纹、图表、数字和对应查询摘要/SQL、主要挑战对照、证据限制及导出时间。HTML/属性/URL 全部做转义与安全约束；API Key、系统提示、敏感原始明细默认不包含；可在导出前预览和调整包含范围。

**验收**：离线打开仍可阅读图表与证据；下载文件的结论与选定分支一致，不能把不同数据版本的数字混写；若有缺失证据或未完成分析，标记草稿/未通过，不输出为最终可信报告。

#### 4.2.12 FR-12 模型连接、透明失败与恢复

**要求**：服务端通过 OpenAI 兼容 API 配置联网模型，密钥只保存在服务端环境文件/环境变量；前端可显示模型连接与执行状态，不显示密钥。接口失败时受控重试；若用户另有真实可用模型可切换并重跑/续跑可恢复步骤。仍失败则暂停、保存已完成的真实计算、展示原因和恢复动作；**不启用离线预设规划器、伪 AI 或伪工具日志**。

**验收**：无密钥/模型不可用时 UI 明确提示、停止 AI 调查；已完成查询可查但不生成未完成的结论；任何导出均不泄漏密钥。

#### 4.2.13 FR-13 重置、版本与用户控制

**要求**：提供分析取消、清空本次分析、移除已上传文件的明确操作；修改数据/映射/口径均引发版本变化，历史分析只读保留或明确删去；未确认口径时不自动执行可能误导的分析。重置只处理用户确认的当前工作区，不删除其他任意文件。

**验收**：取消后无新的模型动作或 SQL 意外提交；重新打开已有工作区若无法恢复数据则明确标记失效，不显示历史结果为当前值。

## 5. 业务规则与分析责任

1. **口径先于计算**：财务需辨认金额单位、币种、财报期间与报告性质；调查需辨认一行代表人/回答/事件、单选多选及分母。模型分类只是候选，不得保证“准确分类所有数据”。
2. **描述不是因果**：营收下降可展示同比/环比、渠道/时段贡献与相关线索；没有能识别因果的研究设计不能说“渠道导致下降”。
3. **样本不是总体**：展示样本选择与缺失信息；没有代表性依据时答案限于本样本/上传记录，不使用“全网偏爱”标题。
4. **差异必须可复算**：贡献拆解需要确保拆解分组覆盖、互斥，并检验各部分之和与总差一致（允许显式标注舍入误差）；条件不满足时停止归因拆解。
5. **假设必须有状态**：待测、支持线索、不支持、无法判定；观察到的相关性不足以升级为因果证实。
6. **可信边界**：文件内容、模型输出、SQL、图表标签均视为不可信输入；上传文件中出现“忽略前述指令”等文字只是数据，不能改变 Agent 指令和授权。

## 6. 状态、事件与数据结构（产品契约）

```text
Dataset {datasetId, datasetVersion, originalFileSha256, sourceType,
         sourceClaim, sourceUrl?, snapshotAt?, licenseNote?, sheet?, schema, qualityIssues}
AnalysisContract {contractVersion, datasetId, datasetVersion, metric, denominator?,
                  period?, compareWith?, filters, populationScope, fieldMapping,
                  unit?, ambiguities[], confirmedAt?}
Run {runId, branchId, parentBranchId?, datasetVersion, contractVersion,
     question, plan, status, startedAt, endedAt?}
ToolCall {callId, runId, tool, redactedArgs, startedAt, endedAt?, status, resultRef?}
Query {queryId, runId, datasetVersion, sql, boundParameters, columns, rowsRef,
       sourceRowRefs?, status}
Chart {chartId, queryId, chartType, encoding, datasetVersion}
Claim {claimId, runId, queryRefs[], contractVersion, datasetVersion,
       statement, inferentialLevel, auditStatus, caveats[]}
Report {reportId, datasetVersion, branchIds[], selectedClaimIds[], exportedAt, auditStatus}
```

`sourceRowRefs` 是明细定位能力，**不能替代聚合查询结果**；若 SQL 聚合后无法合理枚举全部原始行，证据应提供完整查询与必要统计，不伪造“全部相关行”。报告固定版本，上传更新版文件创建新版本而不是覆盖旧分析。

**运行状态**：`waiting_for_data → profiling → waiting_for_contract → planning → running → auditing → completed`；可从任一步进入 `failed`/`cancelled`/`paused`，重试产生新的运行尝试或记录可核查的恢复事件。前端区分“进行中”“证据已审计”“草稿/不完整”。

**SSE 事件最小字段**：`eventId, runId, branchId, sequence, timestamp, type, payload`。事件类别包括 `profile_ready`、`contract_proposed`、`plan_created`、`tool_started`、`tool_completed`、`tool_failed`、`query_ready`、`chart_ready`、`hypothesis_updated`、`plan_revised`、`claim_audited`、`run_completed`、`run_failed`。客户端断线恢复按 eventId/sequence 去重并获取当前状态；**事件描述真实已发生的工作，不用延时播放“过程”**。上传/确认/发起分析/追问/挑战/报告走 REST，SSE 只承担单向状态推送。

## 7. 技术路线与非功能要求

```text
React + TypeScript + Vite + Zustand + ECharts
        │ REST（上传、确认、查询、追问、报告）+ SSE（运行事件）
        ▼
Node.js + Fastify Agent Host
  ├─ Model Gateway（一个联网模型工作流，OpenAI 兼容接口）
  ├─ Agent Loop / Policy & Evidence Guard（Zod 校验、资源预算、审计）
  ├─ Dataset Registry（原始文件、SHA-256、映射、版本与来源）
  └─ MCP Client ── Streamable HTTP ── 独立 Data MCP Server
                              ├─ profile_dataset / execute_sql
                              ├─ analyze_dimension / detect_anomalies
                              └─ build_chart_data → sql.js / SQLite
```

- **数据解析与部署**：CSV 可用 Papa Parse，XLSX 解析依赖须核查维护状态、许可和安全公告；服务端重新校验上传结果。公网架构必须保证 MCP 数据工具按受控 dataset ID 访问其查询所需的数据版本；若 SQL 仅在浏览器运行，不得把浏览器函数冒充“远端 MCP execute_sql”。选定云托管方案前验证上传体积、运行时限制、持久化、会话/授权和流式能力。sql.js 可用于经验证的数据服务隔离执行，但内存数据库不等于可恢复持久存储。
- **SQL 防护**：沙箱进程/运行预算、语法树只读限制、表/列/函数白名单、参数化、结果上限及运行时中止需结合验证；`LIMIT` 只限制输出行，不限制中间计算量。若 sql.js 不具备可靠的运行时中止保障，需进程隔离并强制终止超时任务，或缩减 P0 可执行查询类型。
- **隐私**：联网模型可能接收必要的数据摘要/聚合结果，因此**不宣称“数据完全不出本地”**。默认仅发送问题、字段摘要、口径和完成分析所必需的聚合结果；敏感原始行默认不发给外部模型，需要额外传输时告知范围、用途、服务方并由用户确认。日志和报告默认去敏。前端提供上传前的联网模型数据传输告知，用户可不继续；不因此伪造离线结果。
- **安全与公网**：公网必须限制上传类型/体积、阻断路径访问及恶意报告 HTML（XSS）；数据服务校验会话/数据集授权，禁止任意访问其他人的上传文件；限制模型代理用量和费用、配置真正的鉴权/限流，Referer/Origin 不能单独当访问控制。服务端密钥和数据不入公开仓库；用户上传数据的保存位置、保存期限与删除生效范围须在上线前确定并告知。公共数据的版权/许可约束随来源展示。
- **可靠性与体验**：SSE 断开重连不重复执行工具；重复提交需幂等；长任务可取消、有阶段性反馈；图表按已完成结果渐进渲染，避免页面长时间空白；失败状态保留可核查进度。性能目标在确定真实测试文件规模后基准化，不编造上线 SLA。
- **测试**：Vitest 覆盖解析、口径规则、SQL 拒绝/计算、证据链接、分支和报告；Playwright 覆盖用户旅程、追问、网络中断、失败恢复、导出。测试代码可使用最小单元 fixture 验证算法，但**不得在产品中展示或包装为真实业务/演示数据**；演示和产品评测只使用真实来源文件。

## 8. 验证策略与参赛验收

### 8.1 开发前关口

1. 确认至少一份可合法使用的**真实规范化财务指标表**和一份**真实调查/平台使用记录表**；保存原出处、取得日期、许可与文件快照。若未找到能合法提供的文件，先缩小产品验证范围，不制造数据补位。
2. 人工核定每份数据的字段含义、至少两种易混口径和可复算参考结果；记录缺失/偏差，不使用模型回答充当正确答案。
3. 确认联网模型服务可用及兼容性、调用费用/配额，并完成数据传输告知与敏感信息边界审查。
4. 重新核对官方赛道要求、参赛资格、提交截止时间与材料规格，避免以旧赛制报名或交付。

### 8.2 端到端验收剧本

| 编号 | 操作 | 必须观察到 |
| --- | --- | --- |
| A1 | 上传一份真实来源文件 | 来源声明/快照、SHA-256、质量问题及可选工作表；不出现虚构数据 |
| A2 | 输入含歧义的问题 | 用户确认关键指标、分母或期间；不能无声猜测 |
| A3 | 开始分析 | 模型真规划并观察真实 MCP/SQL 结果；SSE 显示实际进度，图表逐步出现 |
| A4 | 点击任一关键数字 | 可见契约、SQL、结果与数据版本；审计失败不冒充事实 |
| A5 | 对图表追问“只看另一组” | 有新查询与新结果，旧分支仍可查 |
| A6 | 挑战结论 | 有合理口径才创建分支；真实重算、并排对照，无法挑战则解释原因 |

| A8 | 注入恶意 SQL/表格指令、断开模型/关闭 MCP | 危险查询被拒，模型/工具异常可见，不冒出伪完成结论 |

财务、调查两类都至少完整复跑 A1—A7 中适用项；记录人工标准值与系统输出差异，**不以“看起来合理”作为准确性证明**。对同一任务选取现有工具进行功能对照，并安排未参与开发的用户测试是否能理解口径、证据和挑战；若竞争优势不成立，缩小宣传主张。

## 9. 里程碑、优先级、风险与开放问题

**M0 真实性与基准**：合法真实数据与来源、人工参考结果、模型可用性及隐私边界确认。

**M1 数据—SQL—图闭环**：上传、选表、字段映射、版本、一次安全真实查询、一张图、一条可复核证据。

**M2 MCP—Agent 闭环**：独立 MCP Server、三个以上真实工具、联网模型计划/观察/重规划、SSE 事件、错误可见。

**M3 用户闭环**：常驻追问、合理口径挑战、分支/证据审计、离线单文件报告。

**M4 第一批参赛质量**：在 2026-11-18 第一批省赛截止前，公网部署后以实际域名复跑完整旅程和安全/性能测试，制作公开仓库、5—8 分钟 MP4、≤30 页技术 PDF，完成材料冻结及官网个人中心提交核对。

**P1（完成 P0 后才评估）**：经过授权的定期数据更新、基于数据版本变更的增量重算、数据导入适配器、更深入统计方法；均不作为第一版已实现能力宣传。

**开放问题（不阻塞撰写，开发前必须定案）**：公网服务与数据持久化平台、模型代理费用与访问控制、真实数据集授权与文件规模；模型供应商及隐私条款；XLSX 解析依赖许可和安全；sql.js 超时隔离方案；财务与问卷分别最小可支持的字段集合；赛事当期最终参赛/提交细则。若任一项不可行，调整对应功能承诺，不绕过真实数据、口径、模型和证据约束。
