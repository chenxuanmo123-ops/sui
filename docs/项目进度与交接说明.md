## 4. 产品全流程与实际边界

目标流程：导入真实文件 → 核对字段/来源/质量 → 算法处理和统计 → AI 初步定位/生成计划 → 人工确认分析口径 → 真实 SQL → 图表与来源明细 → AI 根据计算事实解读 → 范围追问与分支 → HTML 证据报告。

当前不是任意数据均可自动准确分析的通用产品，也不是完整自主多 Agent 系统。

### 4.1 实际技术栈

- React 19 + TypeScript + Vite 6。
- sql.js / SQLite 在浏览器 Web Worker 中计算。
- ECharts 与自绘 SVG：探索图表和主分析图表有所区别。
- SheetJS 解析 XLSX/XLS，PDF.js 解析与预览 PDF；CSV 有现有导入实现。
- Node.js 同源 HTTP AI 后端；OpenAI 兼容 Chat Completions 接口。
- 自定义结构契约校验与结构化输出解析。
- React 状态及 IndexedDB 工作区持久化。
- Vitest、Node 测试、Python Playwright/Edge 浏览器验收。

最初方案中的 Fastify、Zustand、Zod、官方 MCP SDK 等不能直接当成当前已落地依赖。实际依赖以 package.json 和代码为准。

### 4.2 文件导入

已支持 CSV、XLSX、XLS、文字型 PDF；Excel 可选工作表、表头和范围；PDF 可预览原页、核对提取表格。PDF 当前页可经单独授权调用真实视觉模型转录候选表格。

边界：Excel 一次一张表；PDF 一次一页一张表；复杂跨页、旋转、扫描、多表混排不能保证还原；Excel 公式只读已有缓存，不重算；不执行宏、外链或嵌入图片。PDF 转录行不冒称精确物理行号。

原文件 SHA-256、导入方法、工作表/页码、表头范围、警告和来源定位应保留。编号前导零、单位、百分比及异常格式不应被静默误改。当前单文件 **30 MB**，另有矩形单元格预算约 **200 万**；不是任意规模处理器，不能只删掉阈值就宣传支持大数据。

### 4.3 无需 AI 的处理和计算

已具备字段类型候选、缺失、唯一值、首尾空白、重复、均值、中位数、分位数和 IQR 画像；清洗预览、确认、修剪、严格千分位规范、缺失标记、删空、整行去重和撤销。

真实 SQL 支持九类聚合：求和、均值、中位数、下四分位 P25、上四分位 P75、计数、去重计数、最小、最大；分组、条件筛选、时间分桶。中位数与四分位采用线性插值（`rank = 1 + (n - 1) × p`，与 numpy.quantile / DuckDB quantile_cont 同一定义），全部在 SQLite 窗口函数中计算，不依赖 AI 或前端估算。另有显式分子/分母的条件计数比例，零分母不写成 0%，排除项可见；不支持任意公式或所有金额比率。

探索页有折线、柱状、散点、热力、表格；对比页有期间比较及来源核查。AI 自动计划目前主要生成聚合折线/柱状任务，不能说所有图表均已纳入自动 Agent 工具循环。

SQL 由受约束任务编译，参数化，只读设置；不是任意模型 SQL 执行器。计算和来源绑定数据快照，旧计划不能跨快照复用。

### 4.4 AI 与工作流

- 初步定位：默认模型辅助判断数据场景、字段角色、行粒度和风险，元数据授权后调用；未配置模型时不能伪造定位。
- 助手：中文问题 → 结构化计划 → 校验 → 确认 → 本地真实计算 → 基于事实解读。
- 空目标/空背景可使用安全的默认描述性问题。
- 原始样本与类别字典分别授权，默认关闭。类别字典有列数、基数、长度和总预算限制，超限整列省略；服务端白名单过滤未授权内容。
- 每个任务独立执行，失败不丢失其他成功结果；事实按唯一 taskId 绑定，不能按数组位置猜。
- 精确等值筛选无匹配时先警告；不把 revenues 模糊改成 revenue。
- 失败反馈给 repair-plan，只允许修正失败 ID；展示修改前后，用户再确认，仅重算失败任务。前端每轮最多两次修正，不是服务端持久全局配额。
- 已有候选假设结构和显示；**程序化多假设裁决和自主重规划闭环未完成**。
- 有连接等待、超时、取消和错误提示；本轮增加本地计算任务进度与真正 Worker 中止。

### 7.9 只读 SQL 控制台与多表 JOIN（2026-10-23）

回应“和优秀纯 SQL 分析项目相比，用户能否自己写查询、能否关联第二张表”。控制台不是把 AI 生成的 SQL 展示出来，而是让用户在真实快照上直接执行 SQL，结果不经模型。

- 入口：顶部导航“SQL 查询”。未载入数据时只提示导入真实文件，不生成示意结果。
- 对象：`data`（`_record` + `c0…cN`）、`readable`（原表头视图，大小写重名时回退 cN，仍保留 `_record`）；UDF 为 `strict_number`、`compare_labels`、`time_bucket`。
- 只读边界：`validateReadOnlyQuery` 先做字符级扫描，把字符串、双引号标识符、反引号、方括号和 `--` / `/* */` 注释替换为空格，再检查首关键字、内部分号、写操作/DDL/PRAGMA/事务/文件函数关键字、参数占位符和 `sqlite_*`；随后 Worker 连接本身以 `PRAGMA query_only=ON` 执行。结果最多 500 行，超出明确标记并按显示行导出；30 秒超时会终止 Worker。
- 多表 JOIN：可上传第二个 CSV（30 MB 上限，沿用 `parseCSV` 的 200 列 / 100,000 行与重复列名校验），装载为固定表 `extra`（`_row` + cN）和视图 `extra_readable`。表名固定，用户 SQL 无法建表；更换会先删旧表，移除会同步 `DROP` 回 Worker，避免界面状态与数据库不一致。关联表只在当前浏览器会话内有效，不写入快照、不进入分析/图表/证据链。
- JOIN 示例不假设两表第 0 列是同一个键：在关联表首列抽样 200 个值，在主表前 500 行中寻找实际存在共同值的列，找到则写入注释与对应 cN；找不到就明确提示“未检测到共同值”，不编造连接。
- 结果图表：查询成功后可把结果画成柱形/折线图（懒加载 `SqlResultChart`）。横轴可选任一列或结果行号，纵轴只列能被严格解析为数值的列；文本、空值和 `$1,234` 这类金额字符串不会被当成 0 或数字，纯文本结果明确显示“没有可作为纵轴的数值列”。图表不重新聚合、不插补缺失值、不建立来源绑定；坐标轴从 0 起，避免把微小差异画成巨大落差。
- 测试：`tests/sql-console.test.ts` 7 项（拒绝清单、字面量/注释、readable 与 UDF、关联表装载/JOIN/替换/移除、空列名与超限/重名列回退、图表数值与横纵轴推断、截断与只读）；`scripts/real-data-analysis/sql-console-check.py` 真实 OWID 数据 8 项 PASS（8 行默认查询、聚合 15738.01 / 205.01、结果图由真实返回值绘制、拒绝写与多语句、纯文本不生成数值图、JOIN 示例 8 行、`readable`×`extra_readable` 输出 China/Asia/8、移除后 `no such table`）。
- 限制：仍是 SQLite 方言；`data` 上的双引号未知列名会被 SQLite 当作字符串字面量（DQS），所以示例与文档优先使用 `readable` 或明确 cN。JOIN 结果不会自动建立来源绑定，行号需人工核对；控制台也不会判断连接口径是否业务合理。
- 真实规模：本机用 26 MB Inside Airbnb 阿姆斯特丹快照（`demo-data/airbnb-amsterdam-2026-09-16/data/listings.csv`，不入库）实测：导入 3.2 s；按房型分组 4 行、16 ms；按 `neighbourhood_cleansed` 分组 20 行并在浏览器中绘图约 0.2 s，图表标签与数值来自查询返回值。
