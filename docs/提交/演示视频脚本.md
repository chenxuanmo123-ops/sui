# 数鉴 Agent 演示视频脚本（5–8 分钟）

> 赛事要求：5–8 分钟、MP4、不低于 1080p、普通话讲解。本脚本约 6 分 25 秒。
> 原则：全程使用公网真实部署与真实模型，数字由浏览器内 SQLite 计算。模型临时不可用时如实展示错误并重试，不剪辑成假成功。

## 录制前 10 分钟

1. 打开 <https://sui-ae9.pages.dev/>，确认右上角模型状态可用，`/api/health` 正常。
2. 浏览器全屏（F11），缩放 100%，关闭书签栏、下载栏、通知；只保留一个标签页。
3. 点击「载入随应用附带的真实示例（UCI 骑行日数据）」，确认 731 行、16 列，然后刷新页面回到初始状态，保证正式录制从零开始。
4. 麦克风试录 10 秒，确认没有爆音；OBS 设为 1920×1080、30 fps，码率 6000–8000 kbps。
5. 关闭可能弹窗的软件（微信、钉钉、系统更新提示）。
6. 确认画面中不会出现 API Key、云平台控制台、账单、个人文件路径。

## 分镜与讲解

### 0:00–0:25 开场

**画面**：公网首页，鼠标轻放在标题「把数据放进来，从第一个问题开始。」附近，不点击。

**讲解**：
> 大家好，我是数鉴 Agent 的作者。数鉴 Agent 是一个面向真实文件的 AI 数据分析与可视化 Web 应用。它要解决一个很具体的问题：让不会写 SQL 的人，也能用自然语言完成查询、分析和可视化，同时让每一个数字都能被核查。

### 0:25–1:15 导入与数据体检

**操作**：
1. 点击「载入随应用附带的真实示例（UCI 骑行日数据）」。
2. 数据载入后，缓慢向下滚动到「这份数据现在能回答」，停留在三个建议问题。
3. 指向右上角体检卡片（731 条记录、16 个字段、完整度 100%）。

**讲解**：
> 我载入随应用附带的 UCI 骑行日数据，731 天、16 个字段，载入时会核对文件的 SHA-256。导入后不需要先懂字段类型：系统会告诉我哪些列是时间、数值、分类，完整度怎么样，有没有重复，并给出三个可以直接执行的问题。请注意，这些只是候选，字段的业务含义和单位仍然需要我确认。

### 1:15–2:45 自然语言 → 计划 → 饼图

**操作**：
1. 在输入框输入：`各天气类型的租车总次数占比是多少？`
2. 点击「与 AI 一起分析」。
3. 计划出现后，用 10 秒展示任务卡，读出分组、指标、聚合方式。
4. 勾选「我已核对…允许按此计划计算」，点击「确认计划并计算」。
5. 等待饼图出现，鼠标依次划过三个扇区，展示占比。
6. 向下滚动到结果表、来源记录、实际执行的 SQL；点开一组「查看 N 条来源」。

**讲解**：
> 我输入：各天气类型的租车总次数占比是多少？AI 返回的不是一个答案，而是一份计划：分组字段 weathersit，指标 cnt，聚合方式求和，还列出需要我确认的口径，比如天气编码的含义。我确认计划后，计算在浏览器内的 SQLite 中执行，原始数据不会上传。
> 结果是这张饼图：三种天气类型的租车总次数分别是 2,257,952、996,858 和 37,869，占比 68.6%、30.3% 和 1.2%。这个占比只在当前数据范围内成立，不是市场份额，也不能外推到总体。
> 往下是结果表、来源记录和实际执行的 SQL。每个分组都能回查原始行，SQL 和参数完全可见，所以这个数字不是模型编出来的。

### 2:45–3:55 多轮追问与证据解读

**操作**：
1. 点击「就此结果追问 AI」。
2. 输入：`再按季节拆开看看`，点击「与 AI 一起分析」。
3. 展示第二轮计划（以实际生成的任务为准；预期为按季节求和的聚合任务与可视化探索任务）。
4. 确认计算，等待结果。
5. 滚动到「结合证据解读」，鼠标依次经过几条依据标签（例如「依据 1 · 1 2,257,952 次」；编号与数值以本轮实际结果为准）。
6. 停留在「可能意味着什么 / 可以拿来做什么」与「引用有效不等于解释成立」。

**讲解**：
> 我继续追问：再按季节拆开看看。第二轮计划包含两个聚合任务和两个探索任务：按季节求和、按记录数核查，另外两个用于交叉观察。
> 结果页先给出由规则生成的事实解读，再由模型补充可能含义和用途。每一条都引用本轮的事实编号，比如依据 1 对应天气类型 1 的 2,257,952 次。界面同时写明：引用有效不等于解释成立，这些只是待核对的假设，不是因果结论。

### 3:55–4:55 手动分析与相关

**操作**：
1. 左侧点击「探索分析」。
2. 图表类型选「散点图」，X 选 `cnt`，Y 选 `temp`，点击「执行探索分析」。
3. 滚动到散点图与 Pearson 卡片，指向「仅展示前 100 项」的提示和 r 值。
4. 点击一个散点，展示下方来源记录。

**讲解**：
> AI 不是唯一入口。我切到探索分析，选择散点图，X 是 cnt，Y 是 temp。界面明确说明：图上只展示前 100 个点，但 Pearson r 使用全部 731 个有效配对，r 等于 0.6275。它只描述线性同步程度，不是因果，也不是预测。点击任意一个点，可以查看它对应的原始记录。

### 4:55–5:40 证据交付与移动端

**操作**：
1. 在结果区点击「导出 HTML 证据报告」，展示下载的文件名（不必打开）。
2. 点击「导出可复现 SQL 包」，展示文件名。
3. 打开浏览器设备模拟，切到 390px 宽度，缓慢滚动展示布局，再切回桌面。

**讲解**：
> 每个结果都可以导出结果 CSV、SVG、HTML 证据报告，或者可复现 SQL 包。这个包里包含清洗后的 CSV、schema、SQL、预期结果和一个 Python 复跑脚本，脱离本产品也能复算。页面在 390 像素宽度下也没有横向溢出，手机上可以完成同样的核对。

### 5:40–6:25 技术与边界、收尾

**画面**：回到首页或结果页，保持稳定画面；可叠加一张简单的架构文字卡（可选）。

**讲解**：
> 技术上是 React 19 加 TypeScript，计算在 Web Worker 里的 sql.js 完成，工作区保存在 IndexedDB。AI 只输出受契约约束的计划，SQL 由固定模板编译，只读、参数化；解读必须引用事实编号，不能新增数字。
> 测试方面，AI 接口 39 项、核心计算 224 项、固定数据评测 14 项、生产检查 33 项，全部通过；公网验收 7 项通过。
> 数鉴 Agent 的原则很简单：样本不等于总体，描述不等于因果，模型只解释已经验证的事实。谢谢观看。
