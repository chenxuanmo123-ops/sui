# 数鉴 Agent 演示视频脚本（5–8 分钟）

> 赛事要求：5–8 分钟、MP4、不低于 1080p、普通话讲解。本脚本约 6 分 20 秒。
> 原则：全程使用公网真实部署、应用提供的 OWID 公开能源数据与真实模型，数字由浏览器内 SQLite 计算。模型临时不可用时如实展示错误并重试，不剪辑成假成功。

## 录制前 10 分钟

1. 打开 <https://sui-ae9.pages.dev/>，确认右上角模型状态可用，`/api/health` 正常；打开「AI 助手」应看到新的控制台（标题栏有「对话 / 计划与证据」两个标签、可展开为双栏窗口）。若还是旧界面或 `/api/ai/web-lookup` 返回 404，说明公网还没发布最新构建，先按 `docs/部署与交付.md` 重新 `npm run build` + `wrangler pages deploy dist --branch main`，再开始录制。
2. 浏览器全屏（F11），缩放 100%，关闭书签栏、下载栏、通知；只保留一个标签页。
3. 在无痕窗口打开，先点一次「手边没有文件？从网页直接下载公开数据」，确认能下载并通过 SHA-256 校验；然后关闭无痕窗口重开，保证正式录制从零开始。不要用上一次留下的工作区。
4. 麦克风试录 10 秒，确认没有爆音；OBS 设为 1920×1080、30 fps，码率 6000–8000 kbps。
5. 关闭可能弹窗的软件（微信、钉钉、系统更新提示）。
6. 确认画面中不会出现 API Key、云平台控制台、账单、个人文件路径。
7. 网络兜底：若录制当天公开数据入口持续超时，提前用同一固定提交下载 `owid-energy-data.csv`（9,229,369 B，SHA-256 `266f2e2b…1f76`），录制时通过「选择文件」上传同一份 CSV；画面和旁白必须说明“现场网络改用同一份固定提交的公开数据、哈希一致”，不能把上传说成网页下载。

## 分镜与讲解

### 0:00–0:25 开场

**画面**：公网首页，鼠标轻放在标题「把数据放进来，从第一个问题开始。」附近，不点击。

**讲解**：
> 大家好，我是数鉴 Agent 的作者。数鉴 Agent 是一个面向真实文件的 AI 数据分析与可视化 Web 应用。它要解决一个很具体的问题：让不会写 SQL 的人，也能用自然语言完成查询、分析和可视化，同时让每一个数字都能被核查。

### 0:25–1:15 下载公开数据与体检

**操作**：
1. 点击「手边没有文件？从网页直接下载公开数据」。
2. 等待「正在下载并校验公开数据」的进度与校验完成（约 9.2 MB，等待可加速或剪掉静默，但保留进度与完成画面，不要伪造）。
3. 数据载入后，缓慢向下滚动到「这份数据现在能回答」，指向体检摘要与时间范围。

**讲解**：
> 我先用应用提供的公开数据入口：OWID 能源数据，固定到提交 e7897aed，浏览器直接下载原始 CSV，约 9.2 MB，按 SHA-256 校验后才载入。这份文件是 23,377 行、130 个字段，年份从 1900 到 2025。
> 导入后不需要先懂字段类型：系统会告诉我哪些列是时间、数值、分类，完整度怎么样，并给出可以直接执行的问题。请注意，这些只是候选，字段的业务含义和单位仍然需要我确认——石油产量的单位是 TWh 一次能源，不是桶。

### 1:15–2:45 自然语言 → 计划 → 真实计算

**操作**：
1. 打开右侧「AI 助手」控制台（默认停在「对话」）。在输入框输入：`中国 2000 到 2023 年的石油产量怎么变化？`
2. 点击「与 AI 一起分析」。等待时提示行会显示“正在理解数据与目标…”。
3. 计划返回后，对话里先出现一段可读的回复：拆成了几项任务、有几点口径待核对；随后点「查看计划与口径」，切到「计划与证据」标签。若想展示“两条流程分开”，可在计划发出后点右上角展开图标，窗口变为 1240px 双栏，左边对话、右边计划与证据同屏。
4. 在「计划与证据」里展示任务列表：主任务，加上人均产量、记录数核查、同比变化率等辅助任务（通常 3–4 条，以实际生成为准）；读出主任务的分组、指标、聚合方式、筛选与范围。
5. **先核对主任务确实是中国、2000–2023、石油产量；若模型给的计划不同，先修正条件或重新提问，不要照读数。**
6. 勾选「我已核对…允许按此计划计算」，点击「确认计划并计算」。
7. 结果出现后，确认任务栏停在 T1「中国 2000–2023 年石油产量逐年变化」；在「指标单位」里声明 `TWh`（这是你的声明，不是模型推断），再沿折线移动，展示首尾年份的数值。
8. 向下滚动到结果表、来源记录、实际执行的 SQL；点开一组「查看 N 条来源」。

**讲解**：
> 我输入：中国 2000 到 2023 年的石油产量怎么变化？AI 返回的不是一个答案，而是一份计划：主任务按 year 分组，指标是 oil_production，求和，只筛选 country = China，范围 2000 到 2023；另外它主动加了人均产量、记录数核查和同比变化率三条辅助任务。单位这里标的是“未确认”——数据字段的说明是 TWh 一次能源，但模型没有替我断言，我也不会把未确认的单位说成模型结论。
> 我确认计划后，计算在浏览器内的 SQLite 中执行，原始数据不会上传。先看主任务 T1：24 个年度值，2000 年 1,891.27 TWh，2023 年 2,430.97 TWh；按首尾值算，增加 539.70 TWh，约增长 28.5%，平均每年增加 23.47 TWh。这是描述性汇总，不是预测，也不说明原因。
> 往下是结果表、来源记录和实际执行的 SQL。每个点都能回查到一个国家和年份的原始行，SQL 和参数完全可见，所以这个数字不是模型编出来的。

### 2:45–3:55 多轮追问与证据解读

**操作**：
1. 打开 AI 助手，在「沿着发现，继续追问」输入框输入：`那同期石油消费量呢？`，点击「与 AI 一起分析」。
2. 展示第二轮计划（以实际生成为准；预期为 oil_consumption 的年度聚合任务，可能附带记录数核查等辅助任务）。
3. **同样先核对指标为中国、2000–2023 的石油消费量；不一致就先改条件，再确认计算。**
4. 勾选并确认计算，等待结果。
5. 滚动到「结合证据解读」（复核可能比计算晚几秒；若尚未返回，就如实等它出现或说明仍在生成，不要剪成已完成），鼠标依次经过依据标签（编号与数值以本轮实际结果为准）。
6. 停留在「可能意味着什么 / 可以拿来做什么」与「引用有效不等于解释成立」。

**讲解**：
> 我继续追问：那同期石油消费量呢？第二轮计划把指标换成 oil_consumption，仍然按年份汇总、只筛选 country = China。
> 结果是 2023 年消费 9,091.23 TWh，产量 2,430.97 TWh，相差 6,660.26 TWh；消费从 2000 年的 2,626.90 TWh 增到 2023 年，约增长 246%。产量和消费都在上升，但这两个总量不能直接推断进口依赖，也不能写成因果。
> 结果页先给出由规则生成的事实解读，再由模型补充可能含义和用途。每一条都引用本轮的事实编号。界面同时写明：引用有效不等于解释成立，这些只是待核对的假设。

**可选加演：联网查术语（约 15 秒，时间紧就跳过）**

1. 在对话输入框填入 `石油产量`，点「联网查术语」。
2. 出现资料卡时，指向标题、摘录与「查看原文与更新时间」，读一遍卡片上的边界说明；若网络不通，就如实停在失败提示上，不重试剪辑成成功。

> 助手背后还有一层独立的规范知识库：口径、数据质量、表达边界的提醒都固定在里面，按问题检索，只把命中的几条随请求发出去，它们本身不是数据证据。遇到不熟悉的术语，我可以点「联网查术语」，让它去查公开百科，只用来理解口径和常见说法。卡片上写得很清楚：这是网页背景资料，不是本次计算的证据，也不代表我的数据；查不到或连不上就直接报错，不会拿网页内容冒充结果。

### 3:55–4:55 手动分析与相关

**操作**：
1. 左侧点击「探索分析」。
2. 图表类型选「散点图」；X 数值字段选「石油消费量（TWh）」，Y 数值字段选「石油产量（TWh）」。
3. 筛选字段选「国家/地区」，精确匹配值输入 `China`（数据原始值，非中文）；最多展示项数保持 100。
4. 点击「执行探索分析」。
5. 滚动到散点图与 Pearson 卡片，指向 r 值与有效对数。
6. 点击一个散点，展示下方来源记录。

**讲解**：
> AI 不是唯一入口。我切到探索分析，选择散点图，X 是石油消费量，Y 是石油产量，只筛选国家/地区等于 China。界面明确说明：Pearson r 使用当前筛选下全部有效配对计算。这里是 60 对有效值，r 等于 0.8191，全部 60 个点都在图里，没有截断。它只描述线性同步程度，不是因果，也不是预测。点击任意一个点，可以查看它对应的原始记录。

### 4:55–5:40 证据交付与移动端

**操作**：
1. 在结果区点击「导出 HTML 证据报告」，展示下载的文件名（不必打开）。
2. 点击「导出可复现 SQL 包」，展示文件名。
3. 打开浏览器设备模拟，切到 390px 宽度，缓慢滚动展示布局，再切回桌面。

**讲解**：
> 每个结果都可以导出结果 CSV、SVG、HTML 证据报告，或者可复现 SQL 包。这个包里包含清洗后的 CSV、schema、SQL、预期结果和一个 Python 复跑脚本，脱离本产品也能复算。页面在 390 像素宽度下也没有横向溢出，手机上可以完成同样的核对。

### 5:40–6:20 技术与边界、收尾

**画面**：回到首页或结果页，保持稳定画面；可叠加一张简单的架构文字卡（可选）。

**讲解**：
> 技术上是 React 19 加 TypeScript，计算在 Web Worker 里的 sql.js 完成，工作区保存在 IndexedDB。AI 只输出受契约约束的计划，SQL 由固定模板编译，只读、参数化；解读必须引用事实编号，不能新增数字。助手自带一份独立的规范知识库（25 条口径与表达边界提示），和用户上传的资料分开检索，任何一条都不会被当作证据引用。
> 测试方面，AI 接口 48 项、核心计算 227 项、固定数据评测 14 项、生产检查 33 项，全部通过；公网验收 7 项通过。
> 最后是边界：这是 OWID 的国家—年份面板，不是每国每年都齐全，2023 年只有 79 个国家或地区有石油产量；单位是 TWh 一次能源，不是桶；World、Asia 等是聚合行，不是国家。样本不等于总体，描述不等于因果，模型只解释已经验证的事实。谢谢观看。
