# 数鉴 Agent 演示脚本（提交版）

用途：比赛演示与答辩时按顺序演示，保证每一步都能落到真实数据与可核查证据上。

## 演示前检查

1. 打开公网地址，确认右上角模型连接状态为“已配置”（`/api/ai/status` 返回 `configured: true`）。
2. 点击“载入随应用附带的真实示例（UCI 骑行日数据）”：731 行、16 列，一天一行，公开数据集。
3. 若网络抖动导致图表分包未加载，页面会给出“图表引擎加载失败”的说明，结果表、SQL 与来源记录仍可用；刷新即可恢复。
4. 准备说清一句总纲：**数字全部来自浏览器内 SQLite 的真实计算，AI 只负责理解问题、规划口径与解释已验证结果。**

## 场景 1：占比 → 饼图（主推）

提问：`各天气类型的租车总次数占比是多少？`

期望计划：1 个饼图任务，分组 `weathersit`，指标 `cnt`，聚合“求和”；模型会给出待确认口径（类别编码含义、行粒度），但不阻断计算。

确认后：饼图 + 结果表，占比按当前筛选范围内各分组求和计算。

真实数据核对（`day.csv` 全表）：

| weathersit | 租车总次数 | 占比 |
| --- | --- | --- |
| 1 | 2,257,952 | 68.6% |
| 2 | 996,858 | 30.3% |
| 3 | 37,869 | 1.2% |

要点讲述：
- 占比只在当前数据范围内成立，不是市场份额或总体推断。
- 类别编码未提供字典，图例显示原值，不猜“晴/雨”。

## 场景 2：两个分组维度交叉 → 热力图

提问：`按月和工作日交叉看租车次数`

期望计划：热力图，横轴月份、纵轴 workingday，指标 `cnt`。真实模型选择了“均值”口径（每个组合内多天取平均）。

要点讲述：每个组合是独立聚合的真实单元格；数据中不存在的组合留空，**不按 0 补齐**；颜色只表示该组合的聚合值，不解释因果。

## 场景 3：两个数值字段的关系 → 散点 + Pearson r

提问：`温度和租车次数是否一起变化？`

期望计划：散点图（`temp` × `cnt`），按当前筛选下全部有效配对计算 Pearson r。

要点讲述：r 只描述线性同步程度，不是因果结论、预测能力或显著性检验；点击散点可核查来源记录。

## 场景 4：时间趋势 → 折线 + 描述性趋势

提问：`每个月的租车次数怎么变化？`

期望计划：折线任务（按月分组、指标 `cnt` 求和；真实模型通常会再给一个均值任务用于对照）。

要点讲述：折线按真实聚合值；趋势给出“平均每期变化”和 R²，明确标注为描述性，不是预测或显著性检验。

## 场景 5：多轮追问

在场景 1 出结果后，点击“就此结果追问 AI”，提问：`再按季节拆开看看`

期望：携带上一轮问题、计划标题与该轮真实计算摘要继续规划（最多四轮，不发送原始行，历史数字不作为新证据）。

真实模型实际表现：第二轮给出 2 个聚合任务（按季节的租车总次数与记录数核查）和 2 个探索任务；解读逐条引用本轮事实编号，用“基于结果的观察”“可能意味着什么”分栏，并明确写“引用有效不等于语义与因果已被证明”。

## 证据链演示（任选一个场景）

1. 点击图形中的某个点/扇区 → 下方“所选图形对应的来源记录”列出原始行。
2. 导出“结果 CSV”“导出 SVG”“导出 HTML 证据报告”——报告包含快照指纹、实际执行 SQL、参数、结果到来源记录的映射。
3. 导出“可复现 SQL 包”：清洗后 CSV、schema.sql、analysis.sql、expected.json。

## 必须说到的边界

- 样本不等于总体；描述统计不写因果结论。
- 计数是记录条数，不等同于用户数、订单数或租车次数。
- 占比只代表当前筛选范围；热力图缺失组合不补零。
- 模型未确认的字段含义会进入澄清问题，不会当成已验证事实。
- 若模型服务不可用或余额不足，页面会明确报错，不会生成假结果。
