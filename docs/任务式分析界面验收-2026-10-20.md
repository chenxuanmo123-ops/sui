# 任务式分析界面验收

日期：2026-10-20。范围：本地数鉴工作台界面重构，未上线。

## 设计判断与实际变化

此前常驻导航、字段和助手同时占用空间，用户在导入、检查、分析和核验时都面对相同三栏。新版按任务阶段安排主内容：文件入口 → 数据核对 → 分析结果 → 分组证据/追问。技能用于约束任务优先级、渐进展示、文字可读性和实际验证。

| 阶段 | 当前实现 |
| --- | --- |
| 未导入 | 文件入口、真实公开数据入口、格式说明、连接状态 |
| 已导入 | 真实前5行6列、行数/字段数/空值、字段核对入口 |
| 分析 | 单一问题草稿打开原AI助手，配置与授权保留 |
| 多任务结果 | 一次聚焦一项，切换保留全部结果 |
| 选中分组 | 按需出现来源与限定范围追问 |
| 核验与报告 | SQL、结果表、原始来源和完整任务报告保留 |

移除常驻左侧栏。字段用抽屉，助手按需打开。提问区在文档流中，避免遮挡图表；真实容器宽度驱动SVG绘制，保持文字尺寸。桌面辅助文字和手机导航提高可读性。手动计数标题用“记录数”，避免误把Revenue布尔字段解释成营收。

- tests/interface-redesign-browser.py：5组通过，AI禁用。
- tests/visualization-browser.py：9组通过，明确AI测试替身。
- tests/follow-up-browser.py --workspace：15组通过，明确AI测试替身。
- 本轮前置核心检查：73项通过。

数据是原始UCI Online Shoppers fixture，12330行18列，SHA256 b3055ee355f59134d851d32641183cb4a8b45def7124d2f50442a042f358e0d9。DOI 10.24432/C5F88Q。浏览器实际执行SQLite并与独立CSV核算对照。总体1908/12330、新访客422/1694、1694条来源、子分组1215条范围可恢复。Revenue是购买与否，不是收入；TrafficType代码无字典时不命名成业务渠道。

检查包括390/768/1280/1440宽度、导航文字不挤出按钮、图表坐标与容器宽度一致、提问区不遮图、字段搜索跳转、问题草稿保留、证据和报告、20组分页、2任务切换与全部22组报告、刷新恢复、存储失败提示、清除取消和处理撤销。

这些验证不评价真实模型准确率，也不代表用户已认可审美，不应宣称任意数据或比赛最终验收完成。
