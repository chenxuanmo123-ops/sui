# 数鉴 Agent｜第一版实施方案（方案稿）

> 日期：2026-09-24　状态：方案待验证，非已实现产品。主方向：AI 数据分析与可视化。本文取代此前以“方向 1”为主赛道、内置虚构咖啡店数据、离线预设规划器作为主路径的方案；`docs/PRD.md` 已同步为现行 V1.1 需求草案；本文保留为决策背景资料，以现行 PRD 及后续明确决策为准。

## 1. 产品定位与主张

**定位**：面向真实表格数据的、可以持续追问与质询结论的 AI 分析工作台。用户上传 CSV/XLSX（包括自行获取的公开原始数据文件），通过中文提问获得逐步呈现的计算结果、交互图表及可追溯的结论；AI 助手在整个分析过程及结果页保持上下文，并能根据追问重新查询。核心能力不是“上传文件生成图表”，而是**口径协商 → 真实调查 → 挑战结论 → 可核验交付**。

**赛道**：方向 8「AI 数据分析与可视化」；Agent 与 MCP 是实现手段，不以通用助手作为产品定位。官网赛项页面：`https://www.boxuegu.com/matchTrack/detail/?id=10037`。本方案不声称已获验证的独创性、通用准确率或投资价值；需通过竞品对比和真实用户测试证明。

**约束**：不使用合成、虚构、随机生成的业务数据；不预填查询结果与结论；不把固定流程冒充模型自主决策。用户上传的文件指纹证明“分析针对哪份文件”，不证明内容客观真实；公开来源记录出处、获取时间及允许使用的条件。

## 2. 第一版用户旅程

1. **导入**：上传 CSV/XLSX；对于公开数据，记录可核查的发布机构与原始地址。第一版不承诺任意 URL 抓取。保留原始文件，生成 SHA-256，展示行列数、工作表、字段与来源状态。公开数据可以是预先取得的真实原始文件，但必须展示原始出处及快照时间，不得假装实时联网读取。
2. **检查**：解析和字段质量检查；识别记录粒度、数值/日期/分类字段、缺失值、可能重复、货币/单位等。不确定的字段只给候选映射。
3. **提问及口径确认**：用户输入中文问题；联网模型识别意图，形成“分析契约”：指标、聚合方式、分母、时间粒度/比较区间、筛选范围、适用总体、字段映射及待确认项。只在会改变答案的歧义上要求用户确认，不静默替用户定义“利润”“使用率”“偏爱”。
4. **调查计划**：模型提出可执行步骤与待检验假设，结构化输出经校验；前端展示计划和后续调整原因。计划来自本次问题及当前数据，不来自某个预设故事。
5. **执行与渐进可视化**：Agent Host 用 MCP Client 调用独立数据工具；每次工具请求与只读 SQL 真实执行，推送状态及结果。前端先显示字段与首轮图表，再随着查询结果更新图表，不等待整份报告。模型读取真实结果后决定继续、重规划、澄清或停止。
6. **结论审计**：每个数字绑定真实查询结果；口径、时间、分母、图表查询条件一致。贡献、相关线索、推测和无法判断分别标注；无依据不得称为因果“原因”。
7. **随时追问**：用户可针对当前图表、筛选条件、结论或全文发问。解释性问题引用现有结果；新的计算问题执行新的 MCP 查询；不可回答的问题说明缺失证据。更换数据集/口径后旧回答标注为历史版本，不能假装仍然有效。
8. **挑战结论**：用户或模型提出有数据和方法依据的替代口径，记录变更点并创建分支，真实重算、并排比较，显示结论是否稳健、对口径敏感或数据不足。不得为了“反转”选择任意筛选或编造反方数字；如无有效替代口径则说明无法挑战。
9. **导出**：服务端生成可离线打开的单文件 HTML，包含数据来源/版本、口径、主要查询与结果、图表、分析分支、结论与限制；不默认导出完整敏感明细。

## 3. 两类真实数据的验证范围

| 数据类型 | 第一版应处理的重点 | 禁止的错误外推 |
| --- | --- | --- |
| 规范化财务指标表 | 指标名称、公司、币种、单位、期间、当期值与累计值区别；只比较口径可比的记录 | 把不同单位或累计/单季数直接比较；依据财务数字给投资建议；声称已能解析任意财报 PDF |
| 调查表 / 平台使用记录 | 一行的含义、样本数、多选、分母、首选与使用次数区别；有无抽样框与加权依据 | 把便利样本称为“全网”；把使用次数当“偏爱”；在无抽样依据时推断整体用户偏好 |

**通用上传范围**：结构明确的单表 CSV/XLSX，允许用户选择工作表、确认字段映射；支持基础分组、筛选、对比、趋势和追问。图表组件具备表格、柱状图、折线图、散点图、热力图五种呈现能力；只在字段类型和问题适配时选择相应图种，不为了凑图种强行展示。复杂跨工作表关联、非规范化财报版式、任意网页爬取、统计总体推断和因果发现均不作第一版保证。

## 4. 产品界面

- **数据入口**：真实文件上传、文件来源/哈希、质量问题、可确认的字段映射与记录粒度。
- **分析契约卡**：在查询前简要列出已确定口径与真正待确认的歧义。
- **主画布**：当前问题、结论状态、先到先显的图表、筛选条件与挑战对照；优先呈现发现而非原始日志。
- **常驻「问数鉴」面板**：选中图形元素/结论即可追问“怎么算的”“只看某类呢”“能证明原因吗”；显示所引用的数据版本。
- **证据抽屉**：数据血缘、字段映射、实际 SQL、聚合结果、图表映射、可定位明细及局限。聚合由查询结果证明；展示几行示例并不等于这些行证明整体结论。
- **执行抽屉**：模型计划、MCP 工具调用、耗时、失败、重规划原因、查询 ID；日志脱敏但不伪造。
- **报告预览/导出**：与当前选择的分析分支、数据版本一致。

## 5. 实现架构与契约

```text
React + TypeScript + Vite + Zustand + ECharts
       │ REST 上传/追问/取证据；SSE 分析事件
       ▼
Node.js + Fastify Agent Host
  ├─ Model Gateway：联网 OpenAI 兼容模型；统一用于口径识别、规划、结果观察、追问和解释
  ├─ Agent Loop：结构化输入输出、步数与成本限制、失败重试/暂停、分支上下文
  ├─ Policy/Evidence Guard：参数验证、SQL 安全、数字引用与适用范围校验
  ├─ Dataset Registry：受控原始文件、数据 ID/版本、哈希、来源与生命周期
  └─ MCP Client ── stdio ── Data MCP Server
                              ├─ register_dataset / profile_dataset
                              ├─ execute_sql / analyze_dimension
                              ├─ detect_anomalies / build_chart_data
                              └─ sql.js 只读分析查询
```

- **数据边界**：Host 接收文件并保存到受控存储目录；MCP Server 通过经过校验的 dataset ID 注册数据，而不是让模型提交任意本地文件路径。服务重启时根据已保存的原始文件及元数据恢复注册。具体工具数量和 SDK 版本在最小冒烟测试后锁定；图表在浏览器使用真实查询结果渲染，报告可转为内联 SVG。
- **查询安全**：模型 SQL 是不可信输入；经单语句解析、只读语义校验、允许表/函数限制、参数化过滤、结果行上限和可中止的运行时/资源上限后才能执行。仅检查字符串以 SELECT/WITH 开头或补 LIMIT 不足以构成安全边界。上传的单元格也视为不可信内容，不得作为修改系统指令的依据。
- **对模型发送的信息**：默认问题、字段摘要、口径及执行必要的聚合结果；敏感原始行默认不上传给外部模型。若某任务需要发送更多，界面明确告知和征得确认。API Key 只在服务端，绝不进入浏览器、公开仓库或导出的报告。
- **可复核对象**：`datasetId`、原始文件哈希、`datasetVersion`、`analysisContractVersion`、`runId`、`branchId`、`queryId`、`chartId`、`claimId`。结论以 queryId/结果字段为引用，报表固定到数据版本；更换文件/口径或未来增加新数据，不静默覆盖旧结论。
- **实时含义**：第一版支持 Agent 步骤和查询结果通过 SSE 实时呈现，追问后重算；**不宣称已具备动态数据接入**。图表保存查询定义而非仅存图片，为将来数据版本更新后的重新查询和局部刷新预留接口。未来高频写入或大数据量时再评估替换 sql.js。
- **模型故障**：一次受控重试及可选另一真实模型；仍失败则保留已完成计算、明确提示 AI 分析未完成，可手动检查数据；不播放预设计划或伪造结论。

## 6. 第一版明确不做

- 虚构/合成业务数据及固定演示答案；伪造的 MCP、SQL 或 AI 调用日志。
- “上传任意文件就准确回答任何问题”的通用性承诺；PDF/OCR 财报全自动理解。
- 实时外部业务系统数据流、高频看板、多用户协作和权限系统。
- 无可靠样本依据的总体推断、无实验证据的因果断言、金融投资建议。
- 为凑评分硬加 RAG、多模态或没有分析价值的图表；四套独立 Agent 角色及跨供应商复杂编排。

## 7. 验证、交付与比赛材料

**先验证产品假设**：选择两份真实可合法使用、可追溯来源的不同结构数据，由人预先核定指标口径与关键参考结果；对每份提出正常问题及故意模糊的问题。比较竞品做相同任务的表现；请未参与开发者观察“口径确认”和“挑战结论”是否真的减少误解。没有通过验证时缩小产品承诺，不用包装取代测试。

**第一版硬验收**：
1. 用户上传真实文件可显示来源状态、原始文件哈希、行列及质量问题；没有伪造数据。
2. 财务/调查中至少各一条完整分析，关键口径不明时澄清；不支持的结构明确说明。
3. 联网模型至少完成一次真实计划、读取实际工具结果、决定继续/停下/调整；MCP 工具调用、SQL 和图表可在日志核对，步骤通过 SSE 逐步可见。
4. 页面显示的每个关键数值均可定位到对应查询结果；核验失败不展示为事实，汇总结论不依赖数条示例行做证明。
5. 常驻助手能解释现有图表、针对新增过滤条件真实重算、对不能回答的问题明确说明边界。
6. 「挑战结论」只在有合理替代口径时重算；保留原分支，清楚解释改动点。
7. 单文件 HTML 导出后离线打开，图表、来源、口径、SQL、结论及限制可阅读；用户敏感明细默认不包含。
8. 模型或工具失败时没有假成功、无限加载；上传恶意/格式错误文件与危险 SQL 有可见错误。

**赛项材料**：整理带真实提交历史的代码仓库、README、环境变量模板与运行说明；按官网当期要求准备普通话演示视频及 PDF 技术文档。赛程、视频规格、文档页数和提交入口在最终提交前再次核对官方页面和个人中心，不以本文件替代官方通知。

## 8. 开发顺序（纵向闭环，而不是堆模块）

1. 真实数据和标准答案准备；字段/口径风险清单；两类数据的人工基准。
2. 最小可运行闭环：上传 → 规范化 → 一次真实 MCP 查询 → 一张图 → 一条证据。
3. 接入联网模型的分析契约、计划、观察与追问；真实流式事件与错误状态。
4. 动态重规划、挑战结论、并排对照、证据审计与报告。
5. 浏览器端到端测试、数值回归、恶意输入、UI 打磨及参赛材料与演练。

**开发前关口**：先确认可用的真实数据、模型服务、上传数据发送到模型的隐私边界和官方参赛要求；未完成这四项，不承诺任意数据的分析准确性。
