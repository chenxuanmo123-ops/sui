# 2026 全国高校 AI Web 开发挑战赛：规则与评分标准

> 来源：用户于 2026-10-23 提供的赛事文本，本文按原文整理归档，未联网核验。
> 赛事名称、时间、比例等以大赛官网最终通知为准；如本文与官网冲突，以官网为准。
> 本文件只用于对齐开发与交付，不构成报名或获奖承诺。

## 1. 赛道与主题

- 主题：**“智启未来：AI 驱动的 Web 应用创新挑战”**。
- 面向全国全日制高等院校（含高职高专）在校学生，采用“院校赛—省赛—国赛”三级赛制。
- 核心考察：前端工程能力、AI 技术集成能力、创新思维、用户体验设计。
- 作品须为 AI Native Web 应用：AI 是核心能力，不是附属功能；须为原创，严禁抄袭或直接包装开源项目参赛。

## 2. 命题范围

可从推荐方向中选择，也可自拟。推荐方向共 10 个：

| 序号 | 方向 | 说明 |
| --- | --- | --- |
| 1 | AI Agent 智能助手 | 自主规划、工具调用、多轮对话 |
| 2 | RAG 知识问答系统 | 向量数据库 + 检索增强生成 |
| 3 | 多模态 AI 创意平台 | 文本、图像、语音、视频 |
| 4 | AI 协同办公工具 | 写作、会议纪要、项目管理、文档分析 |
| 5 | AI 教育与学习平台 | 个性化学习、智能出题、辅导 |
| 6 | AI 健康与生活服务 | 营养、心理、运动 |
| 7 | AI 代码开发辅助 | 审查、文档、架构、测试生成 |
| 8 | **AI 数据分析与可视化** | 自然语言交互完成查询、分析与可视化，降低分析门槛 |
| 9 | AI 安全与内容治理 | 内容检测、隐私保护、AIGC 识别 |
| 10 | AI 社交与社区应用 | 匹配推荐、社区运营、兴趣图谱 |

数鉴 Agent 对应方向 8。

选题要求：

- 原创；Web 形态呈现；AI 深度集成；鼓励解决真实问题、具备落地潜力；鼓励创新应用方式而非复刻已有产品。

## 3. 参赛规则

- 每队 1–3 名同校学生，指导老师不超过 2 名。
- 组别必须严格匹配：研究生组（研究生）、A 组（985/211 本科生）、B 组（普通本科）、C 组（高职高专）；低组别可报更高组别，反之不可。
- 组别选错将无条件取消参赛资格及成绩。

## 7. 比赛环境与技术栈

- 技术选型不强制；推荐 React + Next.js、Vue 3 + Nuxt 3、SvelteKit、React + Vite、Astro。
- 推荐 UI：Tailwind CSS、shadcn/ui、Ant Design、Framer Motion。
- 推荐 AI 集成：Vercel AI SDK（流式对话、Tool Calling、生成式 UI）、LangChain.js、Transformers.js、WebGPU/ONNX Runtime Web、Web Speech API、MediaPipe。
- 模型 API：OpenAI、Anthropic、Gemini、智谱、DeepSeek；多模态 GPT-4o、Gemini Pro Vision、通义千问 VL；语音 Whisper/TTS。
- 数据层：Zustand/Jotai/Pinia、TanStack Query、IndexedDB/LocalStorage、WebSocket/SSE。
- 特别说明：以前端为主要形态，后端只作为 AI 接入层；允许 AI 辅助编程，但选手须能解释所有代码；商用 API 费用自担；鼓励端侧推理与隐私保护。

## 8. 奖项与晋级

省赛：一等奖 ≤10%、二等奖 ≤20%、三等奖 ≤30%、优秀奖 ≤30%，一至三等奖晋级国赛。

国赛：一等奖 ≤5%、二等奖 ≤25%、三等奖 ≤30%、优秀奖 ≤40%。获奖比例可能按实际情况调整，且设有最低分数线；零分卷不得奖。

## 9. 违规处理

报名信息作假；违法违规；抄袭或侵犯知识产权；不健康内容；其他被认定的违规行为。组别选错同样取消资格。

## 10. 对数鉴 Agent 的直接含义

按评分项逐条对照当前实现（2026-10-24，详见 `docs/项目进度与交接说明.md`）：

| 评分项 | 当前状态 | 影响 |
| --- | --- | --- |
| 大模型集成 8% | OpenAI 兼容接入、计划校验、失败修复；公网已修通白名单与 workerd 重定向问题，但服务端未放真实密钥，访客需自填 | 需要一次真实 Key 的端到端验收与录屏 |
| Agent/工作流 8% | 规划 → 执行 → 修复 → 复核，有取消与进度 | 已具备，需在文档/视频中讲清“AI 不碰数字” |
| RAG 6% | 已实现浏览器内词法检索（中文二元组 + 英文词 BM25）与引用编号校验；不是向量语义检索 | 覆盖“检索增强 + 引用”，深度弱于向量 RAG，需如实说明 |
| 多模态 5% | PDF 页面视觉转录；CSV/XLSX | 部分覆盖，可补图片/图表理解 |
| AI 安全 4% | 计划校验、证据约束、数字不编造、限流、引用编号拒绝 | 已具备，是差异化亮点 |
| MCP/工具集成 4% | 未实现 MCP；浏览器 SQL 与本地检索可视作受控工具调用 | 明确缺口 |
| 选题创新 10% | “AI 规划 + 本地真实计算 + 证据回查” | 需要文档讲清与传统 BI/纯聊天分析的区别 |
| 交互创新 7% | 可审查计划、证据回查、口径追问；趋势与 Pearson 系数均带范围声明 | 已具备 |
| 前端工程 10% | React 19 + TS、Worker、懒加载；有分包警告 | 稳定 |
| 实用性 10% | 真实文件、真实计算、可导出报告与可复现 SQL 包 | 已具备 |
| 用户体验 10% | 界面完整；**无流式输出**、思考状态有限 | 明确缺口，优先补 |
| 社会/商业 10% | 降低数据分析门槛、本地计算与结论边界 | 需在文档中论证 |

**下一步优先级（按评分收益排序）**：真实模型 Key 验收与录屏 → 流式输出与思考状态 → MCP 的最小可行工具集成 → 分析工作台可用性（排序/搜索）→ 演示视频与技术文档定稿。
