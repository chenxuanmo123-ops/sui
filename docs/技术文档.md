# 数鉴 Agent 技术文档

> 版本：2026-10-24　｜　赛道：AI 数据分析与可视化　｜　在线演示：<https://sui-ae9.pages.dev/>

## 1. 项目概述

数鉴 Agent 是一个面向真实文件的 AI 数据分析与可视化 Web 应用。用户上传 CSV、Excel 或 PDF，用中文提出数据问题；系统先理解数据结构与分析目标，由大模型生成可审查的分析计划，用户确认后在浏览器内用 SQLite 执行真实 SQL，最后生成图表、证据报告和可复现 SQL 包。

项目要解决的不是“让 AI 写一段分析文字”，而是三个更具体的问题：

1. **数字可信**：大模型不接触计算，所有数值由数据库引擎执行 SQL 得到。
2. **结论可回查**：每个分组结果绑定来源记录号、数据快照指纹、实际 SQL 与参数。
3. **边界诚实**：缺失值不补零，样本不外推总体，相关不写成因果，失败不伪装成功。

产品定位是“可核查的描述性分析工作台”，不是通用聊天机器人、自动建模平台或 BI 大屏。当前明确不支持预测、回归、因果识别、任意 SQL 和跨库联表。

## 2. 需求分析

### 2.1 用户与场景

| 用户 | 典型任务 | 现有痛点 |
| --- | --- | --- |
| 学生 / 研究者 | 公开数据、问卷、实验记录的描述统计 | 工具门槛高，AI 给的数字无法核对 |
| 运营 / 产品 | 转化率、分组差异、月度变化 | 口径散落在表格和聊天记录里，难以复现 |
| 教师 / 评审 | 演示数据分析方法 | 结论与原始记录脱节，限制条件被隐藏 |
| 小型团队 | 快速检查 CSV / Excel | 不愿上传敏感原文件到第三方分析平台 |

原文件在浏览器内解析与计算；发给模型的是字段摘要、少量授权样本和用户主动上传资料的命中摘录，不是整份数据。这降低了敏感数据外流的风险，但也带来浏览器内存、文件大小和跨设备同步的限制。

### 2.2 功能需求

- 支持 CSV、XLSX、XLS、PDF；核对工作表、表头、范围与 PDF 提取内容。
- 字段类型候选、缺失、空白、IQR 异常、整行重复候选的分页核查；候选不自动删改。
- AI 初步定位、分析计划、失败修复、结果解读、范围追问。
- 真实计算：求和、均值、中位数、P25/P75、计数、非空去重、最值、条件计数比例、年/月分桶。
- 探索图表：柱状、折线、散点、热力、结果表；描述性趋势与 Pearson 相关。
- 证据链：SQL、参数、来源记录、快照指纹、HTML 报告、可复现 ZIP。
- 只读 SQL 控制台与会话级第二张 CSV 的 JOIN。
- 本机工作区恢复、模型连接管理、公网部署与密钥隔离。

### 2.3 非目标

- 不做预测、回归、显著性检验、因果推断。
- 不做任意 SQL、DDL、写操作、多语句执行。
- 不把平台样本、问卷样本或公开子集说成总体。
- 不宣称 MCP、向量 RAG、流式输出已实现；这些是明确的后续工作。

### 3.2 服务端分层

`server/ai.mjs` 是 AI 接口的核心，Node 入口与 Cloudflare Pages Functions 共用同一套逻辑：

- `server/contracts.mjs`：声明式 schema 与校验。
- `server/ai.mjs`：路由、提示词、计划校验、修复、证据与引用约束、限流。
- `server/model-client.mjs`：OpenAI 兼容传输、超时、错误映射、重定向拒绝。
- `server/structured-output.mjs`：从模型响应中提取并解析结构化对象。
- `server/profile-store.mjs`：仅本机模式保存模型连接。
- `functions/api/*`：Pages Functions 适配层。

### 3.3 部署架构

- 前端与 Pages Functions 部署在 Cloudflare Pages，项目名 `sui`，公网地址 `sui-ae9.pages.dev`。
- 仓库 `main` 分支推送触发自动构建；也可用 `wrangler pages deploy` 直接上传。
- 服务端模型配置使用环境变量 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`；访客自填接口还受 `LLM_ALLOWED_HOSTS` 白名单限制。
- 密钥只存在于服务端环境变量或当前页面内存，不写入浏览器持久化存储、日志或报告。
- Node 服务保留为完整备选，二者共享计划校验与证据绑定代码。

## 4. AI 技术方案

### 4.1 模型选型理由

选择 OpenAI 兼容的 Chat Completions 协议，而不是绑定单一 SDK：

- 兼容 DeepSeek、OpenAI 及多数国内服务商，部署者可以按成本、速度、合规要求切换。
- 同一套请求代码可运行在 Node 与 Cloudflare workerd，避免为部署平台重写。
- 支持 JSON 输出模式的供应商可开启 `response_format`；不支持时仍可用严格提示词与本地解析兜底。
- 结构化输出由服务端 schema 校验，不依赖模型“自觉遵守”。

默认示例配置为 DeepSeek，因为其中文理解与 JSON 输出成本适合比赛演示；但系统没有把 DeepSeek 写死，也没有宣称任何模型在所有数据上都准确。

### 4.2 集成方式

一次完整分析分为六个阶段：

1. **初步定位（可选）**：只发送字段名、候选类型、精确缺失统计、来源说明和用户授权的最多少量样本；输出字段角色候选、质量问题与可行方向，不输出统计值。
2. **计划生成**：输入数据摘要、用户问题、业务背景、可选参考资料；输出 `questions`、`tasks`、`hypotheses`、`limitations`。每个任务包含分组字段、指标、聚合方式、筛选、时间分桶、单位、图表类型。
3. **服务端校验**：字段必须存在；除计数外分组列与指标列必须不同；比例必须写明分子原值和分母取值集合；任务 ID 唯一；候选假设必须绑定真实任务。
4. **用户确认与执行**：前端展示每个任务的口径，用户勾选确认后，任务逐个编译为参数化只读 SQL，在 Worker 中执行；支持取消和仅重算失败任务。
5. **失败修复**：只把失败任务、真实错误和原计划发给模型；修正后的计划仍需用户确认，不静默改口径、不扩大样本。
6. **结果解读**：只发送真实结果的分组摘要与事实编号；每条陈述必须引用存在的 `evidenceIds`，不能输出数字字符；引用参考资料时必须使用已提供的编号。

### 4.3 结构化输出与优化策略

| 策略 | 实现 | 目的 |
| --- | --- | --- |
| Schema 前置 | 系统提示词附 JSON schema，要求只返回完整对象 | 降低格式漂移 |
| 本地解析 | `structured-output.mjs` 处理代码框、前后说明、字符串内括号 | 不因包装文本误判失败 |
| 服务端校验 | `validate` + `checkPlan` / `checkReview` | 拒绝字段不存在、口径矛盾、证据越界 |
| 有限重试 | 同一 180 秒预算内最多两次；只重试内容/格式错误 | 不重试鉴权、网络或语义错误 |
| 输出上限 | 按供应商与模型设置 `max_tokens`；推理模型单独放宽 | 控制延迟与费用 |
| 取消传播 | 浏览器断开即 Abort 上游请求 | 避免无效计费与悬挂 |
| 错误映射 | 400/401/402/403/404/422/429/5xx 转为可操作中文提示 | 用户能区分密钥、余额、限流与地址错误 |
| 重定向拒绝 | `redirect: 'manual'` 并显式拒绝 3xx | 防止带密钥请求被转发到其他域名 |

### 4.4 AI 安全与可控性

- **数据不可信**：提示词明确数据单元格、错误文本、参考资料都只是数据，不能改变指令。
- **最小授权**：默认不发送原始样本和完整类别字典；用户逐项授权后才发送有限样本。
- **数字隔离**：解读提示词禁止输出数字字符，数值由界面从真实结果单独呈现。
- **证据绑定**：`evidenceIds` 必须来自本次事实集合；未知编号整条拒绝。
- **引用校验**：只允许 `R-x` / `M-x` 形式且必须来自本次提供的资料；资料不能替代计算证据。
- **比例防失真**：比例任务不能预先筛选结果列；分子必须包含在分母集合中；分母为零显示“无法计算”，不显示 0%。
- **限流与体积**：每 IP 每分钟最多 20 次；普通请求体 400 KB，文档转录 6 MB。
- **密钥边界**：公网模式禁止网页保存服务端连接；本机保存的密钥不回传浏览器。

### 4.5 本地资料检索（RAG 的当前实现）

- 支持 PDF、TXT、Markdown；PDF 保留页码，扫描件无文字层时明确拒绝。
- 浏览器内切分为带页码的片段；中文二元组 + 英文单词的 BM25 检索，另有 16 条内置方法提示（缺失值、分母、相关与因果等）。
- 每次最多发送四段命中摘录，合计不超过 6000 字；不发送整份资料。
- 资料只用于口径、术语和风险提示，不进入数据快照、图表、报告或计算证据链。
- 局限：这是词法检索，不是向量语义检索；同义改写、长文档跨段推理的能力有限。

## 5. 核心功能实现

### 5.1 文件导入与质量检查

- 单文件上限 30 MB；最多 100,000 行、200 列；Excel 有效区域最多 200 万个单元格。
- CSV 保留原始字符串，去掉 UTF-8 BOM、CRLF 与表头首尾空白；表头必须非空且不重复。
- Excel 需确认工作表、表头行与数据范围；合并单元格、公式缓存值和空行按导入器规则处理。
- PDF 支持文字提取与需授权的页面视觉转录；每次导入一页中的一张表，必须人工核对。
- 质量检查输出：字段类型候选、非空数、空值率、首尾空白、非数值、IQR 异常候选、整行后续重复候选。候选只用于核查，不自动删除或改写。
- 数值解析采用严格模式：`$1,234`、会计负数、百分号、全角字符等需用户显式勾选后处理；`1.2万元`、`N/A` 等无法识别值保留原文或选择置空，绝不当作 0。

### 5.2 真实计算引擎

- sql.js（SQLite/WASM）运行在独立 Web Worker，主线程保持可交互。
- 数据写入临时表 `data`，列名为 `c0…cN`；`readable` 视图映射原表头；另有 `strict_number`、`compare_labels`、`time_bucket` 三个 UDF。
- 所有分析使用参数化只读 SQL；写操作、DDL、PRAGMA、事务、多语句、`sqlite_*` 内部表在控制台层拒绝，Worker 侧设置 `PRAGMA query_only` 兜底。
- 聚合包括求和、均值、中位数、P25、P75、计数、非空去重、最小、最大；分位数用窗口函数线性插值。
- 条件计数比例：分子为结果列等于指定原值的记录数，分母为结果列属于指定取值集合的记录数；未知/缺失排除并报告；总体比例按总分子 ÷ 总分母计算，不平均分组比例。
- 查询结果同时返回来源记录号；每个分组可展开到原始行。缺失值不补零，非数值不参与数值聚合。
- 取消机制：终止 Worker 并重建引擎；已完成结果保留，未完成任务可继续。

### 5.3 探索分析与统计边界

- 图表：柱状、折线、散点、热力、结果表；支持筛选、排序、展示上限和来源回查。
- 时间趋势：仅对折线图按年/月分桶后的聚合时间点做最小二乘拟合，显示平均每期变化与 R²；分类维度、常数序列、少于三个时间点不显示。它不是预测、显著性检验或因果结论。
- Pearson 相关：散点图在当前筛选下的**全部有效配对**上计算 r 与 n。居中在 SQL 中通过 `AVG(...) OVER ()` 完成，避免大数相减丢精度；展示上限只限制画点，不改变系数覆盖范围；截断时卡片与报告明确说明两者范围不同。
- 有效配对少于三条或任一字段为常数时不返回系数，不用 0 或 1 冒充结果。
- 卡片与 HTML 报告均写明：只衡量线性同步程度，不是因果、预测能力或显著性检验；极端值、非线性与共同趋势都会影响 r。

### 5.4 证据链与交付

- 数据快照指纹：对清洗后的当前快照计算 SHA-256；原文件指纹与处理步骤单独保留。
- 结果到来源：每个分组保存来源记录号；证据面板可查看 SQL、参数、口径和原始记录。
- HTML 报告：单文件，内嵌图表 SVG、SQL、参数、结果、来源节选、处理记录与限制说明；文件单元格全部转义。
- 可复现 SQL 包：ZIP 内含清洗后 `data.csv`、`schema.sql`、参数内联的 `analysis.sql`、`expected.json`、`run_analysis.py` 与说明。脚本仅依赖 Python 标准库，重建 SQLite、重跑同一 SQL 并逐行核对，输出 `PASS` 表示复算一致。该保证仅限包内快照与 SQLite + Python 路径。
- 报告明确“原始记录节选不等于完整源文件”“描述性分析不证明因果”。

### 5.5 只读 SQL 控制台

- 支持单条 SELECT / WITH；最多返回 500 行。
- 左侧展示 `data`、`readable` 的列映射与三个 UDF；可上传会话级第二张 CSV 作为 `extra` / `extra_readable` 做 JOIN。
- 拒绝写操作、DDL、PRAGMA、事务、参数占位符、内部表和一次多条语句；字符串或注释中的关键字不算违规。
- 查询结果可按真实数值列绘成柱形/折线图；不重新聚合、不插补缺失值；纯文本结果不生成数值图。
- 关联表不写入快照、不进入证据链或报告，切换数据或刷新后消失。

### 5.6 工作区与隐私

- 工作区保存在当前设备、浏览器和站点地址的 IndexedDB；刷新可恢复，不跨设备同步。
- 恢复不会自动重复调用模型；换浏览器、域名或设备不会自动同步。
- 原文件在浏览器内处理；模型所需元数据、少量样本、类别字典与资料摘录按授权发送。
- 本机模型连接保存在 `.local/`（已忽略），状态接口不回传密钥；公网模式禁止网页保存服务端连接。

| 核心/导入/追问/质量/取消等浏览器脚本 | OWID、UCI、SEC | 分别覆盖图表、导入格式、范围追问、质量诊断、任务取消 |

这些测试证明代码路径和边界行为，不能表述为“任意数据分析准确”“任意模型兼容”或“真实模型业务结论正确”。

### 6.4 已修复的部署问题

- **白名单未生效**：Cloudflare Pages 的环境变量不会注入到已存在的部署，需重新发布后生效。
- **workerd 重定向缺陷**：`fetch(..., { redirect: 'error' })` 在 workerd 中会在发送前抛 `TypeError`；改为 `redirect: 'manual'` 并显式拒绝 3xx，既兼容运行时，也避免密钥随跳转外泄。
- **真实可达性**：用假密钥探测公网 `/api/ai/test` 返回上游 HTTP 401，证明 Cloudflare → DeepSeek 链路已通；这不等同于真实 Key 的分析验收。

### 6.5 当前限制

- 无服务端真实密钥时，公网访客需自填 Key；自填密钥只保存在页面内存。
- 单文件 30 MB、100,000 行、200 列；大文件受浏览器内存与解析时间限制。
- 参考资料检索是词法 BM25，不是向量语义检索。
- 未实现流式输出、MCP、预测/回归/因果分析。
- 公网高并发、长时间可用性、多访客隔离尚未做压力验收。

## 7. 创新点

### 7.1 技术创新

1. **AI 规划与计算执行分离**：模型只输出受 schema 约束的计划，SQL 由本地引擎执行；从架构上消除“模型编数字”。
2. **计划可审查、可修正、可局部重算**：每个任务独立执行，失败只重算失败任务，成功结果不丢失；修正前后口径对照。
3. **证据绑定到记录级**：结果分组 → 来源记录号 → 原文件位置 → 快照指纹 → SQL/参数，形成可回查链路。
4. **可复现交付**：导出的 ZIP 可在本地用 Python 标准库重建数据库并复算，输出 PASS/FAIL，不依赖本产品。
5. **全范围相关与展示范围分离**：散点图只画前 N 条，但 r 用全部有效配对计算，并在界面明确说明覆盖差异，避免“图上看不出、数字却很大”的误导。
6. **统计边界前置**：趋势与相关卡片直接写明非因果、非预测、非显著性检验；分母为零不显示 0%。

### 7.2 应用创新

- 面向中文真实文件与中文提问，不要求用户先学 SQL 或建模。
- 把“口径确认”做成产品的一等公民：行粒度、单位、分母、筛选范围都可以在计划里核对。
- 失败是可见的：模型失败、任务失败、资料冲突、样本不足都会显示原因，不伪装成成功。
- 本地计算降低敏感数据外流风险，适合教学、审计与公共数据核查。

## 8. 总结与展望

数鉴 Agent 已完成从导入、质量检查、AI 规划、真实计算、可视化到证据报告的闭环，并在 Cloudflare Pages 上提供可访问的公网演示。它的核心不是“更会聊天的 BI”，而是把 AI 的能力限制在理解、规划和解释，把数字交给可验证的计算与可回查的证据。

后续优先级：

1. 用真实模型 Key 完成端到端验收与录屏，记录供应商、模型 ID、提示词版本与人工评分。
2. 流式输出与思考状态可视化，补齐交互体验评分项。
3. 评估 MCP 的最小可行工具集成（如只读数据库连接或文件系统），坚持受控与可审计。
4. 扩充真实数据评测：更多领域、更多口径陷阱、更多模型供应商。
5. 完善提交材料：团队信息、5–8 分钟视频、30 页内技术文档 PDF。
