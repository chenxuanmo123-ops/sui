## 1. 执行摘要

**一句话定位**：数鉴 Agent 是对真实、可能杂乱的表格数据进行**可质询、可复算、可纠错**分析的 AI 工作台。

**核心产品旅程**：真实文件导入 → 预览并审查问题行 → 用户确认清理动作与分析口径 → 联网 Agent 调查 → 实际 MCP 工具与 SQL 执行 → 图表逐步出现 → 结论与限制 → 用户追问或挑战 → 新分支重新计算 → 导出定版证据报告。

**差异化假设（需竞品与用户验证）**：相对“输入问题直接出图”，用户更需要知道哪些原始行被排除、数字采用什么口径、结论换一种合理口径后是否仍成立。创新不在技术名词数量，而在将**数据整理—分析决策—反证—证据检查**串成可操作的网页交互。当前尚未完成竞品实测，不把此假设写成已建立的市场领先优势。

**P0 成功定义**：公网版在模型可用情况下，能用至少两种实际业务类型的真实文件完成完整旅程；一份文件包含可审查的真实脏数据；评委能打开任一关键结论的证据、发起一次有效挑战，看到新增实际查询和变化；网络/模型/MCP 失败时不显示假成功。所有验证结果以测试记录为准。

## 2. 用户、场景与业务边界

### 2.1 目标用户与价值

- 有权使用业务或公开表格、会描述问题但不熟练编写 SQL 的业务分析者、研究人员、学生和团队负责人。
- 首要任务不是自动化一切，而是安全地回答“这份数据**能支持**什么结论、按什么口径得到、替代解释是否成立”。
- P0 为单用户分析会话；公网多访客之间仍必须实施数据隔离和访问控制。

### 2.2 核心场景

| 场景 | 允许回答的内容 | 阻断/警告边界 |
| --- | --- | --- |
| 财务指标清单 CSV/XLSX | 同主体、同口径、同币种/单位的期间比较与维度拆解 | 不把累计值当当期值，不把营收当利润；不构成投资建议 |
| 调查或平台使用记录 | 样本内次数、比例、分组比较，明确样本量、分母、多选规则 | 使用次数≠偏爱；便利样本≠全网；无抽样设计不推断总体 |
| 其他记录级单表 | 明确字段映射后的筛选、分组、趋势和分布 | 缺少时间/目标字段时不编造趋势或业务语义；不自动跨表连接 |

“3 月营收为什么下降？”只能据现有维度描述**与下降同时出现的变化和待检验解释**；如果缺少足够证据，不得把相关性写成确定因果。非支持数据必须给出具体阻断原因和仍可完成的分析任务。

### 2.3 范围与非目标

**P0 包含**：CSV/XLSX 单表/单工作表、可审核的混乱数据整理、字段及质量诊断、中文提问与关键口径确认、联网 Agent、真实 MCP/SQL、假设及反证、五类呈现（折线/柱状/散点/热力图/表格，按数据适用性选取）、常驻追问、挑战分支、证据抽屉、单文件 HTML 报告、上传删除及错误恢复。

**P0 不包含**：任意网站抓取、全网舆情代表性推断、通用聊天、预测性机器学习、持续外部数据流、自动跨多表关联、任意 PDF/OCR、未经验证的因果结论、多用户协作权限。图表的“实时”指**本次查询完成后渐进渲染**，不是外部数据不断刷新；未来动态数据可利用数据版本/查询定义重新计算，不在 P0 声称已接通。

**条件性扩展，不作为 P0 完成条件**：指定格式的真实 PDF/扫描表视觉识别；有真实文档需求时的检索增强（第 8 节）。核心链路、证据完整性和公网稳定性优先级更高。

## 3. 产品原则与核心交互

1. **原始数据不被静默改写**：任何跳行、转换、拆分、修正都有理由、预览、操作者和可追溯的版本；用户可回退。
2. **影响结果的口径先确认**：模型可以建议，不能替用户默默决定“偏爱”“退款”“当期/累计”“分母”等关键含义。
3. **数值由工具产生，文字受证据约束**：模型负责提问、规划与解释；关键数字须来自已执行查询/统计并经过规则检查。
4. **反证是用户动作**：每条可分析结论提供“挑战这条结论”，展示合理替代口径、用户确认、新查询及原/新对照；不伪造反证成功。
5. **事实与推断分级**：区分“数据事实”“相关变化”“可能解释”“因果未证实”；证据不足时拒绝肯定表述。
6. **失败诚实可见**：网络或模型断开则暂停及允许恢复，不回放预置答案冒充 AI。

### 3.1 信息架构

```text
数据入口（上传／来源／文件版本）
 └─ 整理台（工作表与区域选择、杂行识别、字段映射、处理差异预览）
     └─ 分析工作台（问题、口径确认、渐进图表、结论）
         ├─ 常驻「问数鉴」（问图、追问、换口径）
         ├─ 「挑战这条结论」（原／新分支并排）
         ├─ 证据抽屉（来源→原行→清理规则→查询→数值→结论）
         ├─ 执行抽屉（计划、实际 MCP 调用与状态）
         └─ 报告预览与导出（版本冻结、脱敏）
```

默认视图强调问题、结果和可信度；技术日志按需展开但真实可查。桌面端优先支持证据/图表并排，移动端保证阅读与基础操作，不保证复杂多栏分析在小屏完整同屏展示。

## 4. 功能需求与验收（P0）

优先级定义：**P0** 为第一批作品上线阻断项；**P1** 为时间/验证条件满足后才进入迭代。每个验收要求以真实文件或安全/单元测试记录证明；单元测试可使用构造的最小 fixture，但产品演示不得以虚构业务文件冒充真实数据。

### FR-01 真实文件、来源与版本（P0）

**行为**：用户上传 CSV/XLSX，选择 XLSX 工作表；显示文件大小、工作表、候选行数、来源类型。公开文件记录发布机构、原始地址、取得日期、使用条件；用户自有文件记录“来源由用户声明、未经平台独立核实”。原文件受控保存、计算 SHA-256，分配数据版本，禁止直接用 URL 对未知站点抓取数据。

**验收**：空文件、格式错误、超出测试限额得到明确错误；同一版本哈希可核对；公开文件展示“取得时的快照”，不冒充实时数据；删除后服务不再允许访问该文件及派生分析，已下载的离线报告无法远程撤销，界面须提醒。

### FR-02 混乱数据诊断与区域选择（P0，V2 新增重点）

**行为**：显示原文件前后及异常区域的行列预览；检测候选表头行、空白分隔行、页脚/备注、疑似合计/小计、列数不一致、合并单元格影响、单元格公式结果/错误、混合类型与单位、日期/金额不合法。每条诊断给**问题类型、原始位置、建议动作、置信或不确定提示**，默认不自动删除可疑数据。用户选择表格区域、表头、是否跳过特定行/列，并可撤销；若无法可靠确定，阻断后要求人工确认。

**验收**：一份有真实备注/合计行的授权文件，不会在用户未确认下将其计入记录总数或静默移除；原始定位支持“文件—工作表—物理行号—列”；CSV 原文与 XLSX 原工作表保留可回看。被跳过行可一键查看，不能以“脏数据”概括所有不符合预期的有效记录。

### FR-03 类型、清理规则与质量审计（P0，V2 新增重点）

**行为**：字段原名、候选语义/类型、空值、解析失败、重复值、日期范围和可疑单位可视化。清理动作分为保留原值、标记缺失、显式格式转换、整行排除、字段映射；对每项给应用前后记录数和受影响行清单。用户确认后产生不可变 `cleaningVersion`；任一改变有效数据集的操作生成新版本并使旧结论标“针对旧版本”。原值和转换后值并存，错误样本可下载/查看（受权限约束）。

**验收**：“1,200”与“1.200”不无条件同义；非法日期不悄悄转成另一日期；修改跳行规则后指标确实重新查询；显示排除记录数/总数，证据可指向原始行与处理规则。

### FR-04 中文问题和分析契约（P0）

**行为**：模型根据问题和字段摘要拟定指标、分母、期间、记录粒度、币种/单位、筛选、比较基准、字段映射和适用样本。对**影响答案**的歧义要求用户确认；不影响答案的默认值公开展示。契约有版本号，用户可调整，旧结论保留旧口径标签。

**验收**：只有使用次数时不自动回答“偏爱”；没有利润字段不把营收说成利润；财报累计与当期不混算；确认后的口径与 SQL 条件一致；对不能计算的问题给出可解释拒答。

### FR-05 联网模型 Agent 调查（P0）

**行为**：正式工作流使用真实联网模型完成意图理解、计划、工具选择、结果观察和解释；Planner/Executor/Analyst/Critic 是可审计的责任环节，**不要求四个模型**。结构化 JSON 输出经服务端 Zod 校验，步数、耗时和查询预算限制；提出有数据依据的竞争假设，读取每次工具的实际返回后决定继续、重规划、澄清或停止。审计环节核对数字、单位、分母与已执行结果。

**验收**：可看到一个由真实工具结果触发的计划调整或假设撤回；若数据不支持多个合理假设，说明不足而不是编故事；模型响应失败则暂停或安全重试，不用预设规划器冒充在线 AI。

### FR-06 独立 MCP 服务和工具链（P0）

**行为**：公网 Agent Host 用官方 MCP SDK 的 Client 通过 Streamable HTTP 连接独立 Data MCP Server；Host 管理认证的数据版本，MCP 工具按授权的 `datasetId/version` 访问数据。至少实现 `profile_dataset`、`execute_sql`、`analyze_dimension`；按可验证价值增加 `detect_anomalies`、`build_chart_data`。每次真实调用产生脱敏事件：工具名、输入摘要、开始/完成/失败、耗时、关联 queryId/错误。`register_dataset` 可作为 Host 内部操作；`build_report` 可由 Host 实现，不为凑工具数而假装 MCP 调用。

**验收**：至少三个不同数据分析 MCP 工具在公网链路真实调用成功；从 UI 日志可定位服务端请求与 SQL 结果；关闭 MCP 服务时可见失败且不会产生成功日志。浏览器端 sql.js 可以用于原型，但不得冒充远端 MCP 的 SQL 执行。

### FR-07 真实 SQL、资源与数据隔离（P0）

**行为**：对确认后的数据版本执行真实 SQL，查询结果冻结查询定义/参数/版本。模型所提 SQL 视作不可信：按 SQL 解析树约束**单个只读 SELECT/受约束 CTE**、表列函数白名单、参数化筛选值、权限校验、结果大小/执行时间/内存上限。拒绝写语句、ATTACH/PRAGMA、多语句、未授权表和危险递归。sql.js 作为候选执行引擎；如运行时中断/隔离不可验证，缩减查询形态或换可安全隔离的执行方案，不能仅靠补 LIMIT 自称安全。

**验收**：正常查询可复跑；多语句注入、其他用户数据集 ID、耗资源语句被拒绝/中止；零分母、空值、财务单位转换明确呈现；上线前完成恶意输入测试。

### FR-08 渐进图表及选择（P0）

**行为**：分析得到已完成查询后逐步渲染适用的折线、柱状、散点、热力图和明细表；不是所有数据都强行生成五种图。标注指标、单位、期间、分母、数据版本、筛选和缺失情况；点击图元可问图、打开证据或用筛选再计算。保存图表编码与查询绑定，避免图和答案属于不同版本。

**验收**：查完一项可先看到一张真实图；失败的查询不产生成功图；查询/口径变化后联动更新或清楚标记旧图；空结果给解释而非空白容器。

### FR-09 结论证据、审计与推断等级（P0）

**行为**：每条重要结论及关键图元绑定 `datasetVersion + cleaningVersion + contractVersion + queryId + 实际 SQL/参数 + 查询结果 + 原始行定位或来源范围 + 审计状态`；明示处理后的原值/修正值、排除规则、样本数及限制。数据事实、相关变化、可能解释分级；原始行只证明“来自哪里”，聚合数字需可复核的完整查询及结果。大范围聚合不承诺枚举每一行。

**验收**：抽查关键数字能用存档数据版本和相同口径独立复算；证据缺失的文本不能标为“已审计”；明细行号可回到原件；改版后旧结论可见但注明失效/过期。HTML 报告若不内嵌完整原始数据，**只能展示审计过程和查询证据，不能宣称脱离原数据可完整重新运行 SQL**。

### FR-10 常驻追问与「挑战这条结论」（P0，主创新交互）

**行为**：常驻问数鉴回答数字怎么算、图表为何变化；需改变筛选或指标的问题，创建新的查询与图表，不用旧结果直接改口。每条支持反证的结论提供「挑战这条结论」：推荐**有数据依据**的替代分母、时间窗、异常值规则或排除规则；用户选择/编辑并确认后，新 `branchId` 保留原分支，运行真实 MCP/SQL，比较原/新数值、适用样本、口径和结论强度。如果替代口径需要清理数据，先回到 FR-03 确认，不能悄悄改写原分支。

**验收**：改变一个关键条件触发新工具调用；原结论不丢失；界面清晰标注“两次查询的口径是否可比”，若不具有可比性只展示差异不宣称哪个正确；不支持的挑战说明缺少什么字段/证据。

### FR-11 报告预览与导出（P0）

**行为**：选择分支和已审计结论，在服务端组装单文件 HTML，静态 SVG 图表/等价内嵌图、指标与单位、来源声明、文件哈希和版本、清理规则摘要、分析契约、关键 SQL/参数/结果、反证对照、推断等级/限制。导出前提供敏感行/列预览和遮蔽选项；未完成的报告标“草稿/未审计”，不能用完整报告样式掩盖失败。

**验收**：断网能打开已下载报告；数字与当次页面查询一致；无外链脚本、无需服务端或模型才能阅读；特殊单元格按文本安全转义，不产生可执行 HTML；报告是否包含原始数据及其再分发许可由用户明确选择，默认不包含。

### FR-12 失败恢复、重置与用户控制（P0）

**行为**：上传、解析、模型、MCP、SQL、SSE、报告失败都显示真实阶段与原因；可取消、重试、清空会话和删除上传数据。SSE 断线重连按 eventId/序号去重，不重复执行工具；不同用户会话隔离。报告已下载后用户自行持有，不承诺远程删除本地文件。

**验收**：故意断开模型/MCP 不会继续出现伪造步骤；重复提交或 SSE 重连不重复扣费/执行副作用；删除后鉴权检查不可访问旧数据，清理周期与删除范围在界面告知。

## 5. 数据、证据和事件契约

```text
Dataset {datasetId, ownerSessionId, originalHash, sourceDeclaration,
         sourceUrl?, retrievedAt?, sheetName?, createdAt, retentionPolicy}
CleaningDecision {decisionId, datasetId, originalRange, action, reason,
                  proposedBy, confirmedBy, beforeCount, afterCount}
DatasetVersion {datasetVersion, originalHash, regionSelection,
                cleaningVersion, columnMapping, createdAt}
AnalysisContract {contractVersion, datasetVersion, metric, denominator?,
                  timeField?, granularity?, filters, units?, populationScope,
                  confirmedByUser}
Run {runId, parentRunId?, branchId, contractVersion, status, planRevision}
ToolInvocation {toolCallId, runId, name, argsSummary, status, startedAt,
                finishedAt?, resultRef?, errorCode?}
QueryEvidence {queryId, datasetVersion, cleaningVersion, contractVersion,
               sql, parameters, resultRef, sourceRowRefs?, auditStatus}
Chart {chartId, queryId, type, encoding, datasetVersion}
Claim {claimId, branchId, queryIds[], statement, inferenceLevel,
       caveats[], auditStatus}
Report {reportId, datasetVersion, selectedBranchIds[], exportedAt,
        containsRawData, redactionPolicy}
```

- 原始行定位使用文件原始工作表物理行号，不以清理后“第 1 行”冒充来源位置。清理过的字段同时保留原始值与标准化值。
- 来源声明和哈希分别解决“声称从哪里来”“这次分析用的是哪个文件”，均**不证明数据真实可靠**；来源方许可和数据真实性应区分记录。
- 正式分析只消费已确认的清理版本和分析契约；每个图表、查询、结论、报告都锁定版本；删除后访问失败，缓存/日志清理策略须落实。
- 事件最小字段为 `eventId/runId/branchId/sequence/timestamp/type/payload`；类别含 `profile_ready`、`cleaning_proposed`、`cleaning_confirmed`、`contract_confirmed`、`plan_created`、`tool_started`、`tool_completed`、`tool_failed`、`plan_revised`、`query_ready`、`chart_ready`、`claim_audited`、`run_failed`、`run_completed`。事件是已发生动作，不是“AI 思考中”的戏剧化回放。

## 6. 系统架构与非功能要求

```text
React + TypeScript + Vite + Zustand + ECharts
  ├─ 导入/整理台、分析主画布、问数鉴、挑战、证据与执行抽屉
  └─ REST 上传/确认/分析/追问/导出；SSE 订阅运行事件
                         │
                         ▼
Node.js + Fastify Agent Host（公网）
  ├─ 数据来源、版本与鉴权；文件/会话存储
  ├─ 联网 Model Gateway；Agent Loop / Zod / 预算 / 审计
  ├─ 报告生成器；事件日志与任务状态
  └─ 官方 MCP Client ── Streamable HTTP ── 独立 Data MCP Server
                           ├─ profile_dataset / execute_sql
                           ├─ analyze_dimension / detect_anomalies（按验证）
                           └─ build_chart_data → 隔离的真实 SQL 执行引擎
```

**前端**：React、TypeScript、Vite、Zustand、ECharts；CSV 可用 Papa Parse，XLSX 库需上线前核查实际维护/许可与安全情况。服务端重新验证前端上传结果。大文件和大型图表应限制加载、采样/分页并标注“只显示部分”；不以图表采样替代指标全量计算。

**模型**：使用 OpenAI 兼容接口仅作为候选接入方式；先验证所选供应商的结构化输出、长任务失败率和工具调用兼容性。API Key 只在服务端；当模型不可用，可重试或切换到另一个**真实联网模型**（若已配置和验证），但不伪称离线预设流程是 AI。模型只接收最小必要的字段信息、查询结果及用户授权上下文。

**安全与隐私**：公网隔离用户数据、限定文件类型/大小/行数与服务预算；数据集 ID 由 Host 校验授权，MCP 不信任调用方自行声明所有权；防 SQL 注入、XSS/报告脚本注入、公式注入（若未来导出 CSV）、恶意大文件及模型代理滥用。Referer 不是鉴权。明确服务端存储地点/期限、模型提供方/最小传输范围、删除实际生效范围；**不得宣传“数据完全留在本地”**。敏感原始行默认不传给外部模型，需要时说明字段范围并取得确认。模型推理用的私有数据不应进入公开仓库、截图或可公开的调用日志。

**可靠性**：Agent 步数、时间和开销上限；SSE 重连不重做任务；报告生成幂等；公网评审期间运行监测和账单预警；任务失败保留已完成证据但显式标不完整。性能阈值在真实样本压测后确定并写入 README/页面，不先承诺无限大小或零延迟。

**部署**：单一仓库可本地复现和公网部署；选择支持文件持久化、受控 MCP 服务、稳定 SSE/等价事件回放和长任务运行的方案。只把前端部署到静态托管、SQL 留在浏览器，不符合本版“公网 Host → 独立 MCP 数据服务”目标；若架构变更，需修改本 PRD、技术文档和演示口径，不默默降级。

## 8. 测试、验收与发布门槛

### 8.1 必需的真实数据与基准

- 至少两类可合法使用的真实文件：一种财务指标清单；一种调查/平台使用记录；确认来源、使用条件、字段口径、样本范围和人工复核指标。没有拿到对应文件就不能把“两类已验证”写成成果。
- 主演示文件需包含真实的非标准区域/异常记录；团队记录真实处理决策，不人工往数据中塞一行假“坏数据”。可另用匿名或授权的真实文件作用户测试。公开样本如经脱敏处理，应声明脱敏范围与数据派生关系，不再声称原样。
- 自动化安全/解析测试可以使用构造的最小 fixture；测试 fixture 与面向评委展示的“业务数据”严格分开。

### 8.2 核心端到端验收 A1—A10

| ID | 用户动作与通过标准 |
| --- | --- |
| A1 | 从公网地址上传真实文件或导入经核验的公开快照，查看出处、许可、工作表和文件哈希 |
| A2 | 看到真实异常行/插入说明/小计行，检查原位置，确认保留或排除；版本及受影响行数正确 |
| A3 | 提中文问题，关键口径不清时先确认，不可回答时有具体拒答理由 |
| A4 | 看到真实联网模型计划及至少三个不同 MCP 数据工具的实际调用与返回状态 |
| A5 | 见到实际 SQL 查询、逐步渲染的适合图表及与版本一致的数字 |
| A6 | 当实际结果不支持某假设时撤回/标未证实，且不无依据宣称因果 |
| A7 | 点击关键结论查看 SQL、参数、聚合结果、清理版本、源文件行定位/覆盖范围 |
| A8 | 追问或挑战合理替代口径，实际新增查询并保留原分支，呈现新旧口径差异 |
| A9 | 下载单文件 HTML，断网打开；口径、局限、证据、脱敏状态与页面一致 |
| A10 | 模型、MCP 或 SSE 故障注入时页面不假报成功；重试、删除及公网隔离有效 |

“假设淘汰”“重规划”验收要在**真实数据确有足够条件**时核查；否则以明确证据不足通过边界项，而不是通过编造假设凑流程。两类文件均运行基本旅程；包含异常数据的文件额外覆盖 A2；至少一条有效挑战覆盖 A8。

### 8.3 测试和质量证明

- **Vitest**：CSV/XLSX 异常解析、定位与回滚、统计口径、SQL 白名单/越权/超时、聚合复算、证据版本、报告转义/脱敏。
- **Playwright**：公网相同构建物下的上传—整理—问答—挑战—导出、断网打开报告、会话隔离、失败状态、关键窄屏操作。
- **人工参考值**：团队逐个标注真实数据中的关键指标、分母、时间和异常处理结果；对比系统输出、记录通过数/受检数、失败及修复，而不是编造一个“准确率”。
- **可用性**：邀请未参与开发的使用者尝试 A1—A9，观察能否理解“样本不等于总体”“推测不等于因果”；汇总卡点与改版记录。
- **性能与安全**：在确定上限的真实文件规模下测上传/查询/首图时间，公布测试机/网络/文件大小；用超限文件、恶意 SQL、HTML 注入与滥用请求检查失败行为。
