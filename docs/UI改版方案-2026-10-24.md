# UI 改版方案（2026-10-24）

基于真实 UCI Bike Sharing 数据的 AI 全流程试跑、当前界面截图，以及 `anthropics/skills` 的 `frontend-design` 规范（已安装到 `.claude/skills/frontend-design/`）整理。

## 1. 为什么现在“看起来没大变化”

当前界面已经做过一轮“证据笔记本”改造，但方向本身落进了通用 AI 设计套路：

- 暖米色纸面 `#f3efe5` + 高对比衬线标题 + 深绿 + 砖红批注。`frontend-design` 明确把这组“暖奶油底 + 衬线 + 陶土色”列为最常见的生成式设计特征。
- 页面仍是“卡片纵向堆叠”：体检、三个问题、质量提示、原始表、字段速览、AI 定位、手动计算依次向下，主操作被推到首屏之外。
- AI 助手是覆盖在内容上的浮窗。1440 宽度下会挡住字段表和结果，视觉上像外挂，不像工作台的一部分。
- 结果页每个任务都重复“标题 + 五段解读 + 图表 + 表”，三个任务就把页面拉到 3000px 以上；真正要看的数字被说明文字包围。
- 字号层级靠 11–12px 的小标签硬撑，正文对比度偏低；数字没有统一等宽/表格数字，读起来不像“测量结果”。
- 两个导航层（顶部主导航 + 工作台分区）加分析路径条，再加页面内浮动“跳到分析内容”，层级过多，且浮动链接在截图里直接压住内容。

结论：不是配色不好看，而是**信息结构和视觉隐喻没有换**。只换颜色不会解决“没有亮点”。

## 2. 设计方向

### 方案 A（推荐）：审计台 Evidence Desk

把产品从“杂志式阅读”改成“可核对的审计工作台”。视觉服务于一件事：每个数字都能顺着证据往回查。

**色彩**

| 角色 | 值 | 用途 |
| --- | --- | --- |
| 纸面 | `#F4F6F2` | 页面底色，冷灰绿，不是暖米色 |
| 单据 | `#FFFFFF` | 结果纸张、表格 |
| 墨 | `#101815` | 标题与正文 |
| 次要 | `#5E6B66` | 说明、标签 |
| 线 | `#D3DAD5` | 分隔线、表格线 |
| 标记黄 | `#E8D44D` | 唯一强调色：证据引用、当前分组、计划选中 |
| 语义色 | 绿 `#1F6B4A` / 琥珀 `#9A6400` / 红 `#A33A2A` | 只表示状态，不装饰 |

**字体**

- 界面与标题：`"Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei"`，标题 650–700，正文 400。
- 数字、哈希、SQL、字段名：`"IBM Plex Mono", "Consolas", monospace`，`font-variant-numeric: tabular-nums`。
- 不再使用衬线标题；标题的辨识度来自字号、字重和留白，而不是字体本身。

**布局（≥1280）**

```
┌──────────────────────────────────────────────────────────────┐
│ 数鉴  分析工作台  数据处理  探索  SQL        数据集 · 731 行  │ 56px
├───────────────┬──────────────────────────────┬───────────────┤
│ 任务 / 计划    │  当前结果（一张连续单据）      │ 证据 / AI      │
│ 260px         │  minmax(0,1fr)                │ 340px          │
│               │                               │                │
│ 01 月度趋势   │  标题                          │ 证据链          │
│ 02 年度对比   │  一句结论                      │ fact → SQL     │
│ 03 天数核查   │  图表                          │ → 原始记录      │
│               │  五段解读（账本式行）          │                │
│ [AI 规划]     │  明细表（折叠）                │ AI 对话         │
└───────────────┴──────────────────────────────┴───────────────┘
```

- 任务切换放在左轨，一次只渲染一个结果，解决纵向堆叠。
- AI 助手成为右轨，不再是浮窗；窄屏折叠为底部抽屉。
- 顶部只保留一层主导航；工作台分区并入左轨或内容标题，不再有第二排标签。
- 数据集元信息压成一条细带：文件名、行数、时间范围、快照哈希前缀。

**结果页的五段解读**

改成“账本行”，左侧固定标签，右侧一句话；证据编号用标记黄底，点击后右侧证据轨定位到对应 fact 与原始记录。避免每段都做卡片。

**体检页**

一屏三段：
1. 这份数据是什么：一行判断 + 四个关键数字 + 三个可执行问题（行式列表，不是三张卡）。
2. 可信度：完整度、重复候选、字段角色、风险提示。
3. 更多：原始预览、字段速览、手动计算，默认折叠。

**动效**

只在结果出现时做一次 180ms 的纸面展开 + 图表绘制；不做逐卡片淡入和全局 hover 位移。

### 方案 B：仪器台 Instrument

深色控制台、等宽数字、荧光绿强调。更适合演示视频和“硬核分析”气质，但长时间阅读疲劳、打印/报告不一致，且深色 + 荧光绿本身也是常见生成式套路。

### 方案 C：保留笔记本，只做结构优化

保留现有配色，只修 AI 浮窗、结果堆叠和字号。风险最低，但无法解决“没有亮点”的根本问题。

## 3. 实施顺序

1. **设计令牌与外壳**：统一颜色、字体、圆角、间距；重做 header、左右轨、响应式断点。只动样式和布局包装，不动任何计算与证据逻辑。
2. **体检页重组**：首屏三问 + 关键数字，质量与原始数据后置。
3. **结果页重组**：左轨任务、单结果渲染、五段账本、证据右轨；修复浮层遮挡和“跳到分析内容”错位。
4. **回归**：六套浏览器验收 + 1440/1024/768/375 截图；确认 AI 证据跳转、报告导出、SQL 控制台、探索页不受影响。
5. **文档与交付**：更新 README 截图、演示手册、技术文档；重新备份。

## 4. 不动的部分

- 所有 SQL、聚合、证据绑定、模型校验逻辑。
- 测试依赖的语义选择器和可访问名称；需要改结构时同时改测试并说明原因。
- 模型未配置时的能力边界提示。
- 报告导出内容与口径说明。

## 5. 验收标准

- 1440 宽度首屏能看到：数据集摘要、三个可执行问题、主操作。
- 结果页在 1440 下无需滚动即可看到标题、结论、图表；五段解读在一屏内可扫读。
- AI 助手打开后不遮挡任何主内容（内容区自动让位）。
- 375 宽度无横向滚动，触控目标 ≥ 44px。
- 字号：正文 ≥ 14px，辅助文字 ≥ 12px，对比度 ≥ 4.5:1。
- 浏览器验收全部通过，截图与文档同步。

已完成：

- 结果页：任务改为左侧 212px 黏性导航，正文一次只显示一个任务；任务卡变成单张审计纸，五段解读改为“标签 + 内容”的账本行。
- 助手：≥1201px 时改为 360px 右侧停靠栏，内容区让位，不再覆盖图表；≤1200px 仍使用原浮层。

- 体检页：判断与分数做成审计抬头，三个可执行问题改为行式账本；风险和数据预览后置，手机上问题卡纵向排列。
- 结果操作：AI 结果卡里的“检查 SQL 与来源”会切到“证据与报告”；导出证据报告时会读取当前结果图表 SVG（包括 AI 任务卡），不再导出空图。
