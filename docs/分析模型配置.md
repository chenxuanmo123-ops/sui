# 分析模型配置

面向部署者与使用者。说明数鉴 Agent 里“分析模型”是什么、需要准备什么、三种配置方式和验证办法。

## 1. “分析模型”指什么

指一个 **OpenAI 兼容的 Chat Completions 服务**（DeepSeek、OpenAI、智谱、通义、Kimi、本地 Ollama 等）。它只负责：

- 读懂字段摘要，生成待确认的分析计划；
- 解释已经由 SQLite 真实算出的结果；
- 在结果不完整时指出还需要什么证据。

它**不参与计算**，也不会把模型回答当作数据。图表、统计、来源记录全部来自浏览器内的真实查询。

> `.env.example` 里的 `LLM_PROVIDER_NAME=我的分析模型` 只是“连接名称”的占位文字，不是可用的模型。真正要填的是接口地址、模型 ID 和 API Key 三项。

## 2. 需要准备的三样东西

| 配置项 | 说明 | DeepSeek 示例 |
| --- | --- | --- |
| 接口地址 `LLM_BASE_URL` | 到 `/v1` 为止，程序自动追加 `/chat/completions` | `https://api.deepseek.com/v1` |
| 模型 ID `LLM_MODEL` | 服务商文档里的模型名，不是产品名 | `deepseek-chat` |
| API Key `LLM_API_KEY` | 服务商控制台创建，形如 `sk-...` | 你自己创建，**不要发给任何人** |

其他常见服务商（以各自文档为准）：

| 服务商 | 接口地址 | 模型 ID 示例 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | 账号里可用的模型名 |
| 智谱开放平台 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` 等 |
| 阿里云百炼（通义） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` 等 |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` 等 |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | 本地已拉取的模型名 |

## 3. 方式一：本机 `.env`（重启后一直生效）

1. 在项目根目录确认存在 `.env`；没有就从模板复制：
   ```bash
   cp .env.example .env
   ```
2. 编辑 `.env`，只改这几行：
   ```env
   LLM_BASE_URL=https://api.deepseek.com/v1
   LLM_API_KEY=sk-你的密钥
   LLM_MODEL=deepseek-chat
   LLM_PROVIDER_NAME=DeepSeek
   LLM_JSON_MODE=true
   ```
3. 重启开发服务（`.env` 只在启动时读取，改完必须重启）：
   ```bash
   npm run dev
   ```
4. 终端应出现 `AI 模型已配置：DeepSeek`，页面欢迎页底部显示“默认分析模型已就绪”。

注意：

- 不要加 `VITE_` 前缀。带该前缀的变量会被打包进浏览器代码。
- `.env` 已在 `.gitignore` 中，**不要**提交、截图或随作品打包。
- `LLM_JSON_MODE=false` 仅用于供应商不支持 `response_format` 的情况；关闭后程序仍会在本地校验 JSON。

### 多个供应商

`LLM_PROVIDERS_JSON` 优先于单模型配置，页面可切换：

```env
LLM_PROVIDERS_JSON=[{"id":"deepseek","name":"DeepSeek","baseURL":"https://api.deepseek.com/v1","apiKey":"sk-...","model":"deepseek-chat","jsonMode":true}]
```

最多 8 个；`id` 只能用字母、数字、下划线、短横线。

## 4. 方式二：网页里填写（不碰文件）

1. 打开页面，点右下/欢迎页的“连接模型”或“管理模型”。
2. 新建连接，填四项：连接名称、接口地址、模型 ID、API Key。
3. 点“测试连接”；通过后勾选“设为内置 AI 的默认分析模型”，保存。

连接保存在本机 `.local/model-connections.json`（密钥明文，仅本机；该目录已排除 Git）。状态接口**不会**把密钥回传浏览器。已保存的密钥不显示原文，只能重新填写覆盖。

公网部署时，网页端保存/删除连接会返回 403，这是预期行为：访客不能改服务端凭据。若允许访客自带密钥，部署者需把 `LLM_ALLOWED_HOSTS` 设为精确的 HTTPS 域名（逗号分隔，无协议和路径）。

## 5. 方式三：Cloudflare Pages 环境变量（公网）

1. Cloudflare 控制台 → Pages 项目 → Settings → Environment variables。
2. 添加与 `.env` 同名的变量（Production 与 Preview 都建议加）：
   `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`LLM_PROVIDER_NAME`、`LLM_JSON_MODE`。
3. 保存后重新部署（Variables 变更不会自动重建）。
4. 把密钥类型设为 Secret/加密，不要写进仓库或构建日志。

Pages Functions 没有本机文件系统，因此 `.local` 那套“网页保存连接”在公网不可用。

## 6. 验证配置

**终端（本机）**：

```bash
curl -s http://127.0.0.1:5173/api/ai/status
```

返回 `{"configured":true,...}` 说明服务端已读到完整配置；返回 `configured:false` 表示地址、密钥、模型 ID 至少缺一项，或改完没重启。

**页面**：

1. 导入任意 CSV。
2. 点“连接 AI”，选择默认模型。
3. 打开分析助手，问一个与字段有关的问题，确认能生成“分析计划”而不是报错。
4. 执行计划后检查结果是否来自真实计算，再让模型解读。

**公网**：

```bash
npm run verify:public
```

会检查静态资源、状态接口、密钥是否泄露、未知 API 是否返回 JSON 404。

## 7. 没有密钥怎么办

删掉 `.env`（或把 `LLM_API_KEY` 留空），然后重启。未填完整的供应商会被自动忽略，程序不会用假密钥“装成可用”。

此时仍可完整使用：

- CSV / XLSX / XLS / PDF 导入与数据核对；
- 手动分析、探索图表、对比诊断、质量诊断；
- 只读 SQL 控制台与关联表；
- 导出结果 CSV、SVG、HTML 证据报告、可复现 SQL 包。

只有“AI 规划 / 解读 / 初步定位”会提示未连接模型。

## 8. 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `configured:false` | 三项没填全，或改 `.env` 后没重启 | 补全并重启 |
| 401 / 403 | Key 错误、过期或无权访问该模型 | 到服务商控制台重建 Key |
| 404 | 接口地址少了或多了路径 | 地址只写到 `/v1`，不要带 `/chat/completions` |
| 400 `response_format` | 供应商不支持 JSON 模式 | 设 `LLM_JSON_MODE=false` |
| 超时 | 网络或模型服务慢 | 换网络重试；不要通过放宽校验掩盖失败 |
| 页面仍显示未连接 | 用了 `VITE_` 前缀，或只改了 `.env` 没重启 | 去掉前缀并重启 |

## 9. 安全约定

- API Key 只存在 `.env` 或 `.local/`，二者都不进 Git；不写进报告、截图、日志、浏览器存储。
- 密钥只由服务端读取，接口只返回“是否配置”和供应商名称。
- 不把模型输出当计算结果；数字必须有 SQL 证据。
- 不为了通过校验而放宽字段、聚合、范围或证据检查。
