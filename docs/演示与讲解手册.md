# 演示与讲解手册

面向参赛讲解、答辩和演示视频。目标：用真实数据在 3 / 5 / 8 分钟内讲清“AI 规划、SQL 真算、证据可回查”，并明确哪些能力还没有。

## 1. 演示前检查清单

| 项目 | 要求 | 检查方式 |
| --- | --- | --- |
| 公网地址 | https://sui-ae9.pages.dev 可打开 | 无痕窗口打开一次，确认不是缓存页 |
| 模型 | 公网已配置服务端模型（`aiConfigured=true`）；本地演示可自填 Key | 公网打开“AI 助手”直接提问；本地“连接模型” → 测试连接 |
| 数据文件 | 默认用内置 UCI 骑行日示例（无需下载）；另备 OWID、UCI 购物意向 CSV；Airbnb 大文件可选 | 内置示例点一次即载入；自带文件能本地打开，大小 < 30 MB |
| 离线兜底 | 模型不可用时仍能讲手动分析 | 断开模型，导入文件 → 探索分析 |
| 证据 | 演示前不要清空浏览器站点数据 | 刷新后工作区能恢复 |
| 合规 | 仓库、截图、视频中无 API Key、无 `.env` | 全仓搜索 `sk-`、`.local` |

模型不可用不影响核心演示：导入、质量诊断、探索图表、SQL 控制台、可复现包都不依赖模型。不要为了“看起来能用”临时填假 Key。

- D0 是 2011–2012 年一个城市的 731 个自然日，不是全国或全球样本；`temp` / `atemp` / `hum` / `windspeed` 在该文件中是 0–1 的归一化值，单位需要自己确认，不能直接读成摄氏度。

## 3. 三分钟速讲（展台/初审）

**0:00–0:30 问题**
“做数据分析最怕两件事：AI 编数字，和算完不知道数字从哪来。数鉴把这两件事分开：AI 只负责理解和规划，所有数字由浏览器里的 SQLite 真实计算，并且能逐条回查到原始记录。”

**0:30–1:30 数据体检与答案**
1. 点“载入随应用附带的真实示例（UCI 骑行日数据）”，不选任何字段：“系统已经算出 731 行、16 个字段、100% 完整度，时间范围是 2011-01-01 到 2012-12-31。”
2. 在“这份数据现在能回答”里点第 02 题“weathersit 之间，cnt 差多少 → 直接算给我看”。
3. 指结果页第一屏：“三个天气类型的租车总次数分别是 2,257,952、996,858、37,869 次，合计 3,292,679，占比 68.6% / 30.3% / 1.2%；第 1 类最高、第 3 类最低。下面才写可能含义、可以拿来做什么、还需要什么、不能得出什么。”
4. 下滑到图表和来源：“3 个分组，来源记录 463 / 247 / 21 条，SQL 与参数都在页面里。”

**1:30–2:20 统计与证据**
1. 回到起点，点第 03 题“cnt 与 temp 是否同步变化 → 查看关系图”。
2. “Pearson r=0.6275，基于全部 731 对有效值；图只画前 100 个点，系数不跟着缩水。卡片同时说明：这只是线性同步，不是因果。”
3. 点任一散点 → 查看来源记录 → 展示原始日期行。
4. 导出 HTML 证据报告：“报告里带 SQL、参数、来源和相关说明，换一台机器可以照着重算。”

**2:20–3:00 边界**
“这是 2011–2012 年一个城市的 731 天，不能代表全国；天气和租车量同步变化，也不能说明天气导致租车。产品把限制直接写在结果旁边，而不是藏在脚注里。”

## 4. 五分钟演示（省赛视频主干）

在三分种基础上增加“质量诊断 + AI 规划”，顺序如下：

| 时间 | 操作 | 讲解要点 |
| --- | --- | --- |
| 0:00–0:30 | 打开公网首页 | 说明文件在浏览器读取，密钥只在服务端/页面内存 |
| 0:30–1:10 | 上传 D2（UCI 12,330 行） | 先看体检：完整度、字段角色、IQR 候选 961、重复候选 125；“候选不是错误，不自动删改” |
| 1:10–2:00 | 点“各访客类型的购买比例”建议问题 | 结果先给五段解读：观察、可能含义、用途、还缺什么、不能得出什么；比例写明 `Revenue=TRUE` 的分子与分母 |
| 2:00–2:30 | 展开图表与来源 | “解读由本地规则从结果生成，不是模型编的；换口径会重新计算并重新生成” |
| 2:30–3:00 | 探索分析：按 `Month` 分组，`Revenue` 计数 | `Revenue` 是购买结果，不是营收；`Month` 没有年份，不能写成时间趋势 |
| 3:00–3:25 | 散点图：`PageValues` × `ProductRelated_Duration`，展示上限 20 | “图只画 20 条，但 r 用全部 12,330 对，卡片会说明范围不同” |
| 3:25–3:55 | 连接模型，问“各月购买转化率是多少，需要补什么证据” | 计划必须写明分子 `Revenue=TRUE`、分母取值集合、排除未知；这是比例，不是营收；AI 的“可能含义/用途”必须带事实编号 |
| 3:55–4:20 | 确认执行 | 逐任务真实 SQL；解读失败也不影响计算；失败任务可修正重算；进度可停止 |
| 4:20–4:45 | 打开证据面板 / 导出可复现 SQL 包 | ZIP 内 `run_analysis.py` 本地复跑输出 PASS |
| 4:45–5:00 | 收尾 | “AI 不碰数字，数字必须能复现；没有模型也能完成分析。” |

## 5. 八分钟完整演示（含失败恢复与 RAG）

在五分钟基础上增加两段“竞争点”：

**5.1 计划被拒绝 / 失败修复（约 1.5 分钟）**

1. 提一个数据回答不了的问题，例如“预测下一年的租车量”。
2. 指出计划里不应出现预测任务；说明系统只支持描述性计算，模型必须把限制写进 questions/limitations。
3. 若任务执行失败，展示失败原因和“仅重算失败任务”，已完成结果保留。

**5.2 本地资料检索 + 引用校验（约 1.5 分钟）**

1. 上传一份两页 PDF 或 TXT（可用 `tests/fixtures/reference-note.pdf`）。
2. “检索在浏览器本地完成，只把命中的摘录发给模型，不发整份文件。”
3. 解读出现引用编号；说明服务端会拒绝未提供的编号，资料不能当计算证据。

**5.3 收尾（30 秒）**

“我们没有把 AI 包装成会算数的黑盒。它负责理解、规划和解释；计算、来源和复现由可验证的工程保证。”

## 6. 评分点对应

| 评分维度 | 演示中对应 | 讲解口径 |
| --- | --- | --- |
| AI 技术深度 35% | 计划 → 校验 → 真实执行 → 失败修复 → 证据复核；本地 BM25 检索 + 引用校验 | 强调“AI 输出受 schema 与证据约束”，不夸大模型准确率 |
| 创新性 25% | AI 计划可审、数字不交给模型、结果可回查、报告可复现；先给数据含义与用途，再给图表 | 与传统“聊天式分析”、纯 BI 和只换皮大屏的差异 |
| 前端工程 10% | React 19 + TypeScript、Web Worker、SVG 图表、懒加载 | 计算不阻塞主线程；大文件仍可交互 |
| 实用性 10% | 真实 CSV/XLSX/PDF、真实公开数据、HTML 报告、SQL 包 | 面向真实分析流程，不是演示玩具 |
| 用户体验 10% | 导入即体检、建议问题一键执行、答案先于图表、进度与取消、错误边界、范围提示 | 诚实说明流式输出尚未实现 |
| 社会价值 10% | 降低分析门槛、数据不出浏览器、结论带限制 | 适合教学、审计、公共数据核查 |

## 7. 答辩高频问题

**问：AI 会不会算错？**
答：AI 不参与计算。它输出的是受 schema 约束的计划，数字由 SQLite 执行 SQL 得到；结果卡片、报告和复现包都绑定同一条 SQL 与来源记录。

**问：相关系数高就能说明因果吗？**
答：不能。我们只给 Pearson r 和有效配对数，并明确它不是因果、预测或显著性检验。共同趋势、极端值、非线性都会让 r 失真。

**问：数据会不会上传到模型？**
答：原文件在浏览器处理。只有字段摘要、少量样本、类别字典，以及用户主动上传资料的命中摘录会发给模型。参考资料不进入证据链。

**问：没有 API Key 还能用吗？**
答：能。导入、质量诊断、数据体检、建议问题、结果解读、探索、SQL 控制台、报告和复现包都不依赖模型；只有 AI 规划与 AI 补充解读需要连接。

**问：完全不懂数据的人怎么用？**
答：导入后不需要先选字段。系统先做本地体检，给出“能回答什么”的问题；点一下就用真实 SQL 执行，结果页再用五段话解释观察、可能含义、用途、还缺什么和不能得出什么。懂行的用户可以随时展开口径、SQL 与来源核对。

**问：结果里的“可能意味着什么”是 AI 编的吗？**
答：默认那五段是确定性规则从真实结果生成的，不调用模型，所以没有模型也能看到。连接模型后只增加“可能含义/可能用途”的补充，而且每条必须引用事实编号、不能写数字、不能用因果措辞；模型失败时原有解读和计算都保留。

**问：和 ChatGPT 直接分析 CSV 有什么区别？**
答：ChatGPT 给你一段可能无法核对的文字；数鉴给你可执行的 SQL、逐条来源、可复现包和明确的统计边界。模型失败时，真实计算结果仍然保留。

**问：为什么不做预测/回归/机器学习？**
答：当前定位是可核查的描述性分析。预测需要额外假设、误差评估和样本外验证，不能在演示里用一条拟合线冒充。

**问：公开数据会不会哪天变了，导致结果对不上？**
答：不会。OWID 公开数据已固定到上游提交 `e7897ae`，同一按钮始终读取同一份文件；来源页显示固定提交，报告绑定快照指纹。换成自己的文件时，指纹随原文件记录。

**问：中文 Excel 导出的 CSV 能直接导入吗？**
答：能。系统自动识别 UTF-8、UTF-16 和 GBK/GB18030，并识别逗号、分号、制表符分隔；识别到非 UTF-8 或非逗号时会在状态栏提示，并仍保留原始值。

## 8. 讲解禁区

- 不说“AI 计算出了这个数”——数字来自 SQL。
- 不说“相关系数证明了两者有关”——只能说线性同步。
- 不把 8 年、12,330 条访问或阿姆斯特丹房源说成总体。
- 不把“连接成功”说成“分析准确”；不把自动测试通过说成模型评测通过。
- 不展示任何真实 API Key；截图前检查浏览器与终端。
- 不宣称已实现 MCP、向量 RAG、流式输出或预测能力。
- 不说“系统自动理解了业务含义”——字段角色和可能含义都只是候选，必须由用户核对口径。

## 9. 演示故障预案

| 现象 | 处理 |
| --- | --- |
| 公网页打不开 | 切本地 `npm run dev`；或提前录屏 |
| 模型 401/超时 | 直接讲手动分析；说明密钥与网络边界，不现场调试密钥 |
| 大文件导入慢 | 改用 D1/D2；D3 只作为“已在本机验证 26 MB”的证据展示 |
| 图表引擎未加载 | 等待 1–2 秒或刷新；不要连续点击执行 |
| 结果与预期不符 | 展示 SQL 与筛选条件，先核对口径，不修改数字迎合结论 |
