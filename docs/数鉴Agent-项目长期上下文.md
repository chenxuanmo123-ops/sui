## 1. 先读这一节：当前有效结论

### 1.1 产品方向已经确定

产品名称：**数鉴 Agent**。

固定赛道：**AI 数据分析与可视化**。

产品不是通用聊天机器人，也不是只展示静态图表的 BI 页面。它的核心任务是：

> 用户上传真实数据，用中文提出数据问题；系统先理解数据和分析目标，再由 AI 生成可执行计划，使用浏览器内的真实计算引擎完成分析，生成合适的图表，并让每条结论都能回到计算结果、来源记录和数据快照。

典型问题：

> 3 月营收为什么下降？重点看渠道和时段。

产品要让用户看到完整过程：

1. 导入真实 CSV、XLSX、XLS 或 PDF 数据；
2. 检查字段、类型、缺失、重复、来源和解析质量；
3. AI 初步判断数据适合分析什么，识别字段角色和风险；
4. 用户可选地补充业务背景、行粒度、字段定义和单位；
5. AI 生成分析计划，计划中可同时包含安全可执行任务和需要确认的问题；
6. 用户确认计划后执行真实计算；
7. 根据分析目标生成趋势、分组、对比、散点、热力或表格结果；
8. AI 只解释真实计算事实，不直接编造数字；
9. 用户可以追问，形成新的分析分支；
10. 导出带 SQL、参数、结果、来源和数据快照的单文件 HTML 报告。

### 1.2 不可回退的产品原则

- **不使用虚构业务数据**：产品体验不能内置假咖啡店订单、假平台偏好或假财报来冒充真实能力。
- **不使用模拟 AI 回答冒充真实模型**：测试替身只能留在自动化测试中，不能进入产品体验或演示叙事。
- **只分析用户上传的数据或有明确出处的公开数据**：公开示例必须能提供来源、下载地址、版本或哈希等证据。
- **AI 不是数字来源**：数字必须来自真实计算结果；模型只能理解问题、规划任务和解释已验证事实。
- **不把描述性统计说成因果结论**：没有实验设计、识别策略或外部证据时，使用“观察到”“相关”“样本内变化”等表述。
- **不把样本说成总体**：平台使用记录、问卷或公开子集只能代表上传样本；不能把使用次数直接说成全网偏爱。
- **不因有待确认问题而全部阻塞**：只要存在安全的描述性任务，就允许用户先查看结果，同时提示哪些口径还需要确认。
- **不把连接成功说成分析准确**：模型能返回 HTTP 200 只说明连接可用，不说明规划质量或结论正确。
- **不把 MCP 当当前主线**：MCP 已明确暂时搁置。当前产品重点是数据处理、AI 分析工作流、真实计算、可视化和证据链。
- **不让 AI 配置窗口盖过数据产品本身**：多模型连接是工程能力，核心竞争力仍是数据分析流程。
- **不为了评分表强行堆多模态、RAG 或 MCP**：每个能力只有在真实解决数据分析问题并可验证时才加入。
- **不宣称任意文件、任意业务、任意问题都能自动准确分析**：当前能力有明确格式、规模、粒度、PDF 和模型兼容边界。

### 1.3 比赛判断基准

这是 AI Web 网页开发挑战赛第一批参赛作品。已掌握的评审权重：

| 维度 | 权重 | 对数鉴的实际要求 |
| --- | ---: | --- |
| AI 技术深度 | 35% | 真实模型集成、稳定结构化输出、Agent/工作流、可控性、工具或函数调用；不能只接一个聊天 API |
| 创新性 | 25% | 选题、分析流程和交互方式有明确差异；创新要落在可操作的产品体验上 |
| 前端工程质量 | 10% | React/TypeScript 结构、组件化、状态管理、性能和错误边界 |
| 实用性 | 10% | 面向真实数据和真实决策问题，能完成从导入到结论的闭环 |
| 用户体验 | 10% | 导入清晰、计划可审查、过程可见、图表易读、失败诚实、AI 可追问 |
| 社会价值与商业潜力 | 10% | 降低数据分析门槛，帮助用户理解数据限制，具备面向研究、运营、教育和小团队的产品化空间 |

详细评分项包括大模型集成质量、Agent/工作流设计、RAG、多模态、AI 安全与可控性、MCP/Function Calling。当前策略是：

- Agent 必须保留；
- 多模型 API 兼容是工程亮点，但不能替代数据分析核心；
- MCP 暂时搁置，不成为参赛作品的必要依赖；
- 多模态只在扫描 PDF、复杂表格或图像型数据确实需要时使用；
- RAG 可用于数据字典、指标口径和来源说明，当前不是强行堆砌的 P0；
- 前端要让评委看见真实数据、AI 规划、计算过程、图表变化和证据回查。

## 2. 产品边界与用户体验

### 2.1 目标用户

- 能拿到业务或公开数据，但不熟练写 SQL 的业务分析者；
- 研究人员、学生、教师和小团队；
- 需要快速确认“这份数据能回答什么、口径是什么、结论是否有证据”的用户。

P0 是单用户、单次分析工作台。暂不做多用户、权限系统、外部业务系统连接和复杂实时大屏。

### 2.2 主要用户旅程

1. 用户打开网页，看到“导入一份真实文件”；
2. 上传 CSV、XLSX、XLS 或 PDF，或主动加载有来源的公开数据；
3. 系统展示字段、类型、缺失、样本和解析警告；Excel 选择工作表、表头和数据范围，PDF 选择页并对照原页；
4. 系统可以使用默认模型做一次“初步定位”，只把字段、质量摘要和最少必要上下文发送给模型；
5. 用户打开窗口化 AI 助手，输入问题；业务背景、每行代表什么、字段定义和单位都是可选补充，不应成为不必要的硬门槛；
6. AI 返回数据场景候选、行粒度、字段角色、假设、待确认问题、限制和任务计划；
7. 用户审阅计划。存在问题时，如果同时存在安全任务，可以先确认并执行；只有任务为空时才阻止执行；
8. 浏览器 Worker 内的 SQLite 计算真实执行；
9. 图表、表格、事件日志和证据逐步显示；
10. 用户点击结论、图表点或来源按钮，查看 SQL、参数、结果、来源行和数据快照；
11. 用户追问或改变筛选条件，系统新建分析分支并重新计算；
12. 用户导出单文件 HTML 报告。

### 2.3 “AI 初步定位”与“AI 分析助手”的关系

- **初步定位**：上传数据后可触发。目标是帮助用户知道数据适合做什么，不直接执行业务分析。默认只发送字段和质量摘要，不发送原始样本。
- **窗口助手**：用户按需打开，输入目标并审阅计划。它可记住会话输入和计划，支持收起、展开、恢复和配置模型。
- **分析执行**：先由模型生成结构化计划，再由本地校验器检查字段、聚合、条件和数据快照，最后交给真实计算引擎。
- **结果解读**：把计算事实交给模型解释；模型不得替换事实，也不得自行生成统计数字。

## 3. 数据输入和真实性边界

### 3.1 已支持的格式

当前实现支持：

- UTF-8 CSV；
- XLSX；
- XLS；
- 文字型 PDF；
- PDF 页面预览和原页核对；
- 对当前 PDF 页使用真实视觉模型做候选表格识别，需用户明确授权。

支持不是“任意文件自动准确还原”。当前限制必须对用户和评委说清楚：

- Excel 一次选择一张工作表；
- PDF 一次选择一页中的一张表；
- 扫描 PDF 没有文字层时需要视觉识别或人工核对；
- 复杂表头、旋转文字、跨页合表、多表混排和特殊字体可能需要人工调整；
- Excel 公式使用文件已有缓存，不在浏览器重算；没有缓存时保留空值并提示；
- 不执行宏、外部链接和嵌入图片；
- PDF 提取行是版面读取行或模型转录行，不等于可靠的 PDF 物理行号。

### 3.2 导入质量检查

当前导入链路会记录或检查：

- 文件名、格式、原始 SHA-256；
- 工作表或 PDF 页码；
- 表头行和数据范围；
- 字段类型候选；
- 空值、非空数量和部分去重信息；
- 解析方法和警告；
- 来源记录；
- 确认后的数据快照指纹。

必须保留的语义边界：

- 零填充编号保留前导零；
- 日期尽量保留原始时刻；
- 百分比、货币符号、括号、逗号等不能被默默清理成另一种语义；
- 合并单元格不自动向下填充；
- 错误单元格不应被当作正常数字；
- 数据单元格里的文字只是数据，不能改变系统提示词或执行指令；
- 不同工作表、页面或修订不能共用旧分析指纹。

### 3.3 公开数据

真实公开数据测试使用 Our World in Data energy-data 的中国 2015—2022 子集：

- 上游来源、固定 commit、筛选条件、文件哈希和 provenance 已保存；
- 文件位于 `tests/fixtures/owid-China-2015-2022.csv`；
- 不会自动载入产品，也不作为虚构演示数据；
- 只用于真实数据导入、计算和回归测试。

未来若把公开数据放进比赛演示，必须展示来源和筛选范围，不能让观众误以为它是内置业务假数据。

## 4. AI 和 Agent 方案

### 4.1 当前工作流

当前不是开放式聊天，而是受约束的工作流：

```text
数据检查
  → 初步定位
  → 理解用户问题
  → 生成结构化分析计划
  → Zod/契约式校验
  → 浏览器真实计算
  → 读取计算事实
  → AI 解释结果
  → 证据引用校验
  → 追问或新分支
```

历史上曾把角色拆成 Planner、Executor、Analyst、Critic；当前代码将它们收敛为可审计的几个步骤，不能为了叙事再虚构四个独立模型。答辩时可以说“角色职责分离”，但要以实际代码说明每个职责如何落地。

### 4.2 AI 能做什么

模型负责：

- 识别数据场景候选；
- 判断可能的行粒度；
- 给字段分配时间、维度、指标等角色；
- 根据用户问题选择相关字段；
- 发现单位、粒度、重复、退款、日期、范围、样本偏差等风险；
- 生成结构化任务；
- 在不影响安全描述性统计时并列提出待确认问题；
- 根据真实计算事实形成带限制条件的解释；
- 在用户追问后生成新的分析分支。

模型不能负责：

- 直接编造数字；
- 未执行 SQL 就声称完成分析；
- 把字段名当作已确认业务语义；
- 把一个样本推断成全网总体；
- 把相关性或期间变化写成因果证明；
- 通过数据单元格中的指令改变系统行为；
- 越过前端和服务端的字段、聚合、范围和快照校验。

### 4.3 当前计划规则

结构化计划包含：

- `goal`：用户目标；
- `scene`：数据场景候选；
- `grain`：每行代表什么；
- `fieldRoles`：字段角色与含义；
- `assumptions`：分析假设；
- `questions`：需要确认的问题；
- `hypotheses`：可选的候选假设，最多四个，每个通过 `testTaskIds` 绑定已有任务；假设 ID 必须唯一、不得与任务 ID 冲突，验证任务不可重复，陈述不能为空；
- `tasks`：可执行任务；
- `limitations`：限制说明。

当前任务最多六个。支持的基础聚合包括：

- `sum`：求和；
- `average`：均值；
- `count`：分组记录数；
- `distinct`：指标非空原值去重数；
- `min`：最小值；
- `max`：最大值。

支持单列分组、精确字段筛选、字符串或数值范围条件，以及标准日期按月或按年分桶。`count` 不读取指标值，因此分组字段和指标字段可以相同；其他聚合要求二者不同且指标可安全解释为数值。

### 4.4 最近修复的关键行为

此前出现过错误提示：

> 待澄清计划不能包含可执行任务。

这已经按正确产品逻辑修复：

- `questions` 和 `tasks` 可以同时存在；
- 有可执行任务时，前端允许用户确认并查看安全结果；
- 有任务和问题时，界面提示“先查看可执行结果，同时确认口径”；
- 只有问题没有任务时，要求补充信息后重新规划；
- 没有任务也没有问题时，提示计划不完整；
- 空目标、空背景时使用安全的默认描述性探索目标，不把业务背景设置成不必要的必填项。

例如用户只上传数据、不填写背景，系统可以先做：

- 按年份统计记录数；
- 查看数值字段的年度变化；
- 检查缺失和去重情况；
- 标记单位和粒度待确认。

这让系统具备“先给安全事实，再邀请用户补充口径”的体验。

### 4.4.1 候选假设与任务级执行（2026-10-17）

- 已实现候选假设契约和界面，标明“待真实结果验证”；尚未实现程序化支持/削弱/不确定裁决，也没有自动重规划闭环。
- 执行前统一检查任务 ID，任务逐个独立执行；失败不丢失其余成功结果，全部失败也返回结构化错误并保留修正入口（2026-10-19 更新）。
- `executePlan` 返回 `{ results, failures }`；成功结果的 `Analysis.ai.taskId` 绑定原任务。
- `evidenceFacts` 只按唯一 `taskId` 绑定事实，拒绝缺失、未知、重复绑定或空结果，不再按数组位置兜底。
- 首任务失败时，主图表采用实际成功任务的图表设置；失败任务单独显示，不显示为全部完成。
- 计划确认前增加本地等值筛选检查：若某个值或条件组合无匹配记录，明确提示；不自动把 `revenues` 模糊改成 `revenue`，不额外发送原始值。该检查不覆盖范围、时间分桶和数值有效性，最终仍由 SQL 校验。

### 4.4.2 失败反馈、确认后重算和类别授权（2026-10-19）

- 新增独立类别字典授权，默认关闭，不等同于原始样本授权。只发送文本列的完整非空唯一值，最多12列、每列16个值、每值120字、总字符预算8000；超限整列省略，不提供频次，不把截断字典标为完整。
- 服务端白名单清洗上下文，未授权的样本和类别值、未知属性及原始行不会透传。初步定位接口不使用类别字典授权。
- 新增 `/api/ai/repair-plan`：只提交失败任务、真实错误及必要上下文；必须保留失败任务 ID，不允许新增任务或改写成功任务。
- 展示修正前后口径，取消旧确认状态；人工重新确认后只执行失败任务，成功任务结果不重算。快照、mapping、唯一 taskId 在合并时继续校验。
- 每次规划前端最多请求两轮修正，服务端校验 attempt 为1或2；目前不是有状态的服务端全局次数限额。
- 已有 API、真实 SQLite 与浏览器回归；修正和 review 的本轮浏览器响应为明确测试替身，尚未完成真实模型修正→执行→review 的恢复评测。

### 4.5 模型连接能力

当前支持 OpenAI 兼容 Chat Completions 的多模型连接：

- API Base URL；
- API Key；
- 模型 ID；
- JSON 输出模式开关；
- 获取模型列表；
- 真实连接测试；
- 默认模型；
- 连接新增、编辑、删除和切换；
- DeepSeek 官方连接快捷入口；
- 窗口化 AI 助手可打开、收起、展开和恢复。

这部分借鉴 CC Switch 的是“多模型配置和切换交互”，不是把产品做成 CC Switch，也不是把配置页当成核心卖点。

本地服务模式下，连接可以保存到 `.local/model-connections.json`；该目录已忽略，不得读出或提交真实密钥。公网模式不能把服务端默认密钥发送到浏览器；访客自填密钥也不应被服务端持久化。

### 4.7 当前真实模型评测记录（2026-10-17）

## 5. 真实计算、图表和证据链

### 5.1 计算引擎

当前计算链路：

- `sql.js`；
- Web Worker；
- 参数化只读 SQL；
- `PRAGMA query_only = ON`；
- 单次查询 30 秒超时后终止 Worker；
- 计算结果携带 SQL、参数、数据集哈希和任务规格；
- 结果可以映射回来源行；
- 数据快照变化后旧计划失效。

当前不是开放任意 SQL 编辑器。模型生成的是受约束任务，应用把任务编译为安全 SQL；不能为了迁就模型而放宽为任意 SQL、写操作或未校验字段。

### 5.2 图表能力

当前探索分析支持：

- 折线图；
- 柱状图；
- 散点图；
- 热力图；
- 结果表；
- 期间对比；
- 排序、筛选和展示上限；
- Top N 与前 N 项的明确标注；
- 图表导出 SVG；
- 单文件 HTML 报告。

需要区分：AI 自动计划当前主要生成六种聚合的折线/柱状任务；散点、热力和期间分解在探索/对比页面使用，尚未完全纳入统一的自动 Agent 工具循环。

### 5.3 证据链

每条可展示结论都要尽量绑定：

- 计算 SQL；
- SQL 参数；
- 任务和筛选条件；
- 结果行；
- 原始数据行或来源记录；
- 文件、工作表或 PDF 页；
- 原始文件哈希；
- 确认后的数据快照指纹；
- 解析警告和限制。

AI 结论引用不在证据集合内时，必须被拒绝或降级为待核实文本。模型解读失败时，应保留真实计算结果和证据，不显示“成功分析”的假状态。

## 9. 30 MB 限制：原因和处理原则

当前有两处文件大小检查：

- `src/ImportDialog.tsx`；
- `src/App.tsx`。

规则是：

```ts
file.size > 30 * 1024 * 1024
```

这是约 30 MiB 的**浏览器本地解析保护阈值**，不是模型接口限制，也不是产品永远只能处理 30 MB。原因包括：

- CSV、XLSX 和 PDF 在浏览器内解析；
- XLSX 是压缩文件，解压后可能远大于文件大小；
- sql.js 需要把数据放进浏览器内存数据库；
- 质量检查和 PDF 页面渲染会增加内存压力；
- 大文件可能导致浏览器卡顿、页面崩溃或比赛现场不稳定；
- 当前同时有 100,000 行、200 列、Excel 矩形单元格和 PDF 页数限制。

后续应基于真实性能测试改成分格式策略：

- CSV 可在稳定性验证后允许更大；
- XLSX/PDF 继续考虑压缩膨胀和解析内存；
- 保留行数、列数和展开单元格保护；
- UI 明确写“浏览器本地解析保护”，不能写成“AI 限制”；
- 不为了扩大数字而牺牲现场稳定性。

在用户没有明确授权之前，不应直接把 30 MB 改成 100 MB；应先测试内存、解析耗时和 Worker 行为。

9. 不要把真实模型连接成功当成业务分析准确；
