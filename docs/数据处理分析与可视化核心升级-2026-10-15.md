# 数据处理、分析与可视化核心升级

日期：2026-10-15。状态：本地功能增量已实现并通过下列验收，尚不是比赛最终成品。

## 1. 本轮解决的问题

旧工作台把过多关注放在连接配置与对话上，聚合种类和探索方式不足。本轮将实际计算放入独立 SQLite Worker，新增数据质量处理、可配置探索画布与期间对比，模型继续负责语义理解、规划和解释。

没有添加内置虚构业务数据、模拟 AI 答案或离线假模型模式。MCP 按既有决定搁置。

## 3. 开源源码学习与对应

以下为实际阅读的固定版本源码；本项目按适合当前范围的方式自行实现，没有复制或包装其完整产品，也没有声称复刻全部能力。

### Graphic Walker：分析查询与展示解耦

版本：87e8e51d2d8e2e32d6c763d32a3357fe29f379a0。

- [clientComputation.ts](https://github.com/Kanaries/graphic-walker/blob/87e8e51d2d8e2e32d6c763d32a3357fe29f379a0/packages/graphic-walker/src/computation/clientComputation.ts)：dataQueryClient 顺序执行 filter、transform、view、sort，最后按 offset / limit 切片。
- [dataQuery.ts](https://github.com/Kanaries/graphic-walker/blob/87e8e51d2d8e2e32d6c763d32a3357fe29f379a0/packages/graphic-walker/src/computation/dataQuery.ts)：界面请求计算服务，与具体执行器解耦。
- [aggregate.ts](https://github.com/Kanaries/graphic-walker/blob/87e8e51d2d8e2e32d6c763d32a3357fe29f379a0/packages/graphic-walker/src/lib/op/aggregate.ts)：按维度分组，并通过聚合函数映射处理指标。

对应：ExploreSpec 描述图表与查询口径；engine.ts 提供计算入口；analytics.ts 编译并执行筛选／聚合／排序／限项；ExplorationChart.tsx 只呈现结果并回传选中项。借鉴查询分层和多聚合设计，使用本项目的 SQLite 查询，未采用其原执行代码、任意表达式或拖拽编辑器。

### Microsoft Data Formulator：计算连接和可检查诊断

版本：5477f0e236426dc8f74a498ec400414fba7fbc0f。

- [agent_utils_sql.py](https://github.com/microsoft/data-formulator/blob/5477f0e236426dc8f74a498ec400414fba7fbc0f/py-src/data_formulator/agents/agent_utils_sql.py)：创建内存 DuckDB 连接，按输入表建立受命名处理的视图。
- [agent_diagnostics.py](https://github.com/microsoft/data-formulator/blob/5477f0e236426dc8f74a498ec400414fba7fbc0f/py-src/data_formulator/agents/agent_diagnostics.py)：集中定义 Agent 诊断结构，供前后端检查。

对应：engine.worker.ts 为数据快照建内存 SQLite 表，analytics.ts 返回结构化查询、参数、数据指纹和记录引用，页面与报告呈现诊断证据。已有导入候选确认交互也参考 DataLoadingChat。这里没有采用 DuckDB／Parquet 工作区，不宣称实现其完整诊断系统或自主 Agent。

### sql.js 与 Apache ECharts：实际集成的基础库

- [sql.js README](https://github.com/sql-js/sql.js/blob/2824d38946bab8b81d3000d5db8435411cb212ff/README.md)：Database、prepare / run、exec 与 WASM 载入，已用于真正 SQL 执行。
- [ECharts HeatmapSeries.ts](https://github.com/apache/echarts/blob/34f4d927eafe251f26f63afd3aeefa30f2feba30/src/chart/heatmap/HeatmapSeries.ts)：学习热力图的系列结构，使用官方库模块绘制二维聚合结果。

CC Switch 在历史实现中只用于连接配置交互参考，不能作为本轮数据核心的主要借鉴依据。

## 6. 尚未解决的边界

1. 尚无真实模型凭据，因此不能保证具体模型的领域分类、指标理解、结构化输出稳定性或视觉转录准确率。需在本机模型窗口接入真实服务后做实际数据集评测。
2. AI当前是理解／澄清／规划／确认／计算／解读流程，尚未实现连续自主工具选择、多假设验证与淘汰循环。六聚合进入AI计划；散点／热力／期间分解由独立页面执行，尚未统一进入Agent调度。
3. 没有跨表联结、任意PDF自动还原、跨页合表、加权平均、精确十进制财务记账或因果推断。
4. SQL在独立Worker计算，但字段质量与清理仍在主线程。100,000行×200列只是输入上限，未经极限性能认证。
5. 图表支持对当前快照交互重算；尚未接入动态数据源与增量刷新。数据与会话只存内存；刷新后丢失，需先导出。
6. 新探索与对比报告不合并AI解读全文。报告来源值最多1000条，保留完整记录引用，完整数据以原文件为准。
7. 没有完成公网部署、评审期间可用性验证或比赛级真实模型盲测。

## 7. 本地复验

项目根目录 npm run dev 同时提供页面与AI接口。终端实际地址为准，本轮用户预览端口为5174。生产复验 npm run build 后 npm start，仍使用本地Node服务，不依赖Vite开发接口。

核心测试 npm run test:core 无需联网、无需模型，直接使用附来源的真实小子集。浏览器测试需安装 Python Playwright / Edge；格式测试先 python tests/create-import-fixtures.py（需 Pillow），再按 README 的 TEST_BASE_URL 指向隔离服务运行。不要在用户正在使用的配置上运行写连接的测试。
