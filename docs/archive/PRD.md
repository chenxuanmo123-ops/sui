## 1. 产品概述

### 1.1 问题与机会

真实文件不仅有列名：还可能存在多表头、备注、小计、空值、单位不一致、日期格式混杂和含义不明的指标。普通「上传—问一句—给一张图」在口径错误时也能显得很像正确答案；完全依赖手工清洗与 SQL 又提高非技术用户的门槛。我们要验证的需求是：**用户需要一个能先识别数据边界，再实际调查、生成合适可视化，并允许追问核查的分析工作台**。这是产品假设，不宣称已证明市场规模或领先竞品。

### 1.2 一句话定位和主要差异

> **数鉴 Agent：面对不同类型的真实数据，先辨认字段与分析口径，再让联网 Agent 调用真实计算工具调查问题，逐步呈现有边界、有出处、可追问的图表与解释。**

首屏和演示首先证明「**不同数据 → 不同分析计划、指标口径、调查步骤及图表**」，不是炫耀通用聊天、模型菜单或技术日志。可信计算与证据是这一主线的基础；不是声称“自动找出一切原因”。

### 1.3 目标、非目标及成功证据

| 类别 | 本版定义 |
| --- | --- |
| 产品目标 G1 | 对至少两份**真实且有权使用、语义结构不同**的文件，经导入、字段/质量检查和必要确认后，能提出不同且合理的分析计划；保存文件来源与测试记录。 |
| 产品目标 G2 | 用户从中文提问到真实计算、渐进可视化、追问重算形成闭环；每个可核查数字能指向实际查询/统计、筛选口径、数据版本。 |
| 产品目标 G3 | 公网访客无需自备密钥能体验实际联网 AI；模型不可用、问题无依据、字段含糊时透明失败/请求澄清，不输出装作成功的答案。 |
| 赛事目标 G4 | 前端可操作价值、AI 工作流和安全可控可被评委直接观察；代码/视频/PDF 材料符合赛事要求。 |
| 非目标 | 任意行业/任意文件一键准确；因果证明、投资建议、联网自动抓取无授权站点；长期自动采集、实时大屏、复杂预测、多租户 SaaS、通用聊天机器人。 |

**建议验收方法而非已达成指标**：G1 用两套不同领域/记录粒度的真实样本及人工参照结论逐例审查；G2 用追问前后实际查询及图表数据的差异日志复核；G3 用真实断连、模型报错、限额、歧义场景实测；G4 用上线访问、仓库与提交物检查表验证。准确率、耗时、成本、文件限制等阈值须在真实数据 PoC 后记录基线再定，不预填漂亮数字。

## 3. 用户、场景与业务边界

### 3.1 目标用户和核心任务

- **主要用户**：拿到一份真实数据、想比较变化/分组/分布，但不知道字段口径或如何写统计查询的分析人员。
- **次要用户**：需要审阅分析过程、复核口径、复现实验的老师、团队负责人及赛事评委。
- **典型任务**：上传原始业务记录或已获授权的公开数据 → 确认粒度/质量 → 提问 → 查看调查计划与逐步结果 → 追问某一维度 → 检查依据 → 导出包含限制说明的分析结果。

### 3.2 跨类型能力的适用边界

这里「不同数据」指**数据语义和分析任务不同**，不只是文件后缀不同。首版至少选择两种真实任务进行人工基准验证，例如：

1. **按时间和指标记录的财务/经营数据**：必须区分同比/环比、累计/当期、币种和单位；无分渠道数据不能解释渠道贡献。
2. **调查或平台使用记录**：区分受访者级/回答级、人数与次数、多选题分母；「使用频率」不自动等于「偏爱」；样本内不自动推断全网。

上述是**候选验证剧本，不是指定已取得的数据集**。项目启动时登记真实文件的发布者或授权人、原始地址/授权凭据、许可证/可展示范围、取得日期、下载文件哈希、人工标注口径；不使用自编“咖啡店订单”等虚假样本。公开网站统计表若为汇总数据，不包装成逐笔交易数据。缺失解释问题所需的字段时，系统要说明不能据此回答并给出可补充的数据类型。

### 3.3 隐私与使用告知

用户上传的数据可能包含个人信息、商业秘密。上传前告知处理位置、所选 AI 服务以及传给服务商的字段摘要/样本/结果范围；默认按完成任务所需的最少信息发送，并允许用户查看哪些数据将外发。公网版不得承诺“完全本地处理”，除非实际传输路径经核验确实如此。用户对文件拥有合法处理权限；对未经授权、含敏感信息的样本应提示不要上传或先脱敏。会话、上传物与报告的隔离、删除方式和留存期限必须在上线前实测并公告，未确定不得声称“不会存储”。

## 4. 用户旅程与信息架构

### 4.1 主旅程

1. **开始**：看到产品支持的文件/限制、样本来源及风险提示；可上传本人有权使用的文件，也可选经过来源核验的公开真实样本；不要求访客配置密钥。
2. **理解数据**：看到工作表/候选数据区、字段类型、记录粒度、单位、缺失/重复/异常提示及原文件行位置；不确定则用户选择区域、修正类型或定义指标后继续。
3. **设定问题**：用中文输入分析目标；Agent 识别任务及口径歧义并形成**可修改/可确认**的调查计划。关键歧义未解决不得跳到结论。
4. **调查与展示**：通过受控工具真实计算；可见“计划→查询/统计→观察→下一步”的进度，图表随有效结果逐步出现；工具和模型失败要有明确状态。
5. **解释与追问**：回答给出范围、样本/分母、限制和相应图表；用户可追问某张图、某个时段或另一分组，系统沿用已确认口径，必要时新建分析分支并实际重算。
6. **复核与导出**：关键数字可查看筛选条件、数据版本、执行过程和可定位的来源；导出报告保留图表、方法及无法推断的事项。

### 4.2 页面模块（逻辑，不强制路由）

| 模块 | 用户能做什么 | 主要状态 |
| --- | --- | --- |
| 入口/数据源 | 上传、查看真实公开样本的来源、选择或删除数据 | 未选、上传中、解析失败、就绪 |
| 数据诊断 | 预览表区、字段与质量，手动确认映射/排除行 | 待确认、可分析、无法解析 |
| 分析工作台 | 提问、查看计划、控制运行/取消/重试、看图和结论 | 计划中、运行中、需澄清、部分结果、完成、失败 |
| 追问与依据 | 按当前上下文提问、查看指标定义/计算/来源；可切换分支 | 未复核、可复核、数据不足 |
| 模型与设置 | 查看当前引擎及处理声明；高级配置仅按审核后的安全策略开放 | 可用、额度限制、配置失败 |
| 报告 | 预览、下载、查看数据及模型版本与适用边界 | 生成中、可下载、失败 |

普通用户默认看到「分析进度与发现」，高级模式可看脱敏后的工具名、参数摘要和实际结果；**不要求访客理解 MCP 或手动连接协议**。

## 5. 产品功能需求（正式交付目标）

> 优先级：**P0** 为第一批必经产品闭环；**条件项**只有通过研究与门槛后才晋升 P0，否则明确不支持；**后续**不计入本轮交付承诺。每条标明行为、失败边界、可测验收。技术实现不是本章的约束。

### FR-01 真实数据导入与来源（P0）

- 接受 CSV、XLSX；显示文件、工作表/区域、读取时间、记录数、来源说明。公开真实样本可由项目提供，但须有原链接/许可或授权记录，注明下载时间及哈希；不得生成虚构业务记录冒充真实数据。
- 上传中断、空文件、加密/损坏文件、不受支持格式明确拒绝；不把随机解析文本当作有效行。
- **验收**：用授权真实 CSV 与真实 XLSX 分别导入并可定位原始行；载入公开样本能查看来源；错误文件不会出现“分析成功”。

### FR-02 杂乱表格检查与可控整理（P0）

- 诊断标题行、空行、备注、小计/总计、混合日期/数字、缺失值、重复记录、候选数据区；标记**疑似问题**而非自动删除一切异常。
- 用户可选择 sheet/区域、修正字段类型与单位、决定排除行；记录清理前后行数和规则版本。无法可靠识别时请求确认或停止。
- **验收**：至少一份真实脏文件出现可审查的行级提醒；人工更正后统计按新规则重算；原始文件与映射关系可追查，不能静默覆盖。

### FR-03 任务理解与语义口径（P0）

- 识别记录粒度、时间跨度、目标指标、维度、单位、汇总层级及用户问题；区分金额/次数/比例、当期/累计、人数/访问量等，不确定时提问。
- 生成分析契约：字段映射、过滤范围、聚合/分母定义、数据缺陷、不能回答的部分、用户确认；问题或口径变化须保存修订。
- **验收**：两份真实异质数据的指标定义和计划存在**可解释的差别**；缺少必要字段或“偏爱”与“使用次数”混淆时，系统不会擅自等同。

### FR-04 联网 Agent 调查（P0）

- Agent 至少完成：问题理解→计划→受控工具调用→读取真实返回→选择继续、修正、澄清或停止→输出限定结论；真实决策节点与依据可在工作台看到。
- 模型负责理解、规划与语言解释，计算由工具完成；结构化动作须校验，不能让原始文件内容变成系统指令。可设置执行步数、耗时与费用上限；超出时保留已完成步骤并标记未完成。
- **验收**：同一真实数据的追问触发不同查询或统计；特意构造的数据不足/空结果使 Agent 请求补充或停止；执行日志中的步骤与后台结果一致；不存在离线预设规划器冒充在线 AI。

### FR-05 真实分析工具与计算安全（P0）

- 提供最少够用的内部工具能力：数据概览/质量、受限筛选与聚合查询、分组对比/基础统计、图表数据组织。工具数量由任务决定，不为凑数固定六个；**MCP 协议暂不实施**，不阻断 Agent 调用真实工具。
- 非可信模型输出只能进入允许的查询/统计接口；若采用 SQL，限定只读范围、参数/标识符校验、语法及资源约束、超时与结果行数限制，并针对 CTE、联合查询及恶意输入实测；不能仅靠正则查 `SELECT` 便宣称安全。是否采用 SQL/WASM 或服务端执行由 PoC 决定。
- **验收**：展示一条图表背后的真实查询/统计输入与输出；故意提交越权/高耗/错误请求时被拒绝或中止，其他访客的数据不可见；工具失败不生成成功结论。

### FR-06 渐进式、语义匹配的可视化（P0）

- 依据时间、类别、数值分布选择有意义的图表或表格；每张图应标记指标、单位、时间范围、过滤条件、分母/样本量（适用时），且由同一份真实计算结果驱动解释。
- 有效结果逐步出现；中途报错或取消，已完成结果标记「部分」，不宣称整份分析完成；仅有少量记录或不适于画图时显示表格/文字而不硬凑散点或热力图。
- **验收**：两份数据的图/表选择有可说明的理由；点击图中数值能看到其生成口径；调整筛选后真实刷新，未重新计算不得展示旧图为新答案。

### FR-07 有边界的结论与依据检查（P0）

- 输出区分「直接观测」「描述性比较」「可能的解释」「数据不足/无法证明」；模型引用数字必须匹配计算结果及单位，不把相关性自动写成因果。
- 每条关键数字保存数据集版本、转换规则、查询/统计、筛选条件、结果和可定位的来源行/来源聚合范围。聚合值可能对应大量行：用范围、计数、抽样行及可复算查询说明，不伪称单一行能证明总额。
- **验收**：抽查任何关键数字可以独立重算一致；故意让解释引用不存在的数字时校验阻断；无渠道字段却问「渠道导致下降」时不会编造渠道归因。

### FR-08 常驻追问与分析分支（P0）

- 结果生成后保留与当前数据集及确认口径绑定的 Agent 问答入口；用户追问时展示继承/修改的条件，必要时询问是否重置歧义口径；不同文件的上下文不混用。
- 追问或合理质询可开新分支并重算，前一版图表与依据保留供对比。旧版提出的「挑战这条结论」可作为追问范例，但**不是首屏主交互或必建的独立产品模块**。
- **验收**：追问“只看某时段/某一组”会触发新计算且数值随之变化；跨文件切换后不会复用旧数据的指标定义。

### FR-09 报告预览与导出（P0，发布前置于主闭环）

- 可导出可独立打开的报告（优先单文件 HTML，具体实现以兼容性与安全测试确定），包含问题、数据出处与版本、确认口径、图表快照/等价可阅读图表、关键结论、计算方法、限制、生成时间及追问结果（如用户选择）。
- 输出内容须 HTML 转义/隔离，防止数据和模型文本注入可执行内容；报告不能依赖浏览器临时会话才能显示基本结果。导出或图表快照失败须说明并允许重新生成。
- **验收**：在无应用登录态/本地会话的浏览器中打开导出文件，文字、图表与方法仍可阅读；抽查数值与当前分析分支一致。

### FR-10 在线模型接入与专业 Prompt（P0）

- 网页提供**无需访客自备密钥**的默认联网模型服务；模型密钥只在受控服务端/安全代理。建立与供应商无关的分析动作、返回结构和领域 Prompt 规范；可按真实服务能力切换适配器，不将任意公开 Base URL、任意 Key 表单直接暴露为公网访客功能。
- 针对财务与调查等已验证的任务类型，以术语/指标词典、口径澄清规则、工具结果约束、禁止无依据结论组成提示规范；对服务返回做结构化校验、重试上限与错误提示。**多服务兼容作为方向**；首版至少验证一个默认服务的端到端链路，是否将第二服务作为公开可切换能力由安全、成本与实测稳定性评审后确定（详见 §10）。
- **验收**：未在浏览器源码、网络响应或仓库暴露服务器密钥；默认服务真实在线调用可见；无效模型返回不会生成假成功；如声称“支持多服务”，则至少两种真实 API 通过同一组验收脚本，且注明各自支持的能力差异。

### FR-11 控制、恢复与重置（P0）

- 支持取消、对失败步骤重试、切换/清除数据及清除会话；失败时保留可诊断提示，需澄清时不消耗无效循环。重试不得偷偷变更数据口径或复用错版本结果。
- 公网需有访问控制、速率/费用限制与滥用防护；若额度耗尽，提示暂停而非播放演示录像冒充运行。
- **验收**：模拟文件解析失败、模型超时、限流、工具报错、取消后重试、两访客同时使用；各状态明确且相互隔离。

### FR-12 真实公开样本与展示（P0）

- 为评委准备至少两份可公开展示的真实异质样本及出处卡片：来源、采集时间、授权/许可证、文件校验值、文档指标口径和已知局限；另支持评委自带合法文件。
- 若无法证明来源合法或样本不满足业务口径，应替换或移除，不为视频效果手工补行；任何必要脱敏必须标明脱敏规则，不能伪装为未改动原始数据。
- **验收**：评委从公网打开即可查看来源并实际运行；样本与仓库说明可交叉核对（许可不允许再分发原始文件时，仅保留可合法展示的证明和操作方式）。

## 6. 条件能力与明确不做的内容

### 6.1 PDF、RAG 和多模态（条件项，不偷换成已支持）

用户提出的 PDF 问题必须认真对待，但 PDF 中有可复制文字、扫描图像、复杂表格等不同情况；它不能与 XLSX 等价承诺。

| 候选能力 | 启用条件 | 没通过时的诚实边界 |
| --- | --- | --- |
| 可选文字 PDF 的指标定义检索 | 有合法真实文档与具体问题；提取的文本可定位页码并改善口径回答；检索结果能对比无检索版本 | 仅支持 CSV/XLSX 数据主闭环；告知 PDF 暂不支持作为数据源 |
| 有限文档 RAG | 至少一份真实、与分析表格有明确关系的附注/调查说明；检索片段带页码、被实际引用并通过人工核对 | 不把对数据表的 SQL 查询宣传为 RAG |
| 扫描 PDF / 图像多模态 | 有真实可展示扫描件，人工基准值及可核对页码/区域，模型和人工复核实际有效 | 不把提取文字或文件扩展名当多模态；扫描件明确不支持 |

试点通过后由团队记录支持的 PDF 类型、页面限制、错误纠正流程与退出标准，再决定是否进入第一批；不能靠评分权重强推一个会误导数字的功能。对 CSV/XLSX 中嵌入图片或无结构备注，提示不可读或需人工处理。未来的实时数据接入、跨表连接、大规模数据仓库与多用户权限均不在本次承诺内。

### 6.2 MCP 处理规则

**当前状态：搁置，不是首版交付项。**本版仅要求 Agent 使用真实、受控、可观察的数据工具。以后若发现真实外部工具接入/协议互操作收益明确，再以独立评审决策引入 MCP；未引入前，代码、UI、答辩和技术文档不得写「已通过 MCP 调用」。

## 7. AI 与数据可信机制

### 7.1 分工、状态和复核

```text
真实文件/来源确认
  → 表区识别、字段与质量审查（规则 + 用户确认）
  → 语义口径确认（联网模型提出，用户/规则约束）
  → Agent 计划（联网模型）
  → 工具参数校验与真实计算（受控程序）
  → Agent 观察结果并决定下一步/澄清/停止
  → 数值与引用核验（程序）
  → 合适图表、解释、可追问工作台与报告
```

模型不可修改工具实际返回值；工具不接受从上传文件/外部文档来的“忽略之前指令”。结论与工具结果冲突则要求修正或标明失败；多次失败停止，而不是无限调用。涉及「下降原因」优先表达已观察到的分解贡献/伴随变化及竞争性假设；没有实验或外部证据不下因果结论。

### 7.2 数据、计算与结论的关系

建议最小数据对象：`DatasetVersion`（原文件指纹、来源、工作表/区域、清理规则）、`FieldMapping`（字段、类型、单位、语义）、`AnalysisContract`（问题、口径、样本、过滤、分母、限制）、`ToolRun`（已校验动作、状态、实际输出、时间/错误）、`ChartSpec`（数据绑定、单位、范围）、`Claim`（结论等级、引用的工具结果/图表、适用边界）、`Branch`（父分支、修改条件）。具体字段/存储结构由技术方案确定。

每条数值沿 `Claim → ToolRun → DatasetVersion/规则 → 来源文件` 可追溯；对图表中的聚合值可以查看组内计数/查询，而不以几条示例原始行假装证明总计。分析前后文件版本不同，旧结论必须标记过期而非默默复用。

### 7.3 安全原则

- 上传隔离、文件类型与大小限制、恶意内容拦截；日志脱敏，不能记录完整个人信息或密钥。
- 查询最小权限、资源上限与可中断执行；模型服务请求最小必要数据外发，并展示用户须知。
- 公网配额、频率限制与使用量监控；基础防刷设计不以 Referer 单项检查代替鉴权/配额。
- 报告/图表/聊天展示统一转义和危险内容处理；第三方依赖与许可证在开发时审查。
- 验收须覆盖提示注入、恶意 SQL、跨会话访问、日志泄露、HTML/CSV 注入和恶意/畸形文件，不因“比赛作品”豁免。

## 8. 非功能性需求和部署边界

| 维度 | 要求与验证方式 |
| --- | --- |
| 可用性 | 公网域名在评审期可访问；无预置密钥/自带服务的访客可执行主流程；健康检查与错误页真实反映状态。公网环境和费用预算待选定。 |
| 性能 | 首屏、文件解析、单次问题、图表交互分别在目标浏览器和真实文件上测量；上限（大小/行数/步数）由 PoC 实测后配置并在 UI 明示，不许宣称支持无限数据。 |

| 浏览器与响应式 | 以当前主流桌面浏览器为主，移动浏览器可完成上传提示、阅读结论和报告；最终支持矩阵在测试记录中写明，不杜撰设备覆盖。 |
| 可观测性 | 能核对计划、工具实际结果、模型/服务版本、错误类型、数据版本；用户侧日志不泄露原始敏感行或完整鉴权信息。 |
| 可复现 | 公开仓库有真实开发历史、README、环境变量样例、合法可共享测试数据/下载说明、启动说明和自动化测试；云端与本地使用同一分析规则而非两套“演示版”。 |

**实现边界而非技术栈锁定**：前端现代组件框架 + 图表库；后端或安全代理负责密钥与在线 AI；计算层可浏览器内或受控服务端。是否使用 React、Zustand、sql.js、Fastify、SSE、特定图表/部署平台，须在技术方案 PoC 中按隔离、隐私、性能、费用和可维护性确定。公网部署不是“写了域名字符串”，需真正上线并从非开发电脑验证。

## 9. 端到端验收与测试矩阵

| ID | 输入/操作 | 通过条件（主观内容由人工对照基准判断） |
| --- | --- | --- |
| A01 | 两份经核验授权、语义不同的真实数据，分别导入 | 文件内容、出处/许可与原始行可追踪；同一问题类型下计划/指标口径实质不同且合理 |
| A02 | 真实 CSV/XLSX 含标题、备注、小计及不规则单元格 | 问题行展示与人工修正可用；小计不重复相加；分析结果与清理规则绑定 |
| A03 | 含歧义指标或无所需字段的自然语言问题 | 请求用户明确口径/指出不足；不会生成不存在的“渠道影响”“偏爱率” |
| A04 | 用户点击运行、观察各步与图表 | 服务端真实联网模型响应、受控工具执行与实际输出一致；图表使用同一结果，失败不回放预制结果 |
| A05 | 人工预先计算的分组/趋势/分母基准 | 核心计算重算一致；图表单位、筛选范围和显示数值一致 |
| A06 | 对某图/某时段追问并改条件 | 产生新的 ToolRun 与更新后的图/结论；旧分析保留且标记数据/口径版本 |
| A07 | 打开任一关键结论的依据 | 可找回计算方法与数据范围/原始行定位；聚合不伪称几行明细是全部依据 |
| A08 | 模型错误、限流、断连、工具超时或取消 | 明确报错/部分完成/可重试；不会写假结论；用户可清除并重来 |
| A09 | 两名访客分别上传不同文件；测试恶意文档/查询/报表 | 数据隔离成立；工具与 HTML 限制生效；不泄露密钥和敏感内容 |
| A10 | 下载报告并在新浏览器打开 | 图表与结论可读，版本/来源/局限清楚，数值与所选分支相符，无可执行注入 |
| A11 | 若公开宣传多供应商接入 | 至少两种真实服务按同一测试脚本走完 A03—A08；若未通过，不宣称支持多款 |
| A12 | 若公开宣传 PDF/RAG/视觉识别 | 对具体支持的真实 PDF/扫描样本执行原页定位、人工校验及失败案例测试；未入版不宣称具备 |

**人工基准构建**：选择样本后由团队先记录人工核算步骤、答案、字段歧义、已知错误与不可答问题，保留文件来源和版本。可以准备操作脚本与测试用例，不能把脚本作为运行时预置模型回答。至少包括两种语义类型、多条追问、数值复算、混乱数据与一条不可答问题；记录成功与失败，不只剪出成功画面。
